# UML 类图与顺序图验收清单

## 类图

- [ ] Service 类位于图的几何中心。
- [ ] 类框名称、属性、操作分区清楚。
- [ ] 任意两个类框无重叠。
- [ ] 任意依赖、实现或关联线不穿过非端点类框。
- [ ] 依赖是虚线空心箭头。
- [ ] 实现关系从实现类指向接口，虚线空心三角落在 `«interface»` 一端。
- [ ] 关联是实线空心箭头，并标注 role name。
- [ ] 对象字段关系使用 association。
- [ ] Association role name 在箭头上方或左侧/左上方，不与连线或类框重叠。
- [ ] 方法参数、局部变量和静态调用使用 dependency。
- [ ] dependency line 上没有文字。
- [ ] 接口使用 `«interface»`。
- [ ] Repository 与 Entity 的关系优先由方法签名表达，不画绕圈长线。
- [ ] 长方法签名未溢出类框。
- [ ] 图中类、字段、方法、依赖与当前代码一致。
- [ ] 不存在无意义的回折、倒退、重复拐点或 U 形连线。

## 顺序图

### Lifeline

- [ ] 最左侧是 `obj: 调用者`。
- [ ] 普通 lifeline 使用 `objectName: ClassName`。
- [ ] 静态方法 lifeline 使用 `«MetaClass»` 和 `: ClassName`。
- [ ] 长类名自动缩小字号且未溢出。
- [ ] lifeline box 没有被相邻 box 覆盖。

### 消息

- [ ] 同步消息实线实心箭头。
- [ ] 回复/异常虚线空心箭头。
- [ ] 只有同步消息编号。
- [ ] `变量 = 方法(...)` 已表达返回值时，不重复画普通返回线。
- [ ] 同步消息终点落在接收方执行条顶边靠消息来向的端点。
- [ ] 消息不落在 lifeline 中心或执行条内部。

### Execution Specification

- [ ] 调用者有一根覆盖整个同步调用的执行条。
- [ ] 被调用方每次独立调用都有自己的短执行条。
- [ ] 连续调用没有合并成一根长执行条。
- [ ] 执行条顶边与进入消息同高。
- [ ] 执行条底边不与 `opt/alt` 边框相交。
- [ ] 连续执行条之间留有可辨认的间隔。

### 回复与异常

- [ ] reply/exception 从发送方执行条边缘发出。
- [ ] reply/exception 落到接收方执行条边缘。
- [ ] 未捕获异常从实际抛出方直接返回 caller。
- [ ] 不画未捕获异常的逐段传播。
- [ ] 异常箭头发出时，来源执行条尚未结束。
- [ ] `DomainException`（DDD）、`ManagementFailure`、`AuthenticationFailure`（结构化）等异常不会从已结束的执行条或 lifeline 上发出。

### 控制片段

- [ ] `opt/alt` 条件文字清楚。
- [ ] 片段只包含对应分支或循环体的行为。
- [ ] `loop` 框完整包含循环体的全部消息。
- [ ] `loop` 框完整包含循环体消息产生的 receiver execution specification，包括嵌套自调用执行条。
- [ ] 每轮循环的 execution specification 都独立位于 `loop` 框内，没有执行条被框线截断。
- [ ] 循环前、循环后的 execution specification 都在 `loop` 框外。
- [ ] caller 表示整个方法调用的外层 execution specification 可以跨框，但不会被误当成单轮循环体。
- [ ] 片段边框不穿过、切断或遮挡执行条或消息箭头。
- [ ] 片段的透明/浅色填充不遮挡编号、文字、箭头和执行条。
- [ ] 插入/移动 `opt/alt/loop` 后重新检查全部几何关系。

## 图稿交付

- [ ] 新图页集中放在 `docs/项目设计图.drawio`，已有图页内容完整。
- [ ] 图页名称标明版本、实现类型（DDD 或结构化）、图型和用例。
- [ ] `<mxfile>` 的 `pages` 数量与实际页面数一致。
- [ ] 已实际查看图页，检查文字、箭头、执行条和控制片段的布局。
- [ ] 用户要求导出时，已按指定格式核查导出文件。
