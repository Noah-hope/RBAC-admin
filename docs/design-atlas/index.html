结构化 vs DDD 核心差异

维度结构化（rbac1-structured）DDD（rbac1-ddd）
依赖方向controller → service → mapper → entityinterfaces → application → domain ← infrastructure
领域模型贫血实体 + 字符串常量充血聚合根 + 不可变快照 + 枚举
规则位置集中在 Service 过程方法聚合根 + 领域服务，应用层仅编排
对象转换DTO → Service → VODTO → Command → Domain → Result → VO
持久化Service 直接组合多个 Mapper一聚合一仓储端口，JPA 适配器封装多表

RBAC0 基线

  • 仅角色直接权限，无继承
  • 单套结构化后端
  • 用户、部门、应用、权限与申请闭环

RBAC1 扩展

  • 角色多父多层 DAG 继承（禁环、保后代菜单）
  • 新增独立 DDD 后端对照实现
  • 接入系统统一身份鉴权与角色码映射

角色继承配置

PUT /api/v1/roles/{roleId}

单事务替换业务角色的直接权限与父角色：校验预置只读、禁重复直接配置、禁环及后代按钮菜单完整。

GRASP 职责分配（DDD 版）

信息专家Role.reconfigure 负责自身校验与原子替换，只读集合 getter 保护不变式。
控制器RoleApplicationService 编排鉴权、事务、持久化、日志与申请结算。
间接 / 保护变化JpaRoleRepository 实现 RoleRepository，封装三表差量与重名异常翻译。
纯虚构RoleHierarchy 将多继承 DAG 抽为不可变快照，推演后代影响。
维度结构化（rbac1-structured）DDD（rbac1-ddd）
规则位置集中在 RoleService 方法内聚合规则归 Role，跨图推演归 RoleHierarchy
实体形态贫血 JPA 实体（无业务方法）充血聚合根（零框架依赖）
持久化Service 直接操作 3 个 Mapper仅调 RoleRepository.save(role)

GRASP 职责分配（DDD 版）

信息专家User 聚合根封装改名、启停、调动与管理员任免，仅在真实变更时驱动审计。

间接SessionStore 端口解耦会话清理，JpaUserRepository 统一同步用户与角色关联。

维度结构化（rbac1-structured）DDD（rbac1-ddd）

总管自动授权直接新建 RolePermission 实体写入 RolePermissionMapper调用 Role.grantNewlyRegisteredPermission 后经 RoleRepository 保存

GET /auth/me

GRASP 职责分配（DDD 版）

信息专家AuthenticatedSession 核验目标应用受众；User 结合 RoleHierarchy 聚合有效权限与业务角色。
纯虚构PermissionCatalog.codesIn 按应用过滤权限码，RoleHierarchy 遍历多继承祖先。
保护变化ApplicationRoleCodeReader 只读端口隔离外部应用角色码映射表查询。
控制器AccessApplicationService 编排会话上下文、快照加载与双模式角色组装。
维度结构化（rbac1-structured）DDD（rbac1-ddd）
受众解析核验SessionController 先调 SessionService.resolveApplication 再进权限服务值对象 AuthenticatedSession.applicationContext 内聚校验受众
继承图遍历RolePermissionService 构建 Graph 记录并在静态集合方法上传参遍历User、RoleHierarchy、PermissionCatalog 按领域职责协作计算
角色码查询PermissionCheckService 直接调 ApplicationMapper.findRoleCodes通过端口 ApplicationRoleCodeReader（JdbcClient 实现）解耦查询

03ER 与数据字典

概念 ER、物理表结构与数据字典

两套后端共享 Flyway 迁移（V1__init_rbac1.sql、V2__application_role_codes.sql）与同一数据库。

  • 不冗余继承副本：仅存直接权限与直接父角色，有效权限沿 DAG 动态计算。
