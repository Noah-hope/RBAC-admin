## 表达层次

这是需求分析级时序图：参与者主要是管理员、权限中心、业务系统、OA；权限中心的处理用自消息概括，不拆出尚未设计的 Controller、Service、Mapper、数据库表或 Java 方法。

消息括号内列出已确定的业务信息，例如当前公司、员工／角色、申请编号、版本、原因，不固定 JSON 字段名称、类型、长度、数据库列名或接口地址。之后完成数据字典及 API 设计时再细化，不需要现在先完成全部字段设计。

图中管理员生命线表示人与系统的业务交互，未另画前端页面层。UC-11 自动执行器标注为权限中心内部职责，不是新增外部系统，也不意味着单独部署服务。

## UML 记号

- 竖向虚线为生命线，时间由上到下。
- 实线实心箭头为请求／处理消息；回到同一生命线的箭头表示内部处理。虚线空心箭头表示返回。
- `alt`：互斥分支，按方括号中的条件选择，不是依次执行所有分支。
- `opt`：满足条件时执行；未确认的编辑、预览不等于提交。
- `loop`：使用后台期间重复校验或批准方案恢复重试。
- `ref`：引用其他用例／子流程，不是新增 UML 用例 include 关系，也不是一个已定 Java 方法。
- 消息序号便于讲解，跨 alt 分支不表示所有编号都在同一次办理中发生。
- 不展开实现级调用栈及激活条跨度，避免把分析消息误认为已确定的同步方法调用。

## 关键规则

UC-02 配置、UC-03 分配和 UC-04 一般撤销提交先返回待审批；离岗关权直接生效；OA 最终结果回调是之后的独立请求，管理员不一直同步等待审批。OA 内部流程不展开。UC-11 区分可靠接收、批准、执行成功／失败；合法方案自动执行，原申请人离任不单独阻止执行。

UC-05／06 按当前公司、当前系统计算功能授权及进入资格，业务系统执行功能访问拦截；本系统不设计数据权限。数据库／服务故障返回服务错误，不能冒充成功空权限或默认放行；部分通用异常在图下方说明，不逐项复制到每条业务消息。

UC-10 使用明确变更动作和稳定身份：员工停用使业务授权及权限管理员任命失效，任职变化只影响不再满足条件的关系；恢复身份不恢复旧关系，重新申请／任命。UC-07 任命与后台登录不授予外部业务权限。

UC-09 三个子流程和 UC-11 自动执行页只是现有用例的配套说明，不新增正式用例编号。
