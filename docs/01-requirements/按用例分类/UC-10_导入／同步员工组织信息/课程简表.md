## UC-10 导入／同步员工组织信息

详细依据：[原用例](UC-10_导入同步员工组织信息.md)

| 项目 | 内容 |
| --- | --- |
| 级别 | 用户目标 |
| 包 | 基础组织与员工资料 |
| 参与者 | 权限中心总管理员；数据来源：HR 系统（一期文件／模拟数据） |
| 描述 | 导入或更新公司、部门、岗位、员工及任职资料，供授权管理使用。 |
| 触发事件 | 首次初始化，或收到员工、组织和任职的更新资料。 |
| 前置条件 | 总管理员已登录，已取得来源明确的资料及字段映射。 |

| 主成功场景 | 信息 |
| --- | --- |
| 1. 总管理员选择来源文件、数据类型和工作表。 | 数据来源、文件、组织／员工／任职类型 |
| 2. 总管理员核对字段与组织映射，发起预检。 | 唯一标识、字段映射、组织对应关系 |
| 3. 系统展示问题、计划变更及影响。 | 问题行、新增／更新、停用和任职变化 |
| 4. 总管理员确认预检通过的批次。 | 确定的导入内容、影响确认 |
| 5. 系统导入资料并记录结果。 | 批次、实际新增／更新结果 |
| 6. 总管理员查看执行报告。 | 成功／失败、数量及原因 |

| 扩展场景 | 信息 |
| --- | --- |
| 3a. 格式错误、身份或组织映射有歧义：修正后重新预检。 | 问题行、字段说明 |
| 3b. 同员工多项合法任职：保留兼岗；完全重复资料不重复新增。 | 任职列表、重复提示 |
| 3c. 已有角色、授权或历史引用的指定部门跨公司迁移：阻止本次变更。 | 受影响部门、原因 |
| 4a. 预检后内容或目标发生变化：重新预检确认。 | 变化提示 |
| 5a. 相同批次已执行：返回原结果；执行失败则整批不生效。 | 批次结果或失败原因 |

其他：不经 OA，不自动建后台账号、任命、分角色或授予进入权限；漏行不等于离职。全局停用使全部业务授权及权限管理员任命失效；任职条件丧失只使相关授权／任命失效；结束最后任职后同批再就职不复权。历史保留，恢复不自动授予，分别重新走 UC-03／07。提供明确人员变更模板、内部稳定 ID 及来源映射。一期不要求真实 HR 接口。 总管理员可在员工页直接全局停用/恢复，恢复不复权；部门管理员仅按 UC-04 关闭本部门来源；不设计组织启停。
