## UC-03 为员工分配角色

详细依据：[原用例](UC-03_为员工分配角色.md)

| 项目 | 内容 |
| --- | --- |
| 级别 | 用户目标 |
| 包 | 员工授权 |
| 参与者 | 权限中心总管理员、权限管理员；协作：OA 系统 |
| 描述 | 为员工申请新增业务角色，审批执行成功后员工获得对应授权。 |
| 触发事件 | 员工入职、兼岗或工作需要新增角色。 |
| 前置条件 | 管理员已登录且有管理资格；目标员工有效并满足角色任职条件，角色已生效。 |

| 主成功场景 | 信息 |
| --- | --- |
| 1. 管理员选择目标公司和待授权员工。 | 公司、员工统一标识、任职信息 |
| 2. 系统展示已有授权及可分配角色。 | 已有角色、授权来源、有效角色 |
| 3. 管理员明确各员工拟新增的角色并填写原因。 | 员工—角色—来源公司/部门配对、周期与原因 |
| 4. 系统展示实际新增明细和权限摘要。 | 角色所属系统、功能权限、进入资格提示 |
| 5. 管理员确认提交，系统受理并交由 OA 审批。 | 固定分配清单、申请编号、待审批状态 |
| 6. OA 返回最终批准结果，由 UC-11 执行角色分配。 | 审批结果、实际新增关系 |
| 7. 管理员查看执行结果。 | 生效状态、员工新增角色 |

| 扩展场景 | 信息 |
| --- | --- |
| 3a. 已有相同有效关系：排除重复项；全部无变化时不提交审批。 | 无变化明细 |
| 5a. 存在越范围、任职不符、无效角色或重叠申请：拒绝，修正后再提交。 | 问题明细、现有申请 |
| 6a. OA 驳回：不增加角色；修改后以新方案重新申请。 | 驳回原因 |
| 6b. 角色内容变化或员工已不符合任职条件：原方案失效，重新申请。 | 失效原因 |
| 6c. 执行失败：整批不增加授权，按 UC-11 恢复处理。 | 执行状态 |

其他：只新增选定关系，不替换已有角色；允许兼岗和跨系统持有多个角色。功能权限来自角色配置；授权另固定来源部门及周期；仅有功能权限而无同公司、同系统进入权限时功能不可使用。失效历史不阻止重新申请。岗位变化但条件仍满足时保留；来源关闭或失去来源任职则授权失效，恢复任职后重新申请。部门角色只适用直接任职。
