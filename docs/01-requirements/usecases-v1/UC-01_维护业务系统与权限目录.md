# UC-01 维护业务系统与权限目录

版本：V1.2，2026-10-15。状态：功能权限、部门管理范围及员工启停流程已按用户确认修订，可作为界面原型依据。

本轮更新：管理范围按公司、部门子树及系统指定；离岗关闭原部门来源权限立即生效，全局停用仅总管理员；保留功能权限、OA 及历史规则。

### 当前需求基线（2026-10-15，V1.2 部门范围与员工启停）

- 一期实现 RBAC0 权限管理：员工经角色获得权限，无角色继承、直接用户授权或显式拒绝。外部系统只做简单 HTTP 调用演示，不实现其内部业务。
- 角色属于一个公司和一个业务系统，可限定部门；公司级角色要求本公司有效任职，部门级角色要求在该部门直接有效任职，不自动覆盖下属部门。岗位不自动绑定角色；任职条件与权限需要均未改变时，不因岗位名称变化更换角色。
- UC-05/06 按“员工＋当前公司＋业务系统”计算权限。仅合并该公司、该系统内的有效角色；系统进入资格与功能权限也必须来自该公司、该系统。公司上下文隔离的是功能授权来源，不定义业务数据访问范围。
- 授权同时校验角色适用条件与来源部门。离岗关闭原部门来源立即失效，其他独立兼岗来源保留；公司级共享角色不随调岗自动转移。仅总管理员可全局停用/恢复员工；恢复不复权。新授权经 OA，新管理任命由总管理员办理。
- 当前 RBAC 系统只管理功能权限。目录登记系统进入权限与功能操作，角色配置是否授予；不定义、保存或返回业务数据范围，不设计本人记录判断或行过滤规则。
- 员工、公司、部门使用稳定内部 ID；首次导入以源唯一用户名建立员工映射，组织分配稳定编码，更名不改变身份。人员变更模板明确新增任职、结束任职、停用、恢复等动作，不从文件缺行推断离职。
- 一期使用至少两个公司、两个系统的代表性数据，覆盖多角色、兼岗、公司授权隔离、功能操作独立与去重、审批生效、撤销、失效及重新申请。其余资料后续逐步补齐。

以上为本轮已确认规则，详细流程与验收必须遵循；描述的是需求设计，不代表代码已实现或真实外部系统已完成对接。

## 1. 用例概述

| 项目 | 说明 |
| --- | --- |
| 编号与名称 | UC-01 维护业务系统与权限目录 |
| 目标 | 登记接入系统及其功能、操作权限，形成角色配置和对外权限 API 共用的目录 |
| 发起者 | 权限中心总管理员 |
| 触发 | 初始化资料、新系统接入、功能增加、目录调整或权限停用 |
| 前置条件 | 总管理员登录有效且具有目录维护资格；新增内容有明确名称、编码和归属 |
| 成功结果 | 目录及版本、审计保存成功，后续角色配置和权限查询使用更新后的目录 |
| 失败保证 | 本次变更整体回滚，不部分写入或破坏已有引用 |

本用例定义“有哪些权限可以配置”，UC-02 决定“角色获得哪些权限”，UC-03 决定“员工获得哪些角色”。登记一个系统或新增权限项不会自动授权给角色、员工或分权限管理员。

本稿沿用总管理员直接维护目录的方案：保存与审计成功后生效，不接入 OA；UC-02 配置、UC-03 分配与 UC-04 一般撤销按 OA 流程；UC-04 离岗关权直接办理。直接生效、编码约束及停用细节是本稿设计约定，不表述为老师原文要求。

### 管理范围与人员权限（V1.2 已确认）

完整规则见 [管理范围与人员权限规则](管理范围与人员权限规则.md)。总管理员指定公司、管理根部门及系统，部门范围含下级但不跨公司；同范围协作，不因同公司就共享整家公司权限。

公司级共享角色只由总管理员维护，权限管理员可为范围内合格员工申请分配；部门角色按明确归属维护。每次员工授权固定实际来源部门，不等同管理员根部门或角色归属。

离岗关闭原部门来源权限立即生效、不等待 OA；一般角色配置、分配及撤销仍经 OA。全局员工停用/恢复仅总管理员；恢复不自动复权。不设计公司/部门启停，普通员工不登录本平台。

## 2. 清单依据与初始化边界

来源：[市政公司应用软件功能权限清单(1).xlsx](D:/D盘的桌面/我的文件/大三课程资料/ooad-项目/市政公司应用软件功能权限清单(1).xlsx)。已核对表中 18 个系统栏目、359 条功能点；最后“系统管理后台”归属仍待明确，不能默认既是外部系统又是本平台管理权限。

| 清单内容 | 本项目中的用途 |
| --- | --- |
| 软件系统 | 业务系统目录 |
| 功能模块 | 一期模拟菜单的导航目录 |
| 功能点 | 一期受保护功能项，可作为功能菜单 |
| 功能说明 | 目录说明与操作核对依据，不是要求实现外部业务功能 |
| 查看、新增、编辑、审批、导出 | 拆分为独立操作权限 |
| 查看本人、查看/编辑本人 | 仅提取查看、编辑作为功能目录候选；保留原文及来源行号，本人限定不转成数据权限，也不据此自动扩大参考角色授权，角色初始化映射须核对 |
| 五类角色列 | 初始角色配置参考，不能导入目录时直接给所有员工授予权限 |

“模块→功能点”作为一期菜单组织方案，不宣称等于真实软件的页面路由。页面、路由、按钮和业务数据仍由外部软件实现，权限中心只维护目录标识和授权规则。

本用例要求提供经过整理的初始化数据及可维护目录，不强制一期开发通用 Excel 上传导入器。可使用经核对的数据脚本初始化；后续如增加导入工具，仍须遵守下列预检规则。

### 系统进入权限（已确认）

每个业务系统登记一项唯一的系统级进入权限（类型 SYSTEM_ACCESS，如 `oa:access`、`hr:access`）；功能操作使用 FUNCTION_OPERATION。两类权限均只表达是否授予，不配置数据范围。系统进入权限不绑定功能或菜单。新系统登记时建立该权限项，但不自动授予任何角色。已有系统未登记或未授权时不能默认进入。

系统进入权限与菜单的“查看／进入页面”权限是不同概念：前者是整个系统的必要前提，后者只决定具体菜单可见。系统访问权限没有父目录，不受某个功能目录启停影响，但受系统、权限自身和授权来源有效性限制。停用它会使该系统所有员工功能权限暂不可用；重新启用可能恢复仍有效的既有授权，须展示全系统影响。功能清单的“全部”不自动包含此系统级权限。

这是本项目补充需求，并非 Excel 已明确列出的权限项。每个系统至多一项 SYSTEM_ACCESS，由数据库约束保证；存在角色引用时不物理删除。功能操作必须关联本系统功能并校验有效状态，不能因允许系统级权限而放松所有权限的功能归属检查。

## 3. 目录与编码规则

系统进入权限直接隶属业务系统；功能目录采用“业务系统→导航目录→功能菜单→操作权限”的逻辑关系；菜单和操作不是同一类对象，不把操作当作可打开页面。

| 对象 | 核心字段与约束 |
| --- | --- |
| 业务系统 | 稳定 ID、全局唯一系统编码、名称、说明、启停状态、版本 |
| 导航目录/功能菜单 | ID、系统 ID、系统内唯一目录编码、名称、节点类型、父级 ID、排序、状态、版本 |
| 权限项 | ID、系统 ID、权限类型、系统内唯一权限编码、名称、状态、版本；FUNCTION_OPERATION 必须关联所属功能，SYSTEM_ACCESS 不关联功能且每系统唯一 |
| 菜单可见条件 | 功能菜单关联一项本功能的查看/进入权限；纯导航目录不要求独立权限 |

一期示例编码：系统 `hr`，功能 `employee-register`，操作 `employee-register:view` 与 `employee-register:edit`。示例不是老师已有编码；外部系统需按最终登记编码调用。

- 编码建立后保持稳定，普通编辑只改显示名称、说明、排序等，不借改名改变权限含义。需要改变功能含义时新增编码、迁移配置并停用旧项。
- 目录父子必须同系统，禁止自身作父级或形成循环；操作必须属于本系统功能。已登记对象不通过编辑直接转移到另一系统。
- 操作目录只登记功能操作，角色—权限关系只记录是否授予。查看、编辑、新增、审批、导出各自独立，不从某项操作推导另一项。原始资料含本人限定时保留来源差异，核对功能授权映射后再初始化参考角色。
- 系统、目录、权限编码均由后端及数据库唯一约束保证；不同系统可有同名操作编码，但查询始终绑定系统。
- 一期优先使用停用保留历史，不提供级联物理删除已引用目录的操作。

## 4. 菜单可见条件

采用用户已确认规则：有某功能的查看/进入权限，UC-05 才返回其菜单；仅有编辑等操作不自动推导查看。已有“查看”可直接使用，不必另造“进入”。

以清单第 48 行为例：

```text
人力资源管理系统 hr
└── 员工信息管理（导航目录）
    └── 员工台账管理（功能菜单）
        ├── 查看：employee-register:view ← 该菜单的可见条件
        └── 编辑：employee-register:edit
```

员工已有 hr:access，且角色授予查看、编辑操作后，菜单可见；父级作为必要导航容器返回，不因此获得其他功能或父页面的操作权限。仅有编辑时操作仍按实际授权返回，菜单不自动显示。

新功能目录和操作可以先停用保存；启用可打开的功能菜单前，必须完成同系统、同功能且有效的查看/进入权限绑定。不能把其他功能的编辑权限当作本菜单可见条件。修改绑定只改变菜单筛选依据，不给任何角色增加操作授权，保存前展示影响。

## 5. 输入、输出与正常流程

输入包括系统/目录/操作字段、父节点、菜单可见权限、状态、修改原因、配置版本和请求编号；操作者取自登录上下文。输出为已保存对象及版本、变更结果和审计关联编号。

| 步骤 | 总管理员操作 | 权限中心处理 |
| --- | --- | --- |
| 1 | 打开目录维护，选择或新增系统 | 校验总管理员资格，读取系统及目录树 |
| 2 | 登记系统编码、名称和说明 | 校验必填字段及唯一性；系统登记不自动生成业务授权或分公司管理范围 |
| 3 | 新增或编辑导航目录、功能菜单 | 校验节点类型、同系统父级、编码及无循环 |
| 4 | 登记功能的查看、编辑等操作 | 校验权限编码、功能归属、有效状态；不会因为文字中出现“全部”自动生成未知操作 |
| 5 | 为功能菜单关联查看/进入权限 | 校验绑定目标有效且属于该功能；纯导航目录不重复创建查看权限 |
| 6 | 预览变更并填写原因 | 展示新增、修改、启停及关联角色/授权影响；提醒启用可能恢复既有关系的有效性 |
| 7 | 确认保存 | 后端复核身份、版本及全部约束，原子保存本次变更与审计 |
| 8 | 查看结果 | 显示直接生效或仍停用的对象；后续 UC-02 使用有效目录，UC-05/06 按有效状态查询 |

系统、目录、操作可按上述顺序分次维护；一次保存的多条变更整体成功或回滚，不要求一次录入所有系统。创建功能与操作之间的依赖可通过停用状态下分步保存解决。

## 6. 清单整理规则

- 按实际合并单元格还原系统和模块归属，不能把空白的合并区域误当成未知系统。
- 将 `view` 统一为“查看”，斜杠分隔的操作拆开，保留原始行号便于核对。
- “无”表示该参考角色没有该项授权，不代表删除这个功能的目录。
- “全部”是该功能经过核对的明确操作集合，不是通配未来新增操作；不能擅自补出清单未确定的删除等操作。
- 各角色列出现的明确操作可作为初始操作集合依据；结合功能说明核对。仅由“全部”或说明文字推测的额外操作应列为待核对，不自动授权。
- 原资料中的本人限定仅保留为来源差异；功能目录可提取查看、编辑候选项，参考角色授权须另行核对，不能自动转换为更宽泛的业务数据访问承诺。
- 空白权限单元格（如 I340）保留为待核对，不解释成“全部”或“无”。对应功能目录可以登记，但该参考角色的未知授权不生成。
- “系统管理后台”暂不混入本平台权限管理员管理权限，归属明确前单独列为待核对项。
- 同批次重复编码、无法确定的对象归属及冲突数据须输出问题清单，不能靠覆盖已有对象消除问题。导入目录与初始化角色授权是不同步骤。

## 7. 修改、停用与恢复

以下为一期统一有效性设计约定，供 UC-05/06 及实现共用：

| 变更 | 效果 |
| --- | --- |
| 新增系统或操作 | 只扩充目录，不自动给公司增加管理系统，不自动授予角色或员工 |
| 修改显示名称/排序 | 更新展示，稳定 ID 和权限编码不变，原关联保留 |
| 停用单项操作 | 所有引用该操作的角色暂不提供该项有效权限，其他操作不受影响 |
| 停用菜单绑定的查看权限 | 该菜单不再因这项权限可见；不顺带撤销仍有效的编辑等操作 |
| 停用整个功能节点 | 该功能菜单及其操作均不参与有效权限计算 |
| 停用导航目录 | 本稿采用子树有效性规则：该目录下功能及操作暂不参与计算，保存前展示子树影响 |
| 停用业务系统 | 不再接受其有效权限查询/检查，不删除角色及历史授权 |
| 重新启用 | 仅恢复对象状态；仍有效的既有授权关系可能重新生效，必须预览提示；已撤销关联不会恢复 |

停用父目录不批量改写子节点自身状态，只在计算时检查其有效祖先；重新启用父目录不会启用本身已停用的子节点。目录有效性是资源启停规则，不是角色继承或父菜单自动授权。

停用不等于永久撤权。若不希望恢复后旧角色继续提供该权限，应另走 UC-02 移除角色权限或 UC-04 撤销关联，不能靠删除历史数据代替审批。目录变更影响未执行申请时，UC-11 重新检查目标及版本/状态，不沿用失效条件执行。

## 8. 替代与异常流程

| 编号 | 条件 | 处理 |
| --- | --- | --- |
| E01 | 非总管理员、会话失效 | 拒绝维护；权限管理员只能使用目录申请角色配置 |
| E02 | 编码重复、字段缺失 | 拒绝本次保存，不覆盖既有对象 |
| E03 | 跨系统父子、操作归属不符、目录循环 | 整体拒绝 |
| E04 | 菜单可见权限属于其他功能或非法类型 | 拒绝绑定；启用功能菜单前必须完成合法绑定 |
| E05 | 修改已被别人更新的版本 | 返回冲突，重新读取预览 |
| E06 | 停用存在角色引用的对象 | 提示受影响范围后允许明确提交，保留关系及历史 |
| E07 | 尝试跨系统迁移或删除已引用目录 | 拒绝，采用新增与停用方式处理 |
| E08 | 初始化遇到空白、未知“全部”展开或含义不清栏目 | 标注待核对，不自动生成宽泛授权 |
| E09 | 同编号重复提交 | 相同内容返回原结果，不同内容拒绝 |
| E10 | 数据或审计写入失败 | 本次事务回滚，不出现部分目录或半完成绑定 |

## 9. 数据与结构化处理

逻辑实体：Application、Resource（导航/功能节点）、Permission、菜单可见权限关联、AuditLog；预览可读取 RolePermission、EmployeeRole 统计影响，不写这些授权关系。

每次保存目录变更、配置版本和成功审计采用同一本地事务。唯一性、外键、版本复核和循环校验在后端落实，不能只靠表单。权限 API 共用系统、祖先目录、功能、操作的有效性判断，避免全量查询和单项检查不一致。

```text
维护业务系统与权限目录
├── 校验总管理员资格
├── 登记系统
├── 维护导航与功能目录
├── 登记操作权限
├── 关联菜单可见权限
├── 校验编码、归属、层级、版本并预览影响
└── 原子保存目录变更与审计

UC-02：从目录配置角色权限
UC-05/06：使用同一目录与有效性规则返回权限结果
```

## 10. 验收示例

| 编号 | 场景 | 预期 |
| --- | --- | --- |
| UC01-T01 | 总管理员新增系统、模块、功能和操作 | 目录正确保存，无员工自动获权 |
| UC01-T02 | 权限管理员直接维护共享目录 | 后端拒绝 |
| UC01-T03 | 重复系统编码或同系统权限编码 | 拒绝，不覆盖旧对象 |
| UC01-T04 | 不同系统使用相同操作编码 | 可登记；API 始终按系统隔离 |
| UC01-T05 | 跨系统父节点或循环目录 | 整体拒绝 |
| UC01-T06 | 员工台账关联本功能查看权限 | 有查看授权时显示菜单，必要父级只作导航 |
| UC01-T07 | 只有编辑授权，或绑定另一功能查看权限 | 前者不自动显示菜单；后者拒绝绑定 |
| UC01-T08 | 新增操作，某角色曾按“全部”配置 | 不自动获得新操作，需 UC-02 重新申请配置 |
| UC01-T09 | 清单含本人限定、复合操作及英文 view | 提取查看/编辑候选功能，保留来源差异；未知角色映射不自动授权 |
| UC01-T10 | 空白单元格或“全部”集合未核对 | 保留问题，不生成猜测授权 |
| UC01-T11 | 停用单操作，另一个操作仍有效 | 只排除停用操作；查看停用可能影响菜单显示 |
| UC01-T12 | 停用功能/父目录/系统 | 按约定有效性阻断；UC-05 与 UC-06 一致 |
| UC01-T13 | 重新启用父目录，部分子节点单独停用 | 有效旧关联可恢复；停用子节点和已撤销关联不恢复 |
| UC01-T14 | 修改展示名、尝试跨系统迁移或物理删除引用项 | 改名保留身份；后两种操作拒绝 |
| UC01-T15 | 陈旧版本、保存或成功审计失败 | 冲突或回滚，无部分目录变更 |
| UC01-T16 | 重复请求，或登记新系统后查询公司管理范围 | 请求幂等；新系统不自动进入公司、部门及系统范围 |

### 系统进入权限补充验收

以下对外功能使用的允许结果要求当前公司、当前系统进入资格；后台目录维护、配置／分配／撤销申请只要求后台资格。

| 编号 | 场景 | 预期 |
| --- | --- | --- |
| UC01-T17 | 登记系统访问权限 | 每系统唯一，不绑定菜单；不自动授权 |
| UC01-T18 | 重复 SYSTEM_ACCESS，或提交数据范围配置 | 拒绝重复进入权限或超出本系统契约的配置 |
| UC01-T19 | 停用系统进入权限后重新启用 | 停用时功能不可用；恢复仅作用于仍有效的既有授权 |

## 11. 后续衔接

- 初始化资料仍需确定每功能“全部”的明确展开、I340 的参考授权及“系统管理后台”归属；不阻止建立通用目录结构，未明确授权不启用。
- 本稿补充的子树停用、恢复提示和直接维护规则属于设计约定，后续评审可调整，但 UC-05/06 必须同步。
- 数据库/API 设计落实字段、接口、错误码与调用身份登记。登记系统目录不代表真实外部系统已接入，调用凭据另按接入设计配置。
- 本轮不实现外部页面，不自动导入资料，不修改手工调整的用例图或现有后端。

### 功能权限补充验收

查看、编辑、新增、审批、导出分别登记为独立功能权限；角色配置只选择是否授予。目录、角色权限关系和查询/校验结果均不定义数据范围字段。SYSTEM_ACCESS 保持每系统唯一；新增操作不自动授予已有角色。
