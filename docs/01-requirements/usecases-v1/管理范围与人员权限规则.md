# 管理范围与人员权限规则

版本：V1.3，2026-10-16。沿用 2026-10-15 grill 已确认的功能权限与来源规则；依据用户 2026-10-16 明确要求，按实际参考材料收敛为公司—部门—岗位，替代 V1.2 的部门子树范围。本文与 UC-01～UC-11 共同构成当前需求基线。

## 1. 后台身份与管理范围

权限中心只有总管理员和权限管理员登录，普通员工是被管理对象，不登录本平台。权限管理员、部门管理员统一称为权限管理员，差别由总管理员指定的管理范围表达，不新增另一类后台身份。

组织与任职按参考材料采用“公司／分公司—部门—岗位”。同一公司内部门平级，不设计部门嵌套、部门父级、部门层级继承或子部门配置。部门表的“上级部门”用于识别总公司／分公司与部门的归属，不据列名引入部门嵌套；公司与分公司关系也不使管理资格自动跨公司继承。材料核对见 [参考材料与组织层级](../参考材料与组织层级.md)。

总管理员为每项管理范围指定一个公司、一个管理部门及可管理业务系统，部门必须属于该公司。范围只包含指定部门，不因同公司、组织展示关系或岗位名称自动包含其他部门。管理员在同一获准范围内协作，不按原申请人隔离，不合并不同任命的范围来伪造一次合法操作。

同一人可有多项明确任命，每次办理选择一项足以覆盖目标的范围依据。范围和任命分别保留稳定标识与版本；人员离任或暂时无人任命不自动删除范围依据与历史。取消旧版“每公司共享一个系统清单、每公司一至三名”的模型，不额外假定部门人数上限。

总管理员管理全部后台账号的创建、启用、停用、密码重置与任命。账号操作不自动授予业务权限或管理资格；停用账号拒绝所有旧会话，启用不复活旧会话。普通员工的外部业务账号仍由相应系统管理。

一期不设计公司、部门的启用/停用操作；保留组织展示、导入、更名及已确认的迁移检查。

## 2. 角色维护与分配

公司级共享角色只能由总管理员创建或修改配置。权限管理员可查看获准系统内已生效的公司级角色，并为其管理范围内符合条件的员工申请分配，不能修改共享角色以影响其他部门。

权限管理员可在指定部门和系统范围内维护部门角色；角色仍属于一个明确部门。员工须在该角色所属部门有效任职，只有其他部门任职不满足条件。公司级角色要求本公司有效任职，岗位不自动绑定角色。

角色配置、员工角色分配、一般的指定角色撤销仍经过 OA，批准并实际执行后才改变有效授权。

## 3. 员工授权的来源部门

角色归属、管理员的管理部门、员工授权的来源部门是不同概念。每条分配明细固定员工、角色、来源公司、来源部门及适用任职依据；来源部门取目标员工实际任职上下文，不能只保存操作者或执行时重新推断。

公司级共享角色同样必须有明确的授权来源部门。总管理员办理分配也明确该来源，不能用全局身份把来源写为空来绕过离岗关权。

相同员工、角色在 A/B 部门可以有两个独立授权来源；仅在相同来源内去重、防重。有效功能按同公司同系统的全部有效来源取并集并去重，关闭 A 来源不删除 B 来源或修改共享角色。

## 4. 离岗关权、一般撤销与全局停用

| 操作 | 办理人及边界 | 生效与结果 |
| --- | --- | --- |
| 离职/调离时关闭原部门权限 | 权限管理员在获准的公司、来源指定部门及系统内办理；总管理员也可办理 | 不等待 OA，确认后原子失效所选来源的授权，记录原因与审计；不修改员工全局身份、角色配置和其他来源 |
| 一般指定角色撤销 | 具备来源范围资格的权限管理员或总管理员 | 按 UC-04 发起 OA 申请，批准并执行后只撤指定关联 |
| 员工全局停用/恢复 | 仅总管理员，包括总管理员明确提交的 HR 变更批次 | 停用立即使全部业务授权及管理员任命失效、拒绝后台访问；恢复仅恢复身份，旧授权/任命不自动恢复 |

离岗关权是特定业务事件下的来源授权失效，不新增显式拒绝规则，也不是组织停用。界面使用“关闭原部门权限”，与“全局停用员工”和“一般角色撤销申请”区分；预览明确来源及可管理系统，不宣称关闭了范围外权限。

关闭后保留关系与历史。重新授予，无论员工去了新部门还是回到原部门，均需当前合法任职和新 OA 分配申请，不直接复活旧记录。新增任职、调岗资料仍由总管理员按 UC-10 维护/导入；离岗关权入口不赋予部门管理员修改全局 HR 资料的资格。

任职导入导致某来源不再有适用任职时，该来源授权持久失效；同一来源还有其他适用兼岗时保留。其他部门或公司的独立有效来源保留。即使员工到新部门后仍满足公司级角色条件，已经关闭的原部门来源也不恢复。

## 5. 旧申请与并发

来源关闭必须记录员工在该公司、来源部门、受影响系统的授权周期/版本变化，即使当时只有待执行分配申请、尚无已生效关联也要留下依据。关闭前的待执行新增申请失效；批量一项失效则整批不执行，不截取 OA 批准清单。

UC-11 按申请类型复核：配置查角色归属与版本；分配查原管理员范围依据、角色版本、来源部门及适用任职、来源周期和关系版本；一般撤销查原管理范围、仍有效的指定来源及关系版本，不机械要求当前授予资格或角色配置未变。迟到批准、失败重试、员工后来回到原部门都不能绕过关闭记录。关闭与执行并发时由本地事务确定先后：先执行则本次关闭使其失效；先关闭则旧申请不得执行。

原申请管理员离任本身仍不单独使合法申请失效；目标员工的来源授权被关闭是另一事件。执行时按原范围配置复核当前公司、部门和系统，不能换成当前查看人的更大范围。

## 6. OA 投递与页面状态

申请详情分别展示 OA 投递情况（待发送、发送失败、已关联 OA）、审批结果、执行结果。保存固定申请但尚未送达 OA 时不能声称 OA 已受理；重试同一固定申请，不重复创建、不改内容。具体字段和恢复机制在 API/详细设计确定。

一期不新增本地撤回或超时自动取消；等待 OA 最终结果期间保留既定占用规则并提示用户。失效授权只读，显示“已失效，无需再次撤销”。

## 7. 联合验收

| 编号 | 场景 | 预期 |
| --- | --- | --- |
| DR-01 | 管理员获准 A 部门、HR 系统 | 仅可办理 A 部门来源；同公司 B 部门、其他公司、未获准系统拒绝；管理 B 部门须有独立任命并选择该任命 |
| DR-02 | 两名管理员处于相同管理范围 | 可协作处理该范围方案；其他同公司管理员不自动可见 |
| DR-03 | 部门管理员试图修改公司级共享角色 | 拒绝；为范围内符合条件员工申请分配共享角色允许并经 OA |
| DR-04 | 公司角色 R 同时由 A、B 来源授给员工 | 关闭 A 后 A 失效，B 仍有效，操作结果继续去重返回 |
| DR-05 | 员工 A→B 调岗，A 来源授予公司级角色 | 原管理员关闭 A 来源立即生效，不等待 OA；B 不自动继承，另行申请 |
| DR-06 | A 来源关闭后收到旧批准，或员工返回 A 后收到旧批准 | 均拒绝执行旧方案，必须新申请；无已生效关联时同样有效 |
| DR-07 | 部门管理员请求员工全局停用/恢复 | 拒绝；总管理员可办理，恢复不复权 |
| DR-08 | 总管理员停用/启用后台账号 | 停用旧会话全部拒绝；启用不授予任命或业务角色、不复活会话 |
| DR-09 | 请求启停公司或部门 | 一期不提供该操作 |
| DR-10 | OA 投递失败后重试 | 页面区分投递与审批/执行，保留同一固定申请，不重复提交授权 |

原型可使用明确标注的代表性模拟数据；原始清单未决映射不阻止通用页面设计，不据此猜测正式授权。

## 8. 同一批次内明确离岗后重新任职（2026-10-17澄清）

明确END_EMPLOYMENT结束员工在某来源部门的最后一项适用任职，随后即使在同一原子批次ADD_EMPLOYMENT到该部门另一岗位，也按“离岗后新岗就职”处理：离岗事件推进相关来源周期，使旧授权、失去任职资格的任命及受影响旧待执行申请持久失效；新增任职不复权，业务授权需新OA申请、管理资格需重新任命。批次整体成功/回滚不抹去其内部已冻结的明确事件顺序。

同部门仍有其他适用兼岗时不关闭整个来源；仅岗位更名、未结束任职时不因名称变化关权。预检须冻结动作顺序与失效影响；同一批次包含多项相互矛盾或无法确定顺序的动作时阻断，不按最终名单自动改写离岗事件。该澄清不引入按岗位自动授权，仍不从缺行推断离岗。
