# UC-03 为员工分配角色

版本：V1.3，2026-10-16。状态：功能权限、部门管理范围及员工启停流程已按用户确认修订，可作为界面原型依据。

本轮更新：按参考材料采用公司—部门—岗位，部门平级；管理范围按公司、指定部门及系统指定；离岗关闭原部门来源权限立即生效，全局停用仅总管理员；保留功能权限、OA 及历史规则。

### 当前需求基线（2026-10-16，V1.3 平级部门与员工启停）

- 一期实现 RBAC0 权限管理：员工经角色获得权限，无角色继承、直接用户授权或显式拒绝。外部系统只做简单 HTTP 调用演示，不实现其内部业务。
- 角色属于一个公司和一个业务系统，可限定部门；公司级角色要求本公司有效任职，部门级角色要求在该部门有效任职，不适用于其他部门。岗位不自动绑定角色；任职条件与权限需要均未改变时，不因岗位名称变化更换角色。
- UC-05/06 按“员工＋当前公司＋业务系统”计算权限。仅合并该公司、该系统内的有效角色；系统进入资格与功能权限也必须来自该公司、该系统。公司上下文隔离的是功能授权来源，不定义业务数据访问范围。
- 授权同时校验角色适用条件与来源部门。离岗关闭原部门来源立即失效，其他独立兼岗来源保留；公司级共享角色不随调岗自动转移。仅总管理员可全局停用/恢复员工；恢复不复权。新授权经 OA，新管理任命由总管理员办理。
- 当前 RBAC 系统只管理功能权限。目录登记系统进入权限与功能操作，角色配置是否授予；不定义、保存或返回业务数据范围，不设计本人记录判断或行过滤规则。
- 员工、公司、部门使用稳定内部 ID；首次导入以源唯一用户名建立员工映射，组织分配稳定编码，更名不改变身份。人员变更模板明确新增任职、结束任职、停用、恢复等动作，不从文件缺行推断离职。
- 一期使用至少两个公司、两个系统的代表性数据，覆盖多角色、兼岗、公司授权隔离、功能操作独立与去重、审批生效、撤销、失效及重新申请。其余资料后续逐步补齐。

以上为本轮已确认规则，详细流程与验收必须遵循；描述的是需求设计，不代表代码已实现或真实外部系统已完成对接。

## 1. 用例概述

| 项目 | 说明 |
| --- | --- |
| 编号与名称 | UC-03 为员工分配角色，与用例图编号对应 |
| 目标 | 将已批准并有效的业务角色分配给范围内员工，批准执行后员工通过角色获得权限 |
| 发起者 | 权限中心总管理员或权限管理员；权限管理员按明确范围任命；同范围管理员共享明确的部门及系统范围，不限于自己申请的角色 |
| 外部参与者 | OA 系统按配置流程组织审批，返回可信最终结果 |
| 执行者 | 权限中心，通过 UC-11 接收审批结果并执行权限变更 |
| 触发 | 管理员在员工授权页面选择“分配角色”，或选择多名员工进行批量分配 |
| 前置条件 | 管理员登录且办理资格有效；目标员工有效并有适用的任职关系；角色已批准执行、可分配；角色所属系统有效 |
| 提交成功结果 | 保存待审批的员工角色分配方案，不改变员工当前权限 |
| 执行成功结果 | 原子保存批准的员工角色关系、执行状态及审计；下一次权限查询/校验反映新授权 |
| 失败保证 | 提交失败、审批驳回、方案失效或执行失败均不增加有效授权；不删除员工原有角色 |

UC-02 决定“角色拥有哪些权限”，UC-03 决定“哪些员工获得该角色”。角色本身获批不意味着所有员工都能直接获授；两项审批的对象不同。

### 管理范围与人员权限（V1.3 已确认）

完整规则见 [管理范围与人员权限规则](管理范围与人员权限规则.md)。总管理员指定公司、管理部门及系统，部门范围只包含指定部门，不跨部门或公司；同范围协作，不因同公司就共享整家公司权限。

公司级共享角色只由总管理员维护，权限管理员可为范围内合格员工申请分配；部门角色按明确归属维护。每次员工授权固定实际来源部门，不等同管理员的管理部门或角色归属。

离岗关闭原部门来源权限立即生效、不等待 OA；一般角色配置、分配及撤销仍经 OA。全局员工停用/恢复仅总管理员；恢复不自动复权。不设计公司/部门启停，普通员工不登录本平台。

## 2. 已确认规则与本稿约定

已确认：管理员按总管理员指定的公司、指定部门及系统范围办理；同范围协作。可申请分配范围内部门角色及本公司获准系统内已生效的公司级共享角色，均经 OA。

OA 是外部系统。权限中心只提交固定申请、接收可信最终结果，并在批准后校验和执行；不规定审批人、审批层级或内部流转，也不把这些内容列为本项目待确认事项。业务必要性在外部审批中判断，不额外增加确认操作。

一期通过模拟 OA 返回批准/驳回结果验证交互即可，不实现审批页面或流程引擎；模拟结果走相同的来源校验、申请匹配和防重复执行逻辑，模拟入口仅用于开发与验收。

为使流程可实现，本稿采用以下设计约定：

1. 同一方案只办理一个来源公司，可包含多个员工及系统。每条明细明确来源部门与目标员工适用任职；一次办理使用足以覆盖所有明细的范围依据，不跨任命拼接资格。
2. 一期批量方案整体批准、整体执行；任一目标越权或执行失败，整体拒绝/回滚。若需只批准部分条目，先拆分方案并重新提交，不按原整批批准结果自行截取。
3. UC-03 只增加明确选中的关系，不执行“用本次列表替换全部角色”。撤销及替换中的删除部分属于 UC-04。
4. 一期默认为执行成功后立即有效、不设置授权到期时间；未来如支持期限，期限必须进入批准内容，不能在执行时临时扩大。
5. 管理员分配资格不等于自动获得业务角色。权限管理员若作为目标员工，仍须走 OA；权限中心管理页面不能直接批准申请或借管理身份使授权生效。审批人员安排由外部 OA 负责。

### 系统进入权限（已确认）

角色分配本身不自动授予系统进入权限，权限管理员应在预览中看到所选角色是否提供该系统进入资格。允许分配仅含功能权限的角色；若员工尚无该系统进入权限，功能授权关系可以保存，但不可使用，不自动追加进入权限。

进入权限和功能权限可来自当前公司、当前系统的不同角色；不同公司或不同系统的进入权限均不能代替。跨公司兼岗分别查询各公司权限。是否可用由 UC-05/06 按完整有效角色集合计算，不以权限管理员可见角色范围代替员工实际授权集合。

### 申请归属、资格来源与自动执行（已确认）

角色和已提交申请不归原申请人个人；角色按公司/部门归属，员工授权明细按来源公司/部门归属。同范围管理员可协作，不能因同公司就访问其他范围。原管理员离任不单独阻断已提交合法申请，目标员工来源关闭则按来源周期拒绝旧批准；保留原提交人与固定内容。

提交时固定资格依据：总管理员为全局资格，权限管理员为明确公司、指定部门及系统的范围记录和版本。UC-11 按原范围记录复核，不能换用当前查看人的更大资格；按申请类型检查对应目标条件：配置查角色归属及版本，授予查来源部门/任职/周期与角色关系版本，一般撤销查指定来源及关系版本，不机械要求当前授予资格。总管理员原申请仍明确实际来源部门，不受普通管理员系统清单限制。

收到可信最终批准后，权限中心自动尝试执行合法的固定方案，不等待任何管理员点击接手或再次确认；原申请人离任、公司暂时没有权限管理员均不单独阻止执行。短暂故障保留批准依据并由服务端重试，重试仍检查原资格来源对应的范围及目标条件；仅实际范围或目标条件不再合法时标记失效。员工角色分配仍须检查目标员工有效任职，撤销历史关联不要求目标员工仍在原岗位。

一期不提供人为取消已批准方案的入口，不以“失效”代替任意取消。合法方案执行或在短暂故障后重试；实际条件不再合法则失效并记录原因。执行成功后如需调整，按 UC-02～04 重新申请。未提交草稿的删除规则保持独立。

未提交草稿可由范围内管理员删除并记录删除事件，释放变更占用；新角色从未提交、从未生效且无引用时一并删除空草稿。已正式提交或已生效的角色/申请保留历史，不借删除绕过审批。正式角色配置提交后须至少包含一项权限（系统进入权限或功能操作均可），不产生已生效空角色；清理员工授权走 UC-04。


## 3. 输入、输出与授权对象

| 输入 | 含义 |
| --- | --- |
| 来源公司、来源部门 | 每条明细固定员工的实际任职上下文，与角色归属、管理员的管理部门分开；总管理员办理也不得省略 |
| 分配明细 | 员工 ID＋角色 ID＋来源公司 ID＋来源部门 ID 的明确配对，逐条预览；不同部门来源可以共存 |
| 角色有效配置版本 | 记录审批时引用的已生效角色权限版本，防止审批期间角色内容改变 |
| 关系版本与来源授权周期 | 同来源防重，识别撤销/失效；来源关闭时即使未生成有效关联，也更新周期使旧批准不能复活 |
| 分配原因 | 例如职责需要、入职授权或兼岗授权，作为审批和审计依据 |
| 方案/编辑版本、提交请求编号 | 用于共同编辑冲突检测、重试幂等和定位固定方案 |

操作者由后端登录上下文取得；员工使用稳定 ID/统一标识，不用姓名匹配。角色使用 ID 关联，编码全局唯一，名称仅显示。

输出分为两次：提交返回方案编号、状态、实际新增明细；执行返回执行结果、实际新增关系及审计关联编号。拒绝、无变化、待审批、已批准待执行与已生效不可混用。

功能权限集合来自所选角色，权限管理员不能在分配页面为单个员工直接增加或移除操作。如需不同的功能组合，先通过 UC-02 配置合适角色。

## 4. 正常流程

| 步骤 | 管理员/外部系统操作 | 权限中心处理 |
| --- | --- | --- |
| 1 | 管理员进入员工授权页面 | 总管理员可办理全局目标；权限管理员按选定公司、指定部门和系统范围读取员工、部门角色及可分配共享角色 |
| 2 | 选择一名或多名员工 | 展示可见范围内的任职、已有角色及授权来源；其他来源不可见不等于没有授权 |
| 3 | 为员工选择拟新增角色 | 仅展示合法、已生效且满足角色任职条件的角色；公司级共享角色可以分配但不能由部门管理员修改 |
| 4 | 预览并填写原因 | 展示员工、角色、来源公司/部门、适用任职、功能摘要、角色及来源周期/关系版本；同来源有效重复项标为无变化 |
| 5 | 管理员确认提交 | 后端逐条检查人员/组织/系统/角色范围、任职、有效状态及版本，去除无变化项，固定实际新增明细 |
| 6 | 管理员查看提交结果 | 保存固定明细及原范围依据；分开展示 OA 投递、审批、执行状态，投递失败不表示 OA 已受理；原有效授权不变 |
| 7 | OA 按配置流程审批 | OA 对同一份员工—角色明细和角色版本作出结果；权限中心不建设审批引擎 |
| 8 | OA 交付最终批准结果 | UC-11 验证服务身份、方案及审批编号、内容摘要、最终状态和重复通知 |
| 9 | 权限中心执行方案 | 复核原范围依据、来源部门与适用任职、来源授权周期、角色及关系版本；整体保存全部新增关系、状态与成功审计 |
| 10 | 管理员查看结果；业务系统再次查询 | 页面显示实际执行结果；员工在当前公司、当前系统的功能权限按有效角色取并集，业务端按结果拦截操作 |

只收到 OA 批准但未成功执行时，页面显示“已批准待执行”或“执行失败”，不显示员工已获得权限。

## 5. OA、方案状态与重试

沿用 UC-02 的方案状态：DRAFT 草稿、PENDING 待审批、REJECTED 已驳回、APPROVED 已批准待执行、EXECUTED 执行成功、EXECUTION_FAILED 执行失败。INVALIDATED 已失效用于终止不能继续执行的方案。WITHDRAWN 已撤回作为可选扩展，一期不要求对接 OA 撤回接口；未支持时已提交申请不能本地直接取消或修改。

- 草稿可编辑；提交后员工列表、角色列表、角色版本和原因固定。改员工、增角色等均须重新提交审批。
- 驳回保留原方案和原因；复制成新草稿修改重提，不把原拒绝记录改成通过。
- 短暂数据库故障回滚后可以重试相同的已批准方案；重试仍按原资格来源检查对应范围、目标条件与版本。
- 来源部门权限已关闭、来源周期变化、员工停用、不再有来源任职或不满足角色适用条件，均使旧分配方案失效；不能因员工仍在同公司或后来回原部门而执行旧批准。
- 同编号不同内容拒绝；重复成功通知返回已执行结果，不重复建立关系或记录新的成功授予事件。
- 审批未通过期间，员工原有授权不受影响。一次新增方案失败，不清除已有角色。

### 任职变化与待执行分配申请

角色适用条件与授权来源分别检查：公司级共享角色要求本公司有效任职，部门级角色要求在角色所属部门有效任职。每个来源还要求对应部门的有效任职及未被关闭的授权周期。

A→B 调岗且 A 来源被关闭时，A 的公司级共享角色来源也失效，即使仍满足公司级角色资格。B 需新申请；其他适用兼岗来源保留。同一来源还有其他适用任职且未关闭时可保留；批量任一项失效则整批不执行。

### 多名权限管理员共同办理与并发

角色不属于原申请人。同范围管理员可协作编辑草稿、查看申请；员工分配明确实际来源部门。跨范围、同公司身份不自动取得可见性。保留原提交人和固定内容，不因其离任改写。

不同员工可同时申请同一角色。对员工＋角色＋来源公司＋来源部门内重复有效关系去重，拒绝同来源重叠新增申请；不同部门的同角色来源分别保存和审批，不相互覆盖。

授予与撤销的并发需要统一的关系版本/串行执行规则：关系即使已撤销也保留足以识别版本的记录或历史标记，旧授予审批不得因记录被删除而被误判为首次授权。与 UC-04、UC-11 联合设计，不以通知到达顺序决定最终权限。

## 6. 页面与数据示例

以合成员工甲、乙为例，不使用实际人员姓名或手机号：

| 员工 | 有效任职 | 本次选择角色 |
| --- | --- | --- |
| 员工甲 | 桥梁分公司工程部 | 桥梁公司—HR—普通员工；桥梁公司—项目系统—项目查询员 |
| 员工乙 | 桥梁分公司工程部 | 桥梁公司—项目系统—项目查询员 |

预览应明确显示 3 条新增关系，不能因为选择了 2 名员工、2 个角色就不加说明地产生 4 条授权。

审批执行前甲、乙不通过本次方案获得权限；执行后在各自已具备相应系统进入资格的前提下，甲可使用两个系统的相应功能、乙只获得项目系统相应功能。功能权限归被分配员工，不归提交权限管理员或角色创建人。

若员工甲还兼任其他分公司的岗位，其他分公司的角色与本次新增互不覆盖；本权限管理员不能以兼岗为理由扩大到另一公司角色的管理范围。部门专用角色要求员工在对应部门具备有效任职，不适用于其他部门，公司级角色要求在该公司具备有效任职；任职判断和管理员可操作范围分别校验。

建议页面分区：员工筛选、已有角色（只读）、拟新增角色、变更预览、申请原因、方案状态。按钮为“保存草稿”“预览”“提交 OA 审批”“取消”。已存在角色旁的取消勾选不得在本用例中暗中触发撤销。

## 7. 替代与异常流程

| 编号 | 条件 | 系统处理 |
| --- | --- | --- |
| E01 | 既无总管理员资格也无权限管理员资格、会话无效、超公司/员工/角色/系统范围 | 拒绝整次请求；不披露越权目标的敏感细节 |
| E02 | 角色未批准执行，或系统无效 | 不可选择；伪造请求也在后端拒绝 |
| E03 | 员工不存在、停用、任职不满足 | 提交或执行时拒绝，审批不能替代资格校验 |
| E04 | 相同来源的有效角色关系已经存在 | 不重复插入，不修改原来源/有效期；提交前作为无变化项排除。全部无变化则不发起审批 |
| E05 | 多人批量中一项无效或越权 | 整体拒绝；不擅自用原整批批准结果执行剩余项 |
| E06 | OA 驳回（可选扩展：可信撤回） | 不新增授权，保留历史；修改后新方案重提 |
| E07 | 审批期间角色配置版本变化 | 不以新权限内容执行旧审批，失效并要求重新申请 |
| E08 | 原权限管理员离任，或目标员工任职/角色状态改变 | 仅原申请人离任不阻止批准后自动执行；目标不合法时才失效重提 |
| E09 | 同关系存在未结束新增方案，或出现后续撤销／失效 | 重复方案冲突，陈旧授予失效；不能恢复已撤销关系 |
| E10 | 业务写入或成功审计写入失败 | 整批事务回滚，员工原有角色保留；执行失败记录在回滚后另行可靠保存 |
| E11 | 重复/伪造 OA 通知 | 合法重复成功通知幂等返回；无服务认证、非最终批准或内容不一致拒绝 |
| E12 | 管理员删除未提交草稿 | 记录删除、释放占用，不改变员工授权，不发起 OA 审批 |

## 8. 数据与事务边界

| 处理 | 读取数据 | 写入数据 | 一致性要求 |
| --- | --- | --- | --- |
| 选择员工和角色 | 办理管理员资格及对应管理范围、员工任职、角色/权限/系统、已有关系 | 无 | 分页查询；看不到的关系不能误删 |
| 保存/提交方案 | 当前资格、配对列表、角色版本、关系版本、重叠方案 | 方案、冻结明细与摘要、提交审计、防重信息 | 原子提交，不更新有效授权；并发提交同关系要受控 |
| 接收批准，UC-11 | OA 调用身份、方案、批准内容 | 已批准待执行状态、接收记录 | 可靠落地、幂等，不把批准等同于生效 |
| 执行方案，UC-11 | 提交资格依据及对应范围、目标版本、已批准明细 | 员工角色关系、来源、操作者、审批依据、执行状态、成功审计 | 整个批次同一本地事务；不能只校验后无锁地任意写入 |

逻辑实体：Employee、EmployeeAssignment、Role、RolePermission、EmployeeRole、AdminScope、AuthorizationChange 及其明细、AuditLog。角色定义和角色权限集合不由 UC-03 修改。等待 OA 期间不持有数据库事务。

单人/批量共享同一套规则。批量数量上限、分页和消息重试参数在接口设计确定，不据此承诺万人同时授权或特定性能。

## 9. 结构化功能分解草案

```text
员工角色分配
├── 读取范围内员工、角色及已有授权
├── 整理员工—角色配对明细
├── 校验总管理员或权限管理员资格及对应范围、员工任职与角色可分配性
├── 去重与新增差异计算
├── 检查版本及重叠申请
└── 保存固定方案、提交记录并关联 OA

OA：对具体员工获得具体角色的必要性作审批
UC-11：验证最终结果 → 按原资格来源复核范围及目标版本 → 原子新增关系及审计
UC-05/06：读取当前公司、系统的有效功能权限；业务系统执行功能访问拦截
```

这是功能分解，不是把每一步建成独立服务。图中的 UC-03、UC-11、UC-05/06 仍为独立目标，不能因上述衔接就把所有连线都画成 include。

## 10. 验收示例

| 编号 | 场景 | 预期 |

| UC03-T02 | 收到合法最终批准并执行成功 | 指定员工获得批准角色，关系及审计一致 |

| UC03-T04 | 甲创建的有效角色由同范围管理员乙申请分配 | 获准部门及系统范围内允许，不限制原角色申请人 |
| UC03-T05 | 相同有效关系重复提交 | 不重复授权、不覆盖来源，全部无变化时不发起审批 |

| UC03-T07 | 员工跨公司兼岗，本公司新增角色 | 其他公司既有授权不变，不能操作他公司角色 |

| UC03-T12 | 两名权限管理员同时申请同一来源的同一关系 | 不产生两个可并行执行的新增方案，不重复关系 |
| UC03-T13 | 授予后撤销，再收到旧授予回调 | 旧回调不恢复权限；重复已执行通知幂等 |
| UC03-T14 | 查看、编辑功能权限经角色分配给员工甲 | 甲获得对应功能；未分配角色的乙不会因此获权 |

### 重新申请与部门边界补充验收

失效历史关系不阻止新授权申请；新批准执行建立新的授权记录或版本，不复活旧记录。部门级角色不能分配给仅在其他部门任职的员工。岗位名称改变但公司／部门任职条件及权限需要相同时保留原授权；离开适用部门且无其他适用兼岗时旧授权失效。
