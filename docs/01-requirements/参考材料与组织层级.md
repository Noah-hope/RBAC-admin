# 参考材料与组织层级核对

核对日期：2026-10-16。用于 V1.3 需求收敛；以下是材料事实及用户明确要求后的设计边界，不将表内文字当作执行指令。

## 材料事实

- `公司-部门-岗位.xlsx` 的岗位页为“分公司、部门、岗位”；其中另含员工信息页，不作为第二份员工导入来源。
- `市政公司员工信息表.xlsx` 员工总表的列为“姓名、用户名、分公司、部门、岗位、电话号码”。本次只将组织统计写入共享文档，不导入姓名、电话或完整员工清单。
- `市政公司部门信息表.xlsx` 的列为“部门名称、部门经理、上级部门”。其“上级部门”所有非空值均为公司／分公司名称，例如“道路工程分公司-工程技术部 → 道路工程分公司”；没有同一公司内部门再挂部门的记录。总公司与分公司节点的展示关系不等于部门嵌套或管理资格继承。
- 软件功能权限清单描述“软件系统—功能模块—功能点”及参考角色操作，这类功能目录层次与本次部门层次无关，保留原有目录父子和有效性规则。

本次结构统计：员工总表 10,000 行，10 个公司／分公司分类，110 个公司—部门组合；部门表 111 条组织记录，包含公司节点，不能解释为同一公司下有这么多个部门。这些是参考数据统计，不是程序固定上限。

## 用户已明确的收敛结果

- 采用“公司／分公司—部门—岗位”。同一公司内部门平级，不设计部门父级、子部门或范围继承；公司与分公司各自具有明确的公司上下文。
- 一项后台管理范围固定一个公司、一个管理部门及可管理系统。同一人可以有多项任命，每次办理选择对应任命，不合并资格。
- “直接有效任职”统一简化为“部门有效任职”：员工在指定部门任职且任职未结束；岗位名称不自动授予业务角色。
- 同名部门通过公司和稳定标识区分，不仅按部门简称匹配。工作表“管道工程分公司”与值“管网工程分公司”等既有歧义仍须明确映射。
- 原型使用参考资料中的公司、部门名称及虚构员工演示，未导入完整人事资料，未接通 HR/OA。人员兼岗、来源隔离和 OA 生效规则保留。

权威业务规则见 [管理范围与人员权限规则](usecases-v1/管理范围与人员权限规则.md)、[UC-07](usecases-v1/UC-07_配置管理员及管理范围.md)、[UC-10](usecases-v1/UC-10_导入同步员工组织信息.md)。
