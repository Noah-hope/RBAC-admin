# 前端界面原型

**当前交付：** 用户已确认执行 [Material Design 3 改造方案](MATERIAL3-PLAN.md)。0.2.0 原型已实现并验证，[阶段评审](STAGE-REVIEW.md)后可作为 API 设计输入。按用户最新优先级（D-029），三项原型展示/演示补齐后续跟踪，不作为 API 启动或契约定稿的前置；相关业务规则保留。后续 API 1.2.0、数据库 1.1 及后端详细设计已交付，当前事实以 `docs/project/MEMORY.md` 为准；正式前端实现后置。

原型版本：0.2.0；说明更新日期：2026-10-17。基于 V1.3 需求，使用项目 `frontend-design` skill；保留 7 个管理主页面、独立权限调用演示及登录/帮助。界面使用统一业务称呼“权限中心”，不再展示早期视觉提案名称“衡序”。

浅色侧栏、白色表面、蓝色主操作、胶囊形导航与按钮，通过语义 Token 管理颜色、字阶、圆角及 8px 基础间距；中文/拉丁字体和 Material Symbols 本地加载。侧栏底部可打开“术语说明”，文案依据[团队术语表](../project/GLOSSARY.md)。顶部原型栏常显“切换为总管理员（演示）”按钮，切换后可返回部门身份；“原型演示工具”默认收起，提供身份/状态选择和权限调用演示。仅总管理员显示平台管理导航，部门身份隐藏无权菜单。业务流程继续使用内存模拟。

技术：Vue 3 + TypeScript + Tailwind CSS，Vite 构建。未增加 UI 框架；旧 `@lucide/vue` 包已移除，Material Symbols 采用本地 SVG。源码与锁文件位于 [prototype](prototype/)，资源来源及许可证见[本地资源说明](prototype/public/assets/README.md)。最新设计依据见 [MATERIAL3-PLAN.md](MATERIAL3-PLAN.md)，早期演进记录见 [DESIGN.md](DESIGN.md)，验证见 [VALIDATION.md](VALIDATION.md)。

840–1199px 首次打开默认显示图标栏，顶部“展开侧栏”可切换文字导航；小于 840px 继续使用抽屉导航。“系统与权限目录”的功能卡片标题置首，按钮随后，支持单项及全部展开/收起操作，不改变权限启停状态。父级目录只用于外部业务功能菜单的分组，不需要分组时选根目录；操作归属功能，不单设父级目录。

“登记操作”固定所属功能及功能编码，支持选择尚未登记的五类常用操作，也可填写自定义操作名称和编码。例如在“公文管理”登记“打印 / print”，完整编码为 `oa:items:print`。编码须以小写字母开头，可含数字及短横线，与业务系统使用的权限标识一致；原型校验必填、格式及重复，正式校验与约束以 API／数据库设计为准，真实后端尚未实现。常用候选不是业务类型上限，不自动增加原始清单未确认的实际操作。

登记成功后，到“角色权限”独立勾选新增操作，再按既定 OA 流程配置角色和分配员工。登记本身不会修改已有角色或员工授权，保存角色草稿也不生效；其他系统的角色不显示该自定义操作。未选择或填写操作时禁止空提交。

界面文案已按日常办理场景收敛：移除各页重复副标题、固定规则横幅、说明性页脚及变更申请固定流程图；办理范围压缩为紧凑栏，保留公司、部门和可管理系统。员工授权在仅一个部门时隐藏重复筛选区，多部门视角仍可筛选。顶部问号打开“页面帮助”，按当前模块查看规则，原型演示说明默认折叠；保留“界面原型／模拟数据”标识及身份切换。见 D-027。

文案维护采用以下约定：页面主体优先展示数据和操作；当前范围、业务状态、错误及无权限原因常显；字段格式、分配资格和危险操作影响在相关表单/确认中提示；一般业务规则放入页面帮助，统一概念仍可查术语说明。精简文字不修改授权规则，不删除关权影响、恢复不复权、OA 批准与执行结果的区别。

## 启动

先进入项目根目录 `rbac-admin`，再在 PowerShell 中运行：

```powershell
Set-Location docs/02-ui-design/prototype
npm ci
npm run dev
```

打开 **http://127.0.0.1:5173/**。默认只监听本机，进入权限管理员演示工作区；无需真实账号。直接点击顶部“切换为总管理员（演示）”即可查看系统目录、管理员与范围、员工组织；页面状态仍在折叠工具中。身份切换只是原型评审工具，不代表部门管理员在正式产品中可以自行升级身份。当前验证环境为 Node.js 22.19.0、npm 10.9.3，依赖版本由 `package-lock.json` 固定。

其他命令：

```powershell
npm run check
npm run build
npm run preview
```

预览构建默认地址为 http://127.0.0.1:4173/，需要先构建。请通过 HTTP 服务打开，勿直接双击 `index.html`。启动目录始终在本阶段内部，不新增根目录前后端工程。

建议先体验：

1. 在第一项目经理部查看林予安的来源抽屉，再切换第二项目经理部任命查看另一个独立来源。
2. 关闭第一项目经理部来源，再切换第二项目经理部任命确认其来源保留；该操作不等待 OA。
3. 为其他合格员工申请分配角色，在变更申请查看投递与审批。展开“原型演示工具”，分别模拟外部 OA 结果、执行故障和服务恢复。
4. 切换工程技术部任命，在权限调用演示中选择陈知远、人力资源系统：有进入与编辑权限，但不会自动出现员工信息查看菜单。
5. 切换总管理员，选择桥梁工程分公司，查看陈知远的另一公司兼岗：功能授权按当前公司分开。
6. 切换总管理员体验后台账号、管理范围和人员导入；普通员工没有本平台注册或登录入口。

## 模拟边界

- 新建角色不再要求手填编码，创建窗口只读提示“保存后自动生成”；保存后在列表及配置详情展示只读编码，更名或配置权限不改变编码。原型用全局内存序号生成 `ROLE_` 加六位数字的示例并检查已有编码，不重写旧样例编码。正式实现由后端生成、数据库保证全局唯一，具体生成算法、容量及并发处理待 API/数据库设计，不把浏览器模拟当作正式生成服务。
- 角色配置可保存草稿并继续编辑，满足条件的未提交草稿可删除；配置未保存关闭时可继续编辑或放弃。驳回申请可复制为新草稿、更新原因后重提；配置类重提可修改权限，分配/撤销类改变员工或来源时应回到业务页重新选择。
- 员工批量分配逐人固定实际来源，并在提交前预览配对；相同来源已有效项按无变化处理。列表统一 10/20/50 分页，角色/申请/审计等页可筛选；审计关联申请可按当前范围跳转。
- 系统目录支持显示资料、导航层级、菜单查看绑定及独立操作登记；父导航停用影响子功能计算。未绑定查看/进入的新功能保持停用，不能直接启用可打开菜单。这些是内存场景，未验证真实后端唯一性或事务。
- 组织/岗位资料在“导入组织资料”中使用固定 Mock 样例演示字段映射、更名、重复冲突及已有引用的跨公司迁移阻断；不宣称支持任意组织/岗位文件导入。人员变更 CSV 路径继续保留。
- 所有姓名、组织、账号、授权和事件均为虚构；初始样本含两个公司、三个系统、12 名员工，覆盖跨公司兼岗和同角色多部门来源。
- 状态仅在浏览器内存中模拟。刷新页面或侧栏“重置演示数据”会恢复示例；不使用后端或持久化数据存储。
- 登录仅验证演示账号与非空输入，不构成真实认证。账号建立/改密不保存所填密码，请勿输入真实密码。8 位密码长度只是本原型输入校验示例，正式策略待技术设计。
- 演示检查不是安全防护、并发控制或数据库事务。原型浏览器测试不作为后续正式逻辑的 TDD 证据；正式逻辑仍须先测试并实际观察失败。
- OA 批准/执行按钮只在明确标注的原型模拟工具中，不是正式产品的人工审批或强行执行入口；未实现 OA 内部审批流。
- 人员导入只支持当前公司、128KB 以内的演示 CSV，六个字段，不支持带逗号或引号转义的字段；未处理真实 Excel、全量课程数据、真实 HR 连接或跨公司混合批次。
- 系统目录仍使用代表性样例，不宣称已完成所有原始清单映射；角色草稿、逐人批量明细与申请覆盖主要路径，不穷举所有编辑恢复、多人并发和跨批次事务场景。
- 未设计正式 API/数据库，权限验证中的响应仅为界面演示；需求与原型已按 V1.3 同步；保留旧需求 PNG/SVG，按需生成。

## 浏览器验证

工程使用 Playwright；当前环境用已安装的 Edge 验证：

```powershell
$env:PLAYWRIGHT_CHANNEL='msedge'
npm run test:ui
```

其他环境可安装 Chromium 后运行：

```powershell
npx playwright install chromium
npm run test:ui
```

如果当前 PowerShell 已设置 `PLAYWRIGHT_CHANNEL`，使用 Chromium 前清除该变量。测试直接驱动本地原型，不访问外部 OA/HR。构建、依赖与测试产物由 Git 忽略，团队共享源码、锁文件和验证记录。
