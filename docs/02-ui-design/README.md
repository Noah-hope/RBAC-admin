# 前端界面原型

版本：0.1.0；更新日期：2026-10-16。基于 V1.2 需求，使用项目 `frontend-design` skill；首版及基础视觉调整已实现，待用户评审。展示名“衡序”及视觉方案是原型提案。

本轮按用户选择优先调整视觉风格：深蓝侧栏、钴蓝主操作和浅灰内容区，统一导航、表格、字号及表单样式。侧栏底部可打开“术语说明”，解释两种后台身份、两类业务角色、任职条件以及停用/关权的区别；文案依据[团队术语表](../project/GLOSSARY.md)。业务流程继续使用内存模拟。

技术：Vue 3 + TypeScript + Tailwind CSS，Vite 构建，`@lucide/vue` 图标。源码与锁文件位于 [prototype](prototype/)，设计依据与视觉自查见 [DESIGN.md](DESIGN.md)，验证证据与用例映射见 [VALIDATION.md](VALIDATION.md)。

## 启动

在 PowerShell 中运行：

```powershell
cd D:\NoahProject\rbac-admin\docs\02-ui-design\prototype
npm ci
npm run dev
```

打开 **http://127.0.0.1:5173/**。默认只监听本机，进入部门权限管理员演示工作区；无需真实账号。顶部可以切换总管理员和页面状态。当前验证环境为 Node.js 22.19.0、npm 10.9.3，依赖版本由 `package-lock.json` 固定。

其他命令：

```powershell
npm run check
npm run build
npm run preview
```

预览构建默认地址为 http://127.0.0.1:4173/，需要先构建。请通过 HTTP 服务打开，勿直接双击 `index.html`。启动目录始终在本阶段内部，不新增根目录前后端工程。

1. 打开林予安的来源抽屉：公司共享角色分别来自工程一组和工程二组。

## 模拟边界

- 所有姓名、组织、账号、授权和事件均为虚构；初始样本含两个公司、三个系统、12 名员工，覆盖跨公司兼岗和同角色多部门来源。
- 状态仅在浏览器内存中模拟。刷新页面或侧栏“重置演示数据”会恢复示例；不使用后端或持久化数据存储。
- 登录仅验证演示账号与非空输入，不构成真实认证。账号建立/改密不保存所填密码，请勿输入真实密码。8 位密码长度只是本原型输入校验示例，正式策略待技术设计。
- 演示检查不是安全防护、并发控制或数据库事务。原型浏览器测试不作为后续正式逻辑的 TDD 证据；正式逻辑仍须先测试并实际观察失败。
- OA 批准/执行按钮只在明确标注的原型模拟工具中，不是正式产品的人工审批或强行执行入口；未实现 OA 内部审批流。
- 人员导入只支持当前公司、128KB 以内的演示 CSV，六个字段，不支持带逗号或引号转义的字段；未处理真实 Excel、全量课程数据、真实 HR 连接或跨公司混合批次。
- 系统目录展示代表性功能层级，新增功能时登记所选独立操作；不宣称完整实现复杂层级迁移或所有原始清单映射。角色草稿/申请只展示本轮主要路径，未实现所有草稿编辑恢复、复杂批量明细和版本并发场景。
- 未设计正式 API/数据库，权限验证中的响应仅为界面演示；本轮不修改 V1.2 权威需求，不刷新需求 PNG/SVG。

## 浏览器验证

工程使用 Playwright；当前环境用已安装的 Edge 验证：

```powershell
$env:PLAYWRIGHT_CHANNEL='msedge'
npm run test:ui
```

其他环境可安装 Chromium 后运行：

```powershell
npx playwright install chromium
npm run test:ui
```

如果当前 PowerShell 已设置 `PLAYWRIGHT_CHANNEL`，使用 Chromium 前清除该变量。测试直接驱动本地原型，不访问外部 OA/HR。构建、依赖与测试产物由 Git 忽略，团队共享源码、锁文件和验证记录。
