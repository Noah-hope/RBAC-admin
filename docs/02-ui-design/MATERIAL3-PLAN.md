## 1. 设计依据与范围

采用项目 [frontend-design Skill](../../.agents/skills/frontend-design/SKILL.md)。需求依据为 V1.2 [管理范围与人员权限规则](../01-requirements/usecases-v1/管理范围与人员权限规则.md)、[用例说明](../01-requirements/usecases-v1/用例说明.md)、UC-01～UC-11；名称遵循[团队术语表](../project/GLOSSARY.md)。原型作为已有交付物核对，不作为业务规则来源。

已检查 `prototype/index.html`、`src/App.vue`、8 个页面组件、公共样式/组件、`data.ts`、`store.ts`、原型说明及验证记录。当前工程为 Vue 3 + TypeScript + Tailwind CSS + Vite，HTML 是 Vue 入口，无需回退到独立 HTML，也无需后续重新迁移到 Vue。检查以源码与既有验证记录为依据，本轮未重新执行浏览器测试。

方案阶段先交付页面、导航、Token、改造清单和验收计划；用户随后明确要求“执行此方案”，现已改造原型源码。仍使用 Mock 数据与浏览器内存，所有 OA/HR 事件均为演示，不调用真实后端 API；未添加 UI 框架依赖。

## 3. 导航与全局布局

1440px 桌面采用浅色工作区：左侧 256px 展开式导航，顶部 64px 工具栏，内容区两侧 24px 内边距。主体表面使用白色，画布和导航采用浅灰；不延续深色侧栏。采用“列表＋按需详情面板”，把持续办理的列表留在主区域，复杂配置使用独立宽面板。

| 区域 | 导航顺序或内容 |
| --- | --- |
| 授权管理 | 员工授权 → 角色权限 → 变更申请 |
| 操作记录 | 审计记录 |
| 平台管理（仅总管理员显示） | 系统与权限目录 → 管理员与范围 → 员工组织 |
| 侧栏辅助入口 | 术语说明、原型使用说明 |
| 原型演示工具（与产品导航分开） | 演示身份、页面状态、权限调用演示、OA 事件模拟及演示重置；默认收起控制区，始终保留“模拟数据”标识 |
| 顶部工具栏 | 导航展开/收起、当前位置、适用时的当前公司、帮助、个人账号与退出；不增加无需求依据的全局搜索、消息中心或通知数量 |

权限管理员不展示平台管理业务入口；直接进入不可访问视图仍显示明确无权限状态。“隐藏导航”只表达原型视角，不作为后端安全实现证据。外部调用演示入口移到演示工具，不改变 UC-05/06 的外部业务后端调用边界。

管理边界采用可见的上下文区：在员工、角色、申请及审计页展示公司、管理根部门及可管理系统，多项任命时明确选择本次依据，不能拼接任命。系统目录、后台账号等平台级页面显示“平台级管理”，不让当前公司误导其全局作用域。公司级组织资料和角色操作仍明确当前公司；切换上下文清除不再适用的选择并提示。

响应式按项目内容需要划分，以下 CSS 像素为本项目方案，并非把移动平台 dp 原样搬到 Web：

| 视口 | 布局策略 |
| --- | --- |
| ≥1200px（以 1440px 为主） | 展开式侧栏，部门筛选与数据表并排；详情面板宽约 480～560px，复杂配置面板 800～960px；主内容可滚动，表头及主要操作保持易找 |
| 840～1199px | 侧栏可收为 80px 导航轨，保留图标可访问名称与悬停提示；部门筛选移到可展开区域；详情以覆盖式面板打开 |
| <840px | 使用按钮打开模态导航，单列内容；复杂表单使用全屏面板，操作区域固定，表格仅自身横向滚动 |
| <600px | 页面边距 16px，筛选按行堆叠；保留状态和操作文字，提供表格横向滚动提示；不把表格截断为无法操作的内容 |

## 4. 设计 Token 方案

使用参考值 → 语义角色 → 组件映射的结构，统一 CSS 自定义属性，并让 Tailwind 映射同一来源。Material 的系统角色、CSS Token 命名参考 [Material Web 主题说明](https://material-web.dev/theming/material-theming/)；颜色配对参考[官方色彩文档](https://material-web.dev/theming/color/)。以下色值及组件尺寸是本项目的浅色蓝色方案，不宣称是 Google Workspace 官方完整主题或经过官方认证的组件实现。

### 4.1 颜色

| Token（`--md-sys-color-` 前缀） | 建议值 | 用途/配对 |
| --- | --- | --- |
| primary / on-primary | `#0B57D0` / `#FFFFFF` | 主要操作、焦点与强调文字 / 实心按钮文字 |
| primary-container / on-primary-container | `#D3E3FD` / `#041E49` | 选中导航、上下文强调 / 对应文字 |
| secondary / on-secondary | `#565E71` / `#FFFFFF` | 次级强调 / 配对文字 |
| secondary-container / on-secondary-container | `#DDE3F1` / `#141C2B` | 筛选选中、次级容器 / 对应文字 |
| surface / on-surface | `#F8FAFD` / `#1F1F1F` | 页面画布 / 正文及标题 |
| surface-container-lowest | `#FFFFFF` | 列表和主要表单表面 |
| surface-container-low / surface-container | `#F3F6FC` / `#EDF2FA` | 导航底色、表头、次级分区 |
| surface-container-high / highest | `#E7EDF6` / `#E1E7F0` | 浮层及更明确的分组层次 |
| on-surface-variant | `#444746` | 辅助正文、字段说明与次级图标 |
| outline / outline-variant | `#747775` / `#C4C7C5` | 必须可辨认的输入边界 / 非关键分隔线 |
| error / on-error | `#B3261E` / `#FFFFFF` | 校验错误、危险主操作 / 配对文字 |
| error-container / on-error-container | `#F9DEDC` / `#410E0B` | 错误说明区域 / 对应文字 |
| inverse-surface / inverse-on-surface | `#303030` / `#F2F2F2` | Snackbar 提示 / 提示文字 |
| scrim | `#000000`，项目遮罩透明度 32% | 模态背景；不用于正文 |

业务状态为项目扩展角色：`--app-color-success` 使用 `#146C2E`，容器 `#C4EED0`；`--app-color-warning` 使用 `#7A4F00`，容器 `#FFE8B2`。已失效/已停用使用中性表面及文字，均带明确标签，不能只靠红绿辨认。投递失败、审批驳回、执行失败使用各自状态文字，不能统一成一个“失败”。

### 4.2 字体与图标

字体族提案为 `Roboto, 'Noto Sans SC', sans-serif`，覆盖 400/500/700 字重，中文使用 Noto Sans SC；字体角色遵循[官方类型 Token 结构](https://material-web.dev/theming/typography/)。需要的字体拟在实现时本地托管，保留来源、版本和许可证，避免演示依赖 Google Fonts 在线服务；本轮尚未下载资产。

| 类型角色 | 字号 / 行高 / 字重 | 使用位置 |
| --- | --- | --- |
| headline-medium | 28 / 36 / 400 | 桌面页面标题 |
| headline-small | 24 / 32 / 400 | 小屏页面与对话框标题 |
| title-large | 22 / 28 / 400 | 详情面板标题 |
| title-medium | 16 / 24 / 500 | 表单分组、功能目录名称 |
| body-large | 16 / 24 / 400 | 主要说明、普通表单输入 |
| body-medium | 14 / 20 / 400 | 表格、详情、字段帮助 |
| label-large | 14 / 20 / 500 | 按钮、导航、表头 |
| label-medium | 12 / 16 / 500 | 标签和辅助状态 |

图标统一为 Google Material Symbols Outlined；拟优先取官方 SVG 本地资源，以封装的 `UiIcon` 提供 20/24px 尺寸，不引入图标 UI 框架。使用 `group`、`shield`、`assignment`、`history`、`account_tree` 等与含义对应的符号；选中项以背景及文字共同表达。图标来源和可用格式见 [Material Symbols 官方指南](https://developers.google.com/fonts/docs/material_symbols?hl=en)。纯图标按钮必须有可访问名称，装饰图标对读屏隐藏；不混用 Lucide 与 Material 的页面图标。

### 4.3 间距、圆角、表面与状态

| 类别 | Token / 值 | 应用 |
| --- | --- | --- |
| 间距（项目扩展） | `--app-space-1…6` = 8/16/24/32/40/48px | 使用 8px 基础体系；4px 仅用于图标与短标签等细微间距，字体行高独立设置 |
| 圆角 | `--md-sys-shape-corner-extra-small/small/medium/large/extra-large/full` = 4/8/12/16/28/999px | 文本输入 4px、标签 8px、主要数据表面 16px、模态对话框 28px、按钮/选中导航胶囊形；按组件语义映射 |
| 表面层级（项目映射） | `--app-elevation-0/1/2/3` | 0 无阴影；1 轻微抬升；2 菜单/下拉；3 对话框。正文列表主要用表面颜色和分隔，不给每行卡片加阴影 |
| 状态层（项目映射） | hover 8%、pressed/focus 12%；独立可见焦点环 | 基于组件前景色的状态层；禁用文字 38%、禁用容器 12%，同时有禁用原因。不能把 focus 状态层当作键盘焦点环 |
| 动效（项目扩展） | `--app-motion-fast/normal` = 120/200ms | 选择、面板与菜单反馈；支持减少动态效果，不自动循环播放装饰动画 |
| 触达范围 | 图标 20/24px，主要按钮视觉高度 40px，触达区域至少 48px | 桌面兼顾密度，小屏优先可触达；表格单行最小 56px，多行内容约 72px |

圆角以角色而非全站同一圆角管理，参考[官方 Shape 文档](https://github.com/material-components/material-web/blob/main/docs/theming/shape.md)。数据表、后台筛选和授权矩阵采用本项目桌面适配，不把所有后台组件宣称为 Material 3 官方标准组件。

## 5. 关键交互与组件规范

| 组件/流程 | 统一交互设计 |
| --- | --- |
| 搜索、筛选与分页 | 每页局部搜索，不新增全局搜索；保留输入标签、清除筛选和结果数量。列表统一 10/20/50 条分页，筛选变更回到第一页，空结果提供清除筛选；统计与详情同范围过滤 |
| 数据表格 | 姓名/目标左对齐，日期与编号易扫读；复选框提供全选/部分选择状态，批量条明确“选择当前页”，翻页后的选中规则明确。宽表独立滚动，操作可发现，不仅悬停显示 |
| 表单 | Outline 风格字段带持续标签；必填及编码规则在输入前可见。校验信息显示在对应字段下，提交失败定位首个错误；错误后保留输入，业务失败另显示页面级原因，不只短暂 Toast |
| 按钮及菜单 | 同一任务区一个实心蓝色主操作，次要操作为描边或文字按钮；危险操作有文字、红色语义及确认，低频操作进更多菜单；不机械给每页添加“新增/编辑/删除” |
| 系统目录 | 系统选择 → 层级目录 → 功能及操作明细，系统进入权限独立分区；目录父级、菜单可见条件、编码等以逐步编辑展示，不把操作文字自动推断成权限 |
| 角色配置 | 先确认归属及系统，再选择权限；进入权限与功能矩阵分区，支持搜索功能及按目录展开；查看、编辑、新增等独立勾选，无默认补授；提交前展示新增/移除、影响及原因 |
| 分配角色 | 选择员工 → 实际任职来源/系统 → 合格角色 → 配对明细预览 → 提交 OA。不同来源员工拆分处理或逐条明确配对，不用同一个来源套全部人；不合格角色说明原因并不可选 |
| 一般撤销 | 从有效来源关系选择，确认明确明细及原因，提交 OA；历史失效项只读，注明“已失效，无需再次撤销” |
| 关闭原部门权限 | 独立操作入口，选择获准来源和系统 → 影响预览 → 原因及确认 → 立即生效；显示旧待分配申请影响。提示其他独立来源可能保留，不宣称关闭范围外全部权限 |
| 全局停用/恢复员工 | 仅总管理员可见；突出全部业务授权及管理员任命影响，恢复明确“恢复身份，不恢复旧授权或任命” |
| 后台账号停用 | 账号页办理，确认中明确“禁止权限中心登录、旧会话失效；员工业务授权保留”，与员工停用使用不同标题 |
| 申请详情 | 顶部保留投递、审批、执行三组状态，下面展示固定变更和时间线；已批准待执行及执行失败不显示“已生效”；OA 模拟器仅在演示工具下展开 |
| 弹窗与详情 | 普通详情面板、复杂配置宽面板、短确认对话框分工明确；避免多层弹窗。原生 dialog 保留键盘焦点约束、Esc 关闭与焦点恢复；关闭有未保存编辑时提供继续编辑/放弃未保存修改的确认，不等同撤回已提交申请 |
| 成功/失败反馈 | 提交申请显示“申请已保存，OA 投递状态为…”，直接管理成功显示实际结果；Snackbar 用于轻量反馈，申请编号、失败原因及可恢复操作保留在页面或详情 |
| 加载、空、错误 | 初次加载显示骨架及状态文字，局部保存禁用重复操作；无数据与筛选无结果分开；故障有重试且不伪装成零权限；无权限和会话失效分别给出返回或重新登录路径 |

## 6. 旧版原型改造清单

以下“新增”指补齐既有 UC 内的界面及 Mock 演示，不增加业务模块。缺口判断来自当前源码；既有回归测试通过不代表已覆盖所有需求。

| 对象 | 保留 | 修改 | 删除/移出 | 新增或补齐 | 依据 |

## 7. 实施顺序与结构

方案确认后按以下顺序改现有 `prototype/`，不另建根目录前后端工程：

1. Token、字体及 Material Symbols 资产；记录来源/许可证，`UiIcon` 完成图标映射后再评估移除旧图标包，不混用或添加 UI 框架。
2. 全局浅色框架、导航、上下文区和演示工具分离；统一按钮、字段、表格/分页、标签、对话框与详情容器。
3. 员工授权 → 角色配置 → 申请详情，完整走通配置/分配/撤销及来源关权的核心演示。
4. 系统目录、后台账号及范围、员工组织预检和审计；按上表补齐已确认需求内的交互缺口。
5. 权限调用演示、登录/改密、帮助及统一异常状态；复核一致性及响应式，更新验证记录和共享记忆。

继续分离 `pages/`（页面）、`components/`（公共交互）、样式 Token 与 Mock 场景；`store.ts` 只承担演示状态。实现前梳理现有模拟数据结构对层级目录、草稿等场景的不足，调整仅服务于原型，不把它视为 API/数据库正式设计。前端可见性与模拟校验不替代未来服务端安全检查。

## 8. 验收计划

以下为方案确定时的验收计划；本轮已完成的检查及范围以 [VALIDATION.md](VALIDATION.md) 为准，不将计划条目一概记为完整验收：

- 构建及类型检查通过；1440×900 为主要桌面验收，补充 1024×900、768×1024、390×844，所有视图、主要表单及详情无页面级横向溢出。
- 各列表搜索、筛选、分页、批量选择可操作；必填、重复编码、越范围、任职不符、无变化、版本冲突反馈清楚且保留输入。
- 核心演示覆盖：角色草稿 → 配置申请 → OA 批准待执行 → 执行成功；分配/一般撤销批准执行后生效；关闭 A 来源保留 B；员工恢复不复权；停用后台账号不取消业务授权。
- 多项任命不拼接、共享角色只读、部门角色直接任职、跨公司及系统隔离；旧批准不能恢复已关闭来源；批量失效整体不执行，均用明确 Mock 场景演示。
- OA 发送失败重试原申请；批准未执行、执行失败、已失效、驳回及复制重提可区分；目录/任命/导入直接管理不伪造 OA 步骤。
- 主要文字与背景配对对比度至少 4.5:1，关键控制边界及焦点至少 3:1；边界线等非关键装饰不承担唯一识别任务。检查键盘导航、可访问名称、错误关联、Esc/焦点恢复及减少动态效果；不以色值静态校验代替整个页面无障碍验收。
- 复用并按新版结构调整现有 16 项原型浏览器回归，必要时补充业务结果场景；这些仍为原型验证，正式实现阶段继续遵守 TDD，不声称真实后端/API/OA/HR 已接通。
