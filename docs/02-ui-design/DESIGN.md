## 设计方向

面向部门权限管理员日常办理授权，以及总管理员维护平台。展示名“衡序 · 权限中心”仅为原型视觉提案。默认进入员工授权，不用装饰性数据看板作为首页。核心阅读顺序是：当前管理边界 → 员工及授权状态 → 明确来源 → 办理操作与结果。

采用安静、清晰的业务工作台：浅色侧栏、靛蓝主色、深色正文、紧凑表格和结构化详情。以始终可见的管理边界条作为产品特征；姓名、来源部门、系统进入资格与功能操作不混在一起。

| 色彩 token | 值 | 用途 |
| --- | --- | --- |
| 画布 | `#F5F7FB` | 内容区底色 |
| 表面 | `#FFFFFF` | 表格、表单和抽屉 |
| 正文 | `#19263D` | 标题与主要信息 |
| 主色 | `#5956D6` | 主操作、当前导航及边界标识 |
| 成功 | `#21866B` | 已生效状态 |
| 警示 | `#B96C19` | 待处理与影响提示 |

危险操作另使用语义红色，配合文字区分，避免只依靠颜色。中文以微软雅黑 UI / 苹方为主，数字使用等宽数字；标题 26px、正文 14px、辅助说明 12px。内容左对齐，正文段落不超过合理阅读宽度；桌面强调表格效率，小屏折叠侧栏，表格区域独立横向滚动。

## 布局比较与自查

方案 A：左侧导航 + 全宽统计卡片 + 下方列表。管理边界容易退居次要位置，统计卡片占据日常办理空间。

方案 B：左侧导航 + 顶部管理边界 + 部门树/员工列表 + 按需详情抽屉。采用 B；把统计缩成紧凑摘要，把空间让给授权来源和待处理事项。卡片用于任务分组，表格、抽屉、警告条使用不同层级，不统一套装饰圆角和阴影。

```text
┌──────────┬─────────────────────────────────────┐
│ 品牌导航 │ 当前位置                  演示身份  │
│          ├─────────────────────────────────────┤
│ 员工授权 │ 页面标题 / 说明             主操作  │
│ 角色权限 │ 管理边界：公司 > 部门树 / 系统       │
│ 变更申请 ├──────────┬──────────────────────────┤
│ …        │ 部门筛选 │ 搜索 / 状态 / 角色       │
│          │          │ 员工表格                 │
│ 演示说明 │          │ 来源详情按需从右侧打开   │
└──────────┴──────────┴──────────────────────────┘
```

自查后的调整：不放无实际依据的集团总人数、风险评分和趋势图；只展示当前模拟可管理范围的计数。以来源部门、OA 投递/审批/执行分栏和共享角色只读提示体现本项目，而非通用后台模板。无需照片、营销插画或 AI 生成位图。

## 状态与范围约束

- 仅总管理员和权限管理员进入原型；普通员工是被管理对象。
- 默认部门管理员拥有市政公司工程管理部及下级、HR/OA 两系统范围；另有总管理员演示视角。未获准部门不展示员工或记录数量。切换演示身份是原型工具，不是正式产品切权入口。
- 分配选择实际任职来源部门；公司共享角色同样带来源。部门角色只匹配角色所属部门的直接任职。
- 关闭来源保留其他独立来源；全局恢复不复权。旧待处理申请在来源关闭后失效，演示迟到结果时不能复活。
- 配置、分配和一般撤销提交不立刻生效；模拟外部批准与执行分别展示。页面不提供“管理员直接批准”业务入口，不设计 OA 内部审批页面。
- 覆盖加载、空结果、服务故障、无权限和会话失效；演示控制明确标注。表单有必填、重复、无变化、越范围或任职不符提示。
- 弹窗具有可访问名称、键盘焦点约束、Escape 关闭和返回原焦点；危险操作先显示实际影响并要求原因。

## 原型边界

源码位于本阶段 `prototype/`，仅浏览器内存模拟，刷新/重置恢复示例。不包含后端、正式 API 契约、数据库、真实认证和外部 OA/HR 连接。演示检查只用于验证交互，不构成安全实现。代表性姓名、账号和组织数据均为虚构。正式业务逻辑仍在后续阶段按 TDD 实现。

本轮采用 Vite、Vue 3、TypeScript 和 Tailwind 的 Vite 插件；依赖由锁文件固定，图标采用 lucide。版本以工程锁文件为准，不确定后端和正式工程选型。安装方式参考 [Tailwind 官方 Vite 指南](https://tailwindcss.com/docs/installation/using-vite)、[Vite 指南](https://vite.dev/guide/)及 [Vue TypeScript 指南](https://vuejs.org/guide/typescript/overview.html)。

## 基础界面调整（2026-10-16）

用户要求启动原型并调整基础界面，并选择优先改善“视觉风格：调整配色、导航和整体观感”。本轮采用深蓝侧栏、钴蓝主操作和浅灰内容区，细化公共样式与说明入口，业务规则沿用 V1.2，视觉细节继续待用户评审。

- 色彩：画布 `#F4F6FA`、表面 `#FFFFFF`、正文 `#223047`、主色 `#315CF5`、侧栏 `#17243D`、分隔线 `#DEE4ED`。辅助文字使用 `#5D697B`；以深蓝导航建立页面框架，蓝色管理边界条突出办理范围。
- 字体：继续使用本机微软雅黑 UI / 苹方，避免原型依赖外部字体服务；标题 26px，表格及表单主要内容 14px，辅助内容 12px，数字等宽。加深正文与表头，提升姓名、角色与状态的辨识度。
- 布局：保留左侧导航、顶部身份与公司、页面主体、右侧详情抽屉；内容左对齐。深色侧栏呈现当前工作区及公司，底部改为简洁帮助入口，原型工具单独标识；当前页面使用蓝底白字导航。
- 说明：增加可随时打开的术语说明抽屉，解释总管理员、权限管理员、两类业务角色、直接有效任职及三类停用/关权操作；文案依据团队术语表。角色列表与表单使用“公司级共享角色”。

自查：不新增概览统计卡片、营销插画或无业务含义的编号；基础改动集中在阅读层级与授权概念说明。术语说明用于辅助理解，本轮不增加真实认证、接口或业务处理能力。
