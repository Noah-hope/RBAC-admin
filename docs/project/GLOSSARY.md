# 项目统一术语表

更新日期：2026-10-17（Asia/Shanghai）。适用于团队成员、agent 的交流，以及需求、界面、接口和设计说明。

本文依据当前 V1.3 需求整理术语及其边界，不新增业务规则。业务行为与验收以[管理范围与人员权限规则](../01-requirements/usecases-v1/管理范围与人员权限规则.md)、[用例说明](../01-requirements/usecases-v1/用例说明.md)及对应详细用例为准；发现冲突时先核对来源并记录问题，再同步修订，不自行扩展含义。下列示例均为解释用途。

## 1. 团队使用约定

- 新会话开始工作时阅读本表。交流和新增文档优先使用“统一术语”列的名称；别称首次出现时注明对应的统一术语。
- “管理员”用于指办理人时，应说明总管理员或权限管理员；“角色”用于描述业务配置时，应说明公司级共享角色或部门角色。
- 描述授权操作时写清员工、角色、来源部门和业务系统；涉及权限管理员操作时补充其管理范围。描述状态时说明是账号、员工、角色、申请还是授权关系的状态。
- 讨论中出现新概念，先查本表。既有概念补充别称和例子；新增或改变业务规则时按需求变更流程确认，再更新本表、受影响文档和共享记忆，并一起提交 Git。
- 中文术语用于统一业务含义，不预先决定 API 字段、数据库表名或代码标识。未确认的命名建议不作为正式别称推广。

## 2. 平台、人员与后台身份

| 统一术语 | 别称或原有称呼 | 定义与使用边界 | 依据 |
| --- | --- | --- | --- |
| 权限中心 | 本平台、集中权限管理系统、RBAC 系统 | 本项目建设的平台，集中配置角色与功能权限、办理员工授权，并向业务系统提供权限查询和检查。普通员工不登录本平台。 | 用例说明、UC-05/06/09 |
| 业务系统 | 外部业务系统 | 接受权限管理的 OA、HR、项目等应用。员工在相应业务系统登录，由该系统调用权限中心检查功能权限。获得业务系统权限与获得权限中心后台资格分别判断。 | UC-01、UC-05/06 |
| 总管理员 | 权限中心总管理员 | 权限中心的全局后台管理身份，管理系统与权限目录、后台账号、权限管理员任命及管理范围；可维护公司级共享角色和部门角色，办理员工授权及员工全局停用/恢复。角色权限配置和一般分配、撤销仍遵循 OA 流程。 | UC-01～04、UC-07/09/10 |
| 权限管理员 | 部门管理员；旧文档中的公司专员 | 由总管理员任命，按指定公司、指定部门和业务系统范围开展工作的后台身份。可以维护范围内部门角色、为合格员工申请分配角色、申请一般撤销、直接办理离岗关闭原部门权限，并查看范围内记录。公司级共享角色配置、员工全局停用/恢复和后台任命由总管理员办理。 | 管理规则第 1～4 节、UC-07 |
| 员工 | 普通员工、被管理员工 | 业务授权的目标人员，具有统一标识及任职资料；员工身份本身不产生角色、系统进入权限或后台资格。具有后台身份的人员仍需分别判断其员工状态、账号和任命。 | UC-03、UC-09/10 |
| 后台账号 | 权限中心账号 | 用于登录权限中心的账号，由总管理员创建、启用、停用和重置密码。创建账号不自动产生权限管理员任命或业务授权；停用拒绝旧会话，重新启用不复活旧会话。 | UC-09 |
| 管理员任命 | 权限管理员任命、管理资格 | 总管理员将员工及其后台账号与明确管理范围关联形成的办理资格。同一人可有多项任命，取消任命本身不删除员工的业务角色。 | UC-07 |

“部门管理员”与“权限管理员”是同一类身份，本文及新增正式文档统一优先使用“权限管理员”。旧称“公司专员”不表示拥有整家公司管理资格。原型展示名“衡序 · 权限中心”属于待评审视觉方案，业务讨论统一使用“权限中心”。

## 3. 组织、任职与管理边界

| 统一术语 | 别称或原有称呼 | 定义与使用边界 | 依据 |
| --- | --- | --- | --- |
| 公司 | 任职公司、来源公司（应按上下文说明） | 角色归属、任职和功能授权计算的公司边界。跨公司兼岗分别计算对应公司的有效功能权限。本期不设计公司启停。 | 管理规则第 1～3 节、UC-05/10 |
| 部门 | 组织中的部门 | 直接归属于一个公司的平级组织单位，不设置部门父级或下级，用于任职、角色归属、后台管理边界及授权来源。本期不设计部门启停；“组织”出现在资料中时应具体说明公司或部门。 | 管理规则第 1～4 节 |
| 任职 | 员工任职、兼岗 | 员工在某公司、部门及岗位的有效工作关系；同一员工可有多个任职。岗位名称不自动绑定角色，导入任职不自动授权。 | UC-03、UC-10 |
| 部门有效任职 | 指定部门有效任职 | 员工实际在指定部门具有有效任职。部门角色按其所属部门有效任职判断资格，仅在其他部门任职不满足。 | 管理规则第 2 节、UC-03 |
| 管理范围 | 公司、指定部门及系统范围 | 总管理员为权限管理员指定的公司、管理部门和可管理系统集合，限制后台可办理的目标与操作。一次操作应选择足以覆盖全部目标的范围依据，不拼接不同任命伪造资格。 | UC-07 |
| 管理部门 | 指定部门 | 总管理员为某项范围选定的一个明确部门，必须归属于该公司；范围只包含该部门，不继承其他部门。管理多个部门须分别任命，办理时切换。 | UC-07 |
| 可管理系统 | 系统管理范围 | 某管理范围允许办理的业务系统集合。管理员可以管理该系统，不表示已获得该系统的员工业务权限。 | UC-07 |
| 同范围协作 | 同范围管理员协作 | 多名权限管理员在同一获准范围内共同处理角色和授权事项，不限于自己创建的记录；同公司不同范围不会自动共享资格。 | 管理规则第 1 节、UC-07/08 |

## 4. 业务角色与功能权限

| 统一术语 | 别称或原有称呼 | 定义与使用边界 | 依据 |
| --- | --- | --- | --- |
| 业务角色 | 员工角色；上下文明确时简称角色 | 员工获得一组业务系统功能权限的配置载体，一个角色属于一个公司和一个业务系统，可进一步归属明确部门。本期 RBAC0，无角色继承、直接用户权限或显式拒绝。 | UC-02/03 |
| 公司级共享角色 | 公司共享角色、公司级角色；原型标签“公司共享” | 同一公司、同一业务系统内可供多个部门员工申请使用的业务角色。仅总管理员创建和修改配置；权限管理员可为范围内合格员工申请分配。每次分配仍固定来源部门，不自动授予全体员工、不跨公司复用。 | 管理规则第 2～3 节、UC-02/03 |
| 部门角色 | 部门级角色 | 归属某公司、某业务系统、某明确部门的业务角色。总管理员或覆盖该归属与系统的权限管理员可维护；分配对象须在角色所属部门有效任职，不适用于只有其他部门任职的员工。 | 管理规则第 2 节、UC-02/03 |
| 角色归属 | 角色所属公司、部门及系统 | 角色配置自身的归属，决定维护边界及分配资格。公司级共享角色不限定具体部门；角色归属与员工某次授权的来源部门分别记录。 | UC-02、管理规则第 3 节 |
| 角色编码 | 角色 code、唯一编码 | 全局唯一且创建后稳定的角色业务标识，与可重名或修改的角色名称分开；内部 id 用作关联，不通过编码推断公司、部门或管理范围。界面按 D-023 采用自动生成、只读展示；当前原型仅模拟，正式生成及唯一性由后端与数据库保证。 | UC-02 R3、输入约定、D-023 |
| 角色草稿 | 待配置角色、未生效角色 | 已创建、尚未首次配置批准执行的角色，不可分配。已有角色的新修改方案待审批时，继续使用旧有效配置；方案状态与角色状态分别表达。本期无独立角色停用/恢复操作。 | UC-02 |
| 功能权限 | 操作权限、功能操作权限 | 决定员工能否执行某业务系统的查看、编辑、新增等独立操作。各操作独立授予，编辑不自动包含查看。公司和部门用于管理及授权来源隔离，本项目不设计业务行过滤等数据权限。 | UC-01/02/05/06 |
| 功能目录 | 导航目录、功能菜单组成的目录 | 描述某业务系统内功能入口的菜单位置与归属；导航目录用于分组，功能菜单对应具体功能。它与公司—部门—岗位结构分开，部门平级不影响功能目录的父子层次。 | UC-01 第 3～4 节 |
| 父级目录 | 上级菜单、上级分组 | 当前功能在同一业务系统菜单中的直接上级；根目录表示无上级菜单、直接归属系统。禁止跨系统父级及循环；目录层次不自动授予父页面或其他功能权限。 | UC-01 第 3～4 节 |
| 操作登记 | 登记操作权限、登记独立操作 | 为某业务系统的一个功能定义可配置的独立操作及其稳定编码；操作归属功能，不单独配置父级目录。可选择尚未登记的常用操作，或填写自定义操作名称及编码；同一功能内名称、编码不能重复。登记不会自动加入已有角色或授予员工。原型支持自定义登记，不以五类常用候选限制业务操作集合。 | UC-01 第 3、5、6 节 |
| 系统进入权限 | 系统进入资格、SYSTEM_ACCESS | 员工进入某业务系统的独立权限，经角色获得。进入系统与获得某项功能操作分别配置；进入资格本身不授予全部功能。 | UC-01/02/05/06 |
| 菜单可见性 | 可见菜单 | 由菜单对应的查看/进入权限生成；必要祖先可作为导航容器，不额外授予父页面或兄弟功能。只有编辑权限不会自动获得查看菜单。 | UC-01、UC-05 |
| 有效功能权限 | 员工有效权限 | 按员工、当前公司和业务系统，校验员工、系统、配置及授权来源有效性后，对有效角色提供的操作取并集并去重；使用功能还需满足系统进入前提。 | UC-05/06 |

“公司通用角色”是讨论过的命名建议，尚未确认为正式名称；目前继续使用“公司级共享角色”。公司级共享角色与部门角色的区别在配置复用及任职条件，不表达业务数据可见范围。

## 5. 授权、撤权与状态

| 统一术语 | 别称或原有称呼 | 定义与使用边界 | 依据 |
| --- | --- | --- | --- |
| 角色分配 | 员工授权、授予角色 | 为员工新增指定角色及来源的关联，需合法任职、管理范围和已生效角色；经 OA 批准并执行后生效，不替换其他已有角色。 | UC-03 |
| 授权来源部门 | 来源部门、原部门来源 | 员工某条授权固定的实际任职部门，连同来源公司、适用任职依据记录。它与管理部门、角色归属分别表达；权限管理员办理时来源须属于本次指定部门，公司级共享角色同样明确实际来源。 | 管理规则第 3 节、UC-03/04 |
| 授权关系 | 员工—角色关联、授权明细 | 员工持有角色的具体来源记录。相同员工、相同角色可有 A/B 两个部门的独立来源，同一来源内去重；关闭 A 不删除 B。 | UC-03/04 |
| 关闭原部门权限 | 离岗关权、关闭原部门授权来源 | 离职或调离时，管理员在获准公司、来源部门及系统内确认并填写原因，立即使相应来源授权失效并审计，不等待 OA；保留其他独立来源、角色配置及员工身份。 | 管理规则第 4～5 节、UC-04 |
| 一般角色撤销申请 | 一般撤销、指定角色撤销 | 对仍有效的指定授权关系发起 OA 撤销申请；批准并执行后只撤对应来源关联，不删除角色或其他来源。 | UC-04 |
| 员工全局停用 | 全局停用员工 | 仅总管理员办理，立即使该员工全部业务授权及管理员任命失效并拒绝后台访问；不以此代替部门范围内的离岗关权。 | 管理规则第 4 节、UC-10 |
| 员工恢复 | 全局恢复员工 | 总管理员恢复员工身份；旧业务授权和管理员任命不自动恢复，分别重新申请分配和任命。 | UC-03/07/10 |
| 后台账号停用 | 停用权限中心账号 | 总管理员禁止该账号登录并使旧会话无效，账号操作本身不删除员工业务授权。必须与员工全局停用明确区分。 | UC-07/09 |
| 来源授权周期 | 来源周期、来源版本 | 用于记录某员工、公司、来源部门及受影响系统的关权边界，阻止旧申请在关闭后因迟到批准、重试或返回原部门而恢复旧授权。具体实现待 API、数据库及详细设计确定。 | 管理规则第 5 节、UC-11 |
| 申请／变更方案 | 固定申请、固定方案 | 角色配置、分配或一般撤销的变更内容及其版本、范围依据、编号。提交后固定内容；投递失败重试原申请，驳回后修改另建方案。 | UC-02～04、UC-11 |
| OA 投递状态 | 待发送、发送失败、已关联 OA | 描述固定申请送往 OA 的情况；本地保存成功不代表 OA 已受理。本期不提供本地撤回或超时自动取消。 | 管理规则第 6 节 |
| 审批结果 | OA 批准、OA 驳回 | 外部 OA 对固定申请给出的最终结果，审批人员及流转由 OA 管理。OA 批准后仍需权限中心复核和执行。 | UC-02～04、UC-11 |
| 执行结果 | 待执行、执行成功、执行失败、方案已失效 | 描述权限中心是否实际提交获批变更。成功后授权才改变；执行失败不产生部分变更，方案已失效时不能借重试绕过条件变化。 | UC-11 |
| 授权审计记录 | 审计、操作追溯记录 | 记录申请、投递、审批、执行及直接管理操作的历史及结果，按当前管理资格和记录来源查看；历史快照不代替当前有效权限。 | UC-08 |

## 6. 交流示例

### 公司级共享角色

总管理员为甲公司的 OA 配置“OA 基础使用角色”，包含系统进入、查看通知和新增申请功能。财务部、研发部的权限管理员可分别为各自范围内员工申请分配同一角色，审批执行后生效。公司级共享角色统一维护功能配置，各次员工分配分别记录来源部门。

### 管理部门、角色归属与来源部门

管理员甲本次管理部门为“第一项目经理部”，获准系统为 OA。员工乙在该部门有效任职。甲为乙申请该部门角色时，管理部门、角色所属部门及授权来源均为第一项目经理部，分别记录其含义；申请公司级共享角色时，角色归属为公司，来源仍为第一项目经理部。第二项目经理部是平级部门；甲管理它时须有独立任命并先切换，不能因同公司自动管理。

### 申请与生效

建议表述：“员工乙的 OA 角色分配申请已关联 OA、审批已批准，但执行失败，权限尚未增加。”记录投递、审批及执行三方面事实，避免将“已批准”直接写成“已授权”。

### 三类停用／关权操作

| 沟通表述 | 准确含义 |
| --- | --- |
| 关闭员工乙在研发一组、OA 系统的原部门权限 | 立即关闭该来源，保留其他合法来源；管理员不得宣称已关闭范围外权限。 |
| 总管理员全局停用员工乙 | 该员工全部业务授权及管理员任命失效，恢复员工身份不自动恢复它们。 |
| 总管理员停用员工乙的后台账号 | 禁止该账号访问权限中心，员工在外部业务系统的授权不因这项账号操作而删除。 |
