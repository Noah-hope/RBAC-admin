# 功能权限范围变更

本文保留 V1.1 功能权限修订的历史验证记录；当前基线另含 [V1.2 管理范围与人员权限规则](../01-requirements/usecases-v1/管理范围与人员权限规则.md)，预览改为[按需生成](PREVIEWS.md)。

日期：2026-10-15。依据：用户明确要求“修改需求，当前 RBAC 系统只管理功能权限”。需求总览和 UC-01～UC-11 更新为 V1.1。

## 当前范围

员工通过有效角色获得功能权限：系统进入，以及系统内查看、编辑、新增、审批、导出等已登记操作。角色只选择是否授予权限；查看不自动包含编辑，编辑也不自动包含查看。

有效权限仍按“员工＋当前公司＋业务系统”计算。仅对同公司、同系统的有效角色取功能操作集合并集并去重；撤销一个来源时保留其他有效来源提供的相同操作，最后来源撤销后才失去该操作。

UC-05 返回系统进入资格、菜单和功能操作集合。UC-06 返回指定权限的 `hasPermission`；功能操作必须同时满足当前系统进入资格。示例中不再定义或返回数据范围字段。

## 移除内容

- 原有 SELF/ALL 数据范围、支持范围集合及角色权限关系上的 scope。
- 数据范围配置界面、范围修改审批内容和逐操作范围合并规则。
- 本人记录判断、业务行过滤与数据权限的演示、验收要求。

本项目不因此承诺对外部系统任何具体记录放行；外部系统自身的业务规则不由本次需求设计。

## 保留内容与来源处理

公司、部门仍用于后台管理边界、角色归属、任职资格和授权来源隔离，不是业务数据范围。系统进入权限、菜单可见条件、OA 批准后自动执行、幂等与事务一致性、人员停用/任职失效后不自动恢复等规则保留。

老师原始清单中的“查看本人/编辑本人”保留为来源差异。可提取查看、编辑作为功能目录候选，参考角色授权映射须核对；不自动将来源限定转换为更宽泛的授权，也不新增“本人权限”来继续实现数据权限。

本次仅落实已明确的功能权限范围变更。grill 审视提出的其他流程建议尚未确认，不随本次修改写成已确定业务规则。
