# 集中权限管理系统：第一期用例说明

版本：V1.0，2026-10-13。状态：本轮需求审视已确认的最终用例基线，供小组设计与验收使用。

本版按最新讨论支持操作权限与本人数据范围；角色方案采用“组织归属＋业务系统＋可配置角色”。它是待小组评审的设计稿，不代表教师已确认全部规则，也不代表现有后端已实现所有用例。本版为统一需求基线，不与早期讨论稿混用。

### 最终需求基线（2026-10-13）

- 一期实现 RBAC0 权限管理：员工经角色获得权限，无角色继承、直接用户授权或显式拒绝。外部系统只做简单 HTTP 调用演示，不实现其内部业务。
- 角色属于一个公司和一个业务系统，可限定部门；公司级角色要求本公司有效任职，部门级角色要求在该部门直接有效任职，不自动覆盖下属部门。岗位不自动绑定角色；任职条件与权限需要均未改变时，不因岗位名称变化更换角色。
- UC-05/06 按“员工＋当前公司＋业务系统”计算权限。仅合并该公司、该系统内的有效角色；系统进入资格与功能权限也必须来自该公司、该系统。公司数据隔离、SELF 对象判断和过滤由业务系统实施。
- 任职变化后不再满足角色条件的授权立即失效；有其他符合条件的兼岗则保留该授权。员工全局停用使其全部业务授权及公司专员任命失效，不区分临时停用与离职。保留历史，不物理删除；恢复身份或任职不自动恢复失效授权，业务角色重新申请 OA 批准，专员由总管理员按 UC-07 重新任命。
- 操作目录明确支持范围：有明确本人语义的操作可支持 SELF/ALL，其他功能操作一期仅支持 ALL；SYSTEM_ACCESS 不适用范围，scope=null。配置及执行均校验所选范围属于支持集合。
- 员工、公司、部门使用稳定内部 ID；首次导入以源唯一用户名建立员工映射，组织分配稳定编码，更名不改变身份。人员变更模板明确新增任职、结束任职、停用、恢复等动作，不从文件缺行推断离职。
- 一期使用至少两个公司、两个系统的代表性数据，覆盖多角色、兼岗、公司隔离、本人范围、审批生效、撤销、失效及重新申请。其余资料后续逐步补齐。

以上为本轮已确认规则，详细流程与验收必须遵循；描述的是需求设计，不代表代码已实现或真实外部系统已完成对接。

## 1. 范围、参与者与共通规则

系统边界是集中权限管理系统。普通员工是被管理对象和业务系统用户，不是本平台管理后台的直接参与者。HR、OA、业务系统是边界外参与者；数据库是内部实现，不画成参与者。

| 参与者 | 职责 |
| --- | --- |
| 权限中心总管理员 | 系统/权限目录、全部公司及系统的角色配置、员工授权、管理员范围与审计；不在本项目规定其 OA 审批职责 |
| 公司权限管理专员 | 每公司 1～3 名（可仅 1 名），共同拥有总管理员配置的本公司范围内角色配置申请权及员工角色分配、撤销申请权；不按角色申请人隔离 |
| 业务系统 | 自行认证员工，以服务身份调用权限查询/校验，执行实际拦截和过滤 |
| HR 系统 | 提供组织、员工及任职信息；一期用文件或模拟数据源 |
| OA 系统 | 外部完成审批并返回最终批准/驳回结果；内部人员与流转不展开，一期模拟结果交互 |

### 已确认的一期交付范围

- 软件系统采用老师的清单，不限制一个公司只能对应一个系统。
- 支持操作权限；“查看/编辑本人”中查看和编辑均为 SELF。
- 允许创建角色、配置角色权限；允许员工兼岗。

共通规则：只允许正向角色授权；不做角色继承、显式拒绝或直接用户权限。权限分为系统级进入权限及系统＋功能＋操作权限；功能范围记录在角色权限关系，进入权限不配置范围。后台办理范围和统一身份由权限中心校验，外部业务记录归属由业务系统校验；不能相信浏览器自报身份。停用或失效对象不参与有效权限计算；功能使用还必须满足当前系统进入资格。数据库故障与普通权限不足分别处理。

### 已确认：系统进入权限

每系统登记唯一 SYSTEM_ACCESS（如 hr:access），不绑定菜单，scope=null。角色通过原 OA 流程明确配置它，不自动附赠，也不包含在功能清单“全部”中；进入权限和功能权限可来自同系统不同有效角色。

- UC-05：返回 canAccessSystem；无进入资格时为 false，菜单与操作为空。有进入资格但无功能权限时为 true，集合仍为空。
- UC-06：直接检查进入权限返回 hasPermission 及 null 范围；检查功能操作时先检查进入资格，没有则 false。有进入且有操作权限才返回 true 和 ALL／SELF。
- 失去最后一个进入来源后，功能暂不可用但原关联保留；再次获授进入权限后尚有效的功能可恢复。其他系统不受影响，停用员工仍全局拒绝。
- 后台专员身份、公司可管理系统与业务进入资格分开，不相互自动授予；外部登录认证和实际拦截仍由外部系统负责。

菜单自身的查看/进入页面权限不同于系统级进入权限。SYSTEM_ACCESS 不受菜单层级限制；功能操作仍检查功能及祖先目录的有效状态。外部业务功能允许场景以具备当前公司、当前公司、当前系统进入资格为前提；后台管理操作只要求后台资格，不要求业务系统进入权限。

### 统一管理与公司边界（已确认）

“公司权限管理专员”即公司授权管理员（早期图中称部门授权管理员）；总公司和各分公司各自指定 1～3 名，可仅一名。公司人员范围按明确公司归属及所属部门层级计算，遇到另一个公司节点停止，不因总公司位于组织树上层而包含全部分公司。

权限中心总管理员可管理所有公司、所有系统及所有公司专员，也可办理 UC-02～04；公司专员仅在本公司获准系统内办理。双方的业务角色配置、分配、撤销均经过 OA。总管理员跨公司办理时仍明确目标公司；每份申请按一个公司归属保存，系统状态、目标合法性及版本校验照常执行。

一期不配置逐操作及 ALL／SELF 的申请上限，也不逐个指定可分配角色。获准系统目录内的合法权限可以申请，角色授权内容仍由 OA 审批。后台资格不自动产生外部业务系统进入权限。

### 申请归属、资格来源、自动执行及删除（已确认）

角色和已提交申请归属目标公司，不归原申请人个人。原申请人离任或失去后台管理资格，仅影响其后续人工操作，不删除有效角色，也不单独使已提交申请失效。保留原提交人、提交时资格依据与固定内容；同公司有资格专员或总管理员可查看和处理后续事项，但不得改写原申请身份或批准内容。

提交时校验当前办理管理员并固定资格来源：总管理员使用全局管理资格，公司专员使用目标公司的任命及系统范围。UC-11 执行时核对提交时合法依据；总管理员原始申请不受公司专员的系统清单限制，专员原始申请仍须符合该公司当前获准系统范围。总管理员查看或处理专员申请，不改变原申请的资格来源，不能绕过已经缩小的公司范围。双方均明确目标公司，并按申请类型校验组织归属、目标条件及版本。

收到可信最终批准后，权限中心自动尝试执行合法的固定方案，不等待任何管理员点击接手或再次确认；原申请人离任、公司暂时没有专员均不单独阻止执行。短暂故障保留批准依据并由服务端重试，重试仍检查原资格来源对应的范围及目标条件；仅实际范围或目标条件不再合法时标记失效。员工角色分配仍须检查目标员工有效任职，撤销历史关联不要求目标员工仍在原岗位。

一期不提供人为取消已批准方案的入口，不以“失效”代替任意取消。合法方案执行或在短暂故障后重试；实际条件不再合法则失效并记录原因。执行成功后如需调整，按 UC-02～04 重新申请。未提交草稿的删除规则保持独立。

未提交草稿可由范围内管理员删除并记录删除事件，释放变更占用；新角色从未提交、从未生效且无引用时一并删除空草稿。已正式提交或已生效的角色/申请保留历史，不借删除绕过审批。正式角色配置提交后须至少包含一项权限（系统进入权限或功能操作均可），不产生已生效空角色；清理员工授权走 UC-04。

### 本轮补齐的四项功能边界

- UC-09 增加总管理员创建后台账号子流程，关联有效员工、登录名和员工账号唯一、临时密码强制修改；账号创建与 UC-07 任命分开。
- 一期不提供独立角色启停，角色区分待配置与已生效；系统、目录、权限和员工的既定启停规则保留。
- UC-10 阻止已有角色、授权或其他历史引用的部门及其子树直接跨公司迁移，不能通过改父级隐式转移管理范围。
- UC-03/11 根据目标员工是否仍符合目标角色的任职条件决定分配申请能否执行，调岗本身不构成失效理由；已生效旧授权不再满足任职条件时失效，保留历史且不自动恢复。

## UC-01 维护业务系统与权限目录

详细版本见 [UC-01_维护业务系统与权限目录.md](UC-01_维护业务系统与权限目录.md)（V1.0，2026-10-13），包含清单映射、正常流程、异常、启停规则、结构化分解及验收示例。

- **目标/参与者**：权限中心总管理员登记接入系统、导航目录、功能菜单及操作权限；沿用直接维护并审计的设计，不接入 OA。
- **资料依据**：老师清单中的系统、模块、功能点及操作作为初始化依据；模块/功能点用作一期模拟菜单，不要求实现外部页面。
- **流程**：校验资格 → 登记系统 → 维护目录 → 登记操作 → 关联菜单查看/进入权限 → 校验并预览影响 → 原子保存和审计。
- **编码/归属**：系统编码全局唯一，目录和权限编码各自在系统内唯一；稳定编码不随显示名称变化，禁止跨系统父子、操作归属和目录循环。
- **菜单可见**：功能菜单绑定本功能的查看/进入权限，已有查看无需另造进入；父级仅作导航，不继承授权。
- **初始化**：规范 view、拆分复合操作及本人范围；“全部”是明确的操作集合，不是 ALL 范围或未来操作通配；空白及未知项不猜测授权，五类角色仅作配置参考。
- **新增/启停**：新增不自动授权、不自动扩大公司管理范围。停用保留历史；本稿约定父目录停用使子树暂不参与有效授权，恢复时仍有效的旧关联可能重新生效，须提示影响。
- **异常/事务**：重复编码、非法绑定、陈旧版本拒绝；目录、版本与成功审计整体提交或回滚，不级联删除已引用项。
- **验收 AT01**：新增操作后原角色不自动获权；菜单按绑定查看权限显示；目录启停与 UC-05/06 的有效性计算一致。

## UC-02 创建角色并配置权限

详细版本见 [UC-02_创建角色并配置权限.md](UC-02_创建角色并配置权限.md)（V1.0，2026-10-13）。本轮简化外部 OA 边界，保留方案状态、全局唯一编码及重提和版本规则。

- **发起者**：权限中心总管理员或公司权限管理专员；公司专员每公司 1～3 名，由权限中心总管理员指定并配置申请范围；总管理员可跨公司、跨系统办理，专员在本公司获准系统内提出配置；不设置逐操作及 ALL／SELF 申请上限。同公司在任专员共享范围内角色的配置申请和员工分配资格，不限自己申请的角色；员工角色分配也须经 OA 审批，见 UC-03。
- **外部审批**：OA 完成审批并返回最终结果；审批人员和流转层级由 OA 决定，权限中心不实现审批页面或引擎。
- **输入**：角色名称、编码、组织、系统、操作权限变更与范围、基础版本、原因和请求编号。
- **流程**：保存角色草稿/选择已有角色 → 配置操作与范围 → 展示变更和影响 → 后端范围及版本校验 → 提交固定方案 → OA 审批 → UC-11 接收可信最终结果并执行。
- **生效**：提交不生效，审批不等于执行成功；新角色草稿不可分配，首次执行成功后激活，已有角色等待审批时继续使用旧配置。
- **状态**：草稿、待审批、已驳回、已批准待执行、执行成功、执行失败；失效为补充终止状态，撤回对接为可选扩展。OA 批准不等于权限已生效。
- **编码与版本**：角色 code 全局唯一、id 用作关联；同一角色仅一份未结束配置方案，审批绑定固定编号/内容/版本。
- **异常**：越范围、跨系统、陈旧版本、审批内容不一致或来源不可信均拒绝；驳回后复制成新草稿修改重提，原记录保留；迟到通知不覆盖新配置。权限中心普通管理页面不能直接将方案标为已批准。
- **事务**：草稿保存与审计同事务；方案提交独立事务；实际配置、执行状态、版本与成功审计由 UC-11 原子提交。
- **验收**：合法范围内的专员申请可提交；未收到可信最终批准结果不能生效；批准并执行成功后本人查看/编辑限制实际生效；其他角色保持不变。

## UC-03 为员工分配角色

详细版本见 [UC-03_为员工分配角色.md](UC-03_为员工分配角色.md)（V1.0，2026-10-13），包含正常流程、状态、异常、数据与事务、结构化功能分解及验收示例。

- **目标/发起者**：总管理员在全部公司及系统内、公司权限管理专员在公司共同管理范围内申请给员工分配有效角色，支持批量和兼岗；不限于自己申请的角色。
- **触发/前置**：选择员工授权；办理管理员已认证且资格有效，员工有效并具有适用任职；角色已批准执行、可分配，所属系统有效。
- **输入**：明确的员工—角色配对列表、来源组织、角色有效配置版本、授权关系基础版本、分配原因、方案与请求编号。
- **主流程**：筛选范围内员工 → 查看已有授权 → 选择有效角色 → 预览新增明细 → 后端校验范围/任职/版本并排除无变化项 → 保存固定方案 → OA 审批 → UC-11 接收可信最终结果 → 重新校验并执行 → 返回生效结果。
- **审批与状态**：必须经 OA 审批；具体审批人员和流程由外部 OA 决定，不作为本项目待确认或实现内容。提交仅进入待审批，批准也不等于执行成功；原有授权持续有效。
- **替代/异常**：重复有效关系不重复授权；批量中任一项越权则整体拒绝；驳回后修改并以新方案重提；角色版本、目标员工任职或原资格来源对应范围变化导致目标不合法时旧方案失效；仅原申请人离任不阻止合法批准方案自动执行；重复成功通知幂等，旧通知不得恢复已撤权限。
- **输出/后置**：提交输出方案编号和状态；执行成功后新增批准的角色关系，员工权限按有效角色取并集，ALL/SELF 来自角色配置。
- **事务/数据**：方案提交不修改有效授权；UC-11 可靠保存批准结果，再在本地事务中统一提交整批角色关系、执行状态与成功审计，失败整体回滚。
- **规则**：本用例只新增，不以所选角色替换已有全部角色；跨系统兼岗由多个单系统角色实现，其他组织的授权不被覆盖。不同员工可同时申请同一角色，相同来源的同一关系避免重叠申请。
- **验收 AT03**：为合成员工甲申请 HR 普通员工与项目查询员，审批执行前权限不增加；批准并执行后各系统返回各自权限；越范围拒绝，原有角色保留。

## UC-04 撤销员工角色

详细版本见 [UC-04_撤销员工角色.md](UC-04_撤销员工角色.md)（V1.0，2026-10-13），包含正常流程、异常、OA 边界、结构化功能分解与验收示例。

- **目标/发起者**：总管理员或公司权限管理专员申请撤销范围内指定员工—角色关联，不限原分配人；保留其他有效授权来源。
- **前置**：办理管理员已认证且具备目标来源组织的撤权资格。员工已调离/停用或系统停用，不妨碍清理本组织历史关联。
- **输入**：授权关系 ID、关系版本、来源组织、撤销原因、方案及请求编号。
- **流程**：查询可管理关系 → 选择撤销明细 → 预览影响 → 校验并保存固定方案 → OA 审批 → UC-11 验证最终批准结果 → 复核资格及关系版本 → 原子撤销并记录审计。
- **审批与生效**：提交不撤权；OA 驳回不改变授权；批准且执行成功后撤销生效。审批人员与内部流转完全交由外部 OA 负责。
- **权限规则**：只撤销指定关联，不删除角色、不影响其他员工、不停用员工身份。剩余角色提供的重合权限保留；撤销 ALL 来源后如只剩 SELF，则范围缩小为 SELF。
- **异常与并发**：重复通知不重复执行；越范围拒绝；旧审批不得撤销后续重授的新关联；批量整体执行或回滚。不同员工持有同一角色不互相锁定。
- **事务/数据**：方案提交不改有效授权；关系状态及版本、执行状态、成功审计在 UC-11 同一本地事务提交，保留历史。
- **验收 AT04**：角色 A 提供查看/审批，B 提供查看，撤销 A 后保留查看、失去审批；其他组织授权不变；停用员工即使尚有关联也被权限校验拒绝。

## UC-05 查询员工有效权限

详细版本见 [UC-05_查询员工有效权限.md](UC-05_查询员工有效权限.md)（V1.0，2026-10-13），包含调用边界、返回示例、合并规则、结构化功能分解及验收示例。

- **目标/参与者**：可信业务系统后端查询员工在自身系统的可见菜单、允许操作及每项操作的 ALL／SELF 范围；不是查询专员在权限中心后台的菜单。
- **前置/输入**：业务系统自行认证员工，从登录上下文取得统一员工标识；以绑定系统的服务凭据调用，不直接相信浏览器传来的员工身份。
- **流程**：验证调用身份及系统范围 → 检查员工状态 → 读取当前系统有效角色和权限 → 去重并逐操作合并范围 → 按 A08 生成菜单和导航容器 → 返回一致结果。
- **合并**：同一操作 SELF＋ALL＝ALL，不同操作分别计算；同公司、同系统有效角色共同参与，跨公司兼岗分别查询，不混入其他系统权限；没有系统进入资格时不返回可用功能。
- **菜单规则（已确认）**：取得菜单对应查看/进入权限才返回该菜单；仅有编辑等权限不自动获得查看。必要祖先只作导航容器，不授予父页面或兄弟权限，具体映射由 UC-01 落实。
- **异常**：员工未知、停用或无进入资格返回 canAccessSystem=false 和成功空集合；有进入资格但无功能授权返回 true 和空集合；凭据无效、越系统调用、参数错误及服务故障分别返回错误，不能假称成功或默认放行。
- **边界**：只读取已生效配置，不经过 OA、不修改授权。菜单与操作从同一份一致读取结果生成；一期不引入权限缓存。
- **后续访问**：业务系统自行渲染界面；实际操作与本人限制由业务后端结合 UC-06 执行，旧查询结果不是长期通行证。
- **验收 AT05**：一次返回菜单、操作及范围；跨系统隔离；撤销 ALL 来源后返回 SELF；员工停用返回空集合，数据库故障返回错误。

## UC-06 检查员工指定操作权限

详细版本见 [UC-06_检查员工指定操作权限.md](UC-06_检查员工指定操作权限.md)（V1.0，2026-10-13）。沿用 UC-06 编号，图中文字已统一为“检查员工指定操作权限”。

- **目标/参与者**：业务系统后端检查员工在自身系统中是否拥有指定操作权限及其有效范围。
- **前置/输入**：调用方已认证并绑定系统；提供员工统一标识、操作权限编码和请求编号。不接收外部记录 ID 或 ownerId。
- **流程**：验证输入及服务身份 → 确定当前系统、员工和操作 → 查询有效授权来源 → 判定有无权限并合并该操作范围 → 返回结果。
- **输出**：建议返回 hasPermission 与 scope；功能有权限返回 ALL／SELF；直接检查系统进入权限有权限返回 true、null；无权限返回 false、null。SELF 不是对任意业务记录放行。
- **规则**：与 UC-05 共用有效角色及权限并集规则；只检查当前系统，不根据菜单显示、岗位名称或其他操作权限推断目标权限。
- **外部职责**：业务系统认证员工，判断具体记录是否属于本人、过滤列表并执行拦截；权限中心不访问外部业务数据库或作具体记录的归属判断。
- **异常**：未知/停用员工、未知/停用操作或无有效授权返回无权限；无效服务身份、越系统、参数错误及服务故障返回对应错误。故障不默认放行。
- **数据/事务**：只读一致的当前有效授权，记录必要调用信息；不经 OA，不修改业务或授权数据，不持有跨系统事务。
- **验收 AT06**：返回单项权限及范围，SELF＋ALL 合并为 ALL，撤销后新检查反映变化；与 UC-05 在相同数据状态下一致；外部调用方不能忽略 SELF 而任意放行。

## UC-07 配置管理员及管理范围

详细版本见 [UC-07_配置管理员及管理范围.md](UC-07_配置管理员及管理范围.md)（V1.0，2026-10-13），包含已确认规则、一期约定、流程、异常、结构化分解和验收示例。

- **目标/参与者**：权限中心总管理员为总公司及各分公司分别配置共同管理范围并任免专员，不经过 OA，保存和审计成功后直接生效。
- **人员范围**：本公司及所属部门及其下级部门（不跨其他公司边界）；兼岗员工只处理本公司来源授权，已调离员工的本公司历史授权仍可按 UC-04 清理。
- **系统与角色**：总管理员选择公司可管理系统；同公司专员共享范围。角色按组织归属与系统范围动态纳入，不逐个指定、不按创建人隔离；草稿不可分配。
- **名单**：每公司 1～3 名，一期可只安排一名。本稿允许初始化/离任期间暂为零人，按未取消且未因员工状态／任职失效的任命计数，停用账号不自动释放名额；这些计数口径为实现约定。

- **生效边界**：取消资格或缩小范围限制后续管理操作；未执行方案按原资格来源复核对应范围及目标条件，不等待人员接手，原申请人离任不单独使方案失效。既有角色和员工业务授权不自动删除，不将管理资格等同业务权限。
- **已确认**：不配置逐操作及 ALL／SELF 的申请上限；公司范围仅限定人员、角色归属及获准系统，实际角色配置仍经 OA 审批。
- **异常/事务**：非总管理员、越范围候选、超限或陈旧版本拒绝；名单、系统集合、版本及成功审计整体提交或回滚，旧会话不能绕过当前资格。
- **验收 AT07**：任命无需 OA；同公司角色共享；不能管理另一公司或未获准系统；资格取消后管理请求被拒绝但业务授权保留。

详细版本见 [UC-11_接收审批结果并执行权限变更.md](UC-11_接收审批结果并执行权限变更.md)（V1.0，2026-10-13），包含最终结果、三类执行、重复/失败恢复、结构化分解及验收示例。

- **参与者/边界**：外部 OA 服务，一期使用认证的模拟调用；不实现 OA 内部审批，不接管 UC-01/07 等直接管理操作。
- **输入**：服务凭据、本地申请与外部审批编号、最终批准/驳回、固定版本/内容摘要、事件编号。
- **流程**：认证 → 匹配固定申请 → 检查重复/冲突 → 可靠保存最终结果 → 批准后按原资格来源复核范围及目标版本并自动执行 → 按 UC-02/03/04 执行 → 原子提交变更、执行状态和审计。
- **结果规则**：驳回不改授权；批准接收不等于执行成功；冲突最终结果不覆盖原结果。重复已成功通知只返回原记录。
- **复核区别**：角色配置检查基础版本，授予检查员工任职及角色版本，撤销检查关联及来源但不因员工已调离而阻止历史清理。
- **系统进入权限**：随原配置/分配/撤销方案执行，不自动补授；失去进入资格不删除保留的功能关联。
- **失败/事务**：接收结果先独立落地，业务变更与成功审计再整体提交；失败回滚，原批准方案可在条件仍合法时重试，原资格来源对应范围或目标版本变化导致目标不合法则需新申请；仅原申请人离任不阻止自动执行。
- **验收 AT11**：可信匹配结果才执行，重复并发只成功一次，批量整体一致，重授后的关系不受旧撤销回调影响。
