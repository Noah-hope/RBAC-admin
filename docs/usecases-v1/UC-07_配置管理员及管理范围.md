# UC-07 配置管理员及管理范围

版本：V1.2，2026-10-15。状态：功能权限、部门管理范围及员工启停流程已按用户确认修订，可作为界面原型依据。

本轮更新：管理范围按公司、部门子树及系统指定；离岗关闭原部门来源权限立即生效，全局停用仅总管理员；保留功能权限、OA 及历史规则。

### 当前需求基线（2026-10-15，V1.2 部门范围与员工启停）

- 一期实现 RBAC0 权限管理：员工经角色获得权限，无角色继承、直接用户授权或显式拒绝。外部系统只做简单 HTTP 调用演示，不实现其内部业务。
- 角色属于一个公司和一个业务系统，可限定部门；公司级角色要求本公司有效任职，部门级角色要求在该部门直接有效任职，不自动覆盖下属部门。岗位不自动绑定角色；任职条件与权限需要均未改变时，不因岗位名称变化更换角色。
- UC-05/06 按“员工＋当前公司＋业务系统”计算权限。仅合并该公司、该系统内的有效角色；系统进入资格与功能权限也必须来自该公司、该系统。公司上下文隔离的是功能授权来源，不定义业务数据访问范围。
- 授权同时校验角色适用条件与来源部门。离岗关闭原部门来源立即失效，其他独立兼岗来源保留；公司级共享角色不随调岗自动转移。仅总管理员可全局停用/恢复员工；恢复不复权。新授权经 OA，新管理任命由总管理员办理。
- 当前 RBAC 系统只管理功能权限。目录登记系统进入权限与功能操作，角色配置是否授予；不定义、保存或返回业务数据范围，不设计本人记录判断或行过滤规则。
- 员工、公司、部门使用稳定内部 ID；首次导入以源唯一用户名建立员工映射，组织分配稳定编码，更名不改变身份。人员变更模板明确新增任职、结束任职、停用、恢复等动作，不从文件缺行推断离职。
- 一期使用至少两个公司、两个系统的代表性数据，覆盖多角色、兼岗、公司授权隔离、功能操作独立与去重、审批生效、撤销、失效及重新申请。其余资料后续逐步补齐。

以上为本轮已确认规则，详细流程与验收必须遵循；描述的是需求设计，不代表代码已实现或真实外部系统已完成对接。

## 1. 用例概述

| 项目 | 说明 |
| --- | --- |
| 编号与名称 | UC-07 配置管理员及管理范围 |
| 目标 | 总管理员任命权限管理员，指定公司、管理根部门与可管理系统 |
| 发起者 | 权限中心总管理员 |
| 前置条件 | 总管理员会话有效；公司、部门、系统、候选员工及其后台账号合法 |

本用例管理后台资格，不授予业务系统角色，不提供升为总管理员或组织启停的入口。完整共通规则见 [管理范围与人员权限规则](管理范围与人员权限规则.md)。

## 2. 角色与范围规则

1. 范围包含指定公司、根部门及下级部门、获准系统；遇到其他公司边界停止。同公司兄弟部门不自动包含。
2. 范围和人员任命分开保存。一个范围可有多名管理员，同范围协作，不按角色创建人隔离；一个人可有多项明确任命，每次请求选择足以覆盖全部目标的范围依据。
3. 不再使用整家公司唯一系统清单及固定一至三人上限；保留同范围任命去重、版本和并发检查，不另设未确认的人数限制。
4. 候选员工须全局有效、具备该公司及获准部门范围内适用任职，并关联可用后台账号；无账号先按 UC-09 创建，不自动任命。
5. 权限管理员只能配置范围内部门角色。公司级共享角色由总管理员维护；管理员可为范围内符合条件员工申请分配共享角色。
6. 管理范围包含下级部门，不使部门角色自动适用下级员工；角色仍按直接任职校验。
7. 后台资格不等于外部系统进入权限，任命及扩大系统范围不会自动授予 SYSTEM_ACCESS 或功能操作。

## 3. 输入与输出

输入：范围编号（新增时生成）、公司 ID、管理根部门 ID、系统 ID 集合、任命名单、范围/编辑版本、修改原因和请求编号。范围内已有角色不需要逐个选择白名单。

输出：公司与根部门、子树边界、系统集合、管理员名单、当前版本及审计编号。明确空名单可暂时无人办理，空系统集合表示无业务系统管理资格；缺失字段不解释为清空。

## 4. 正常流程

| 步骤 | 总管理员操作 | 权限中心处理 |
| --- | --- | --- |
| 1 | 打开权限管理员配置 | 校验总管理员资格，读取已有范围及任命 |
| 2 | 选择公司和管理根部门 | 展示部门子树；验证部门属于目标公司，不跨公司扩张 |
| 3 | 选择可管理系统和管理员 | 检查系统已登记、账号可用、员工适用任职及任命去重 |
| 4 | 预览并填写原因 | 展示部门/系统增减、任免和待执行方案影响；不改变业务授权 |
| 5 | 确认保存 | 复核身份、范围、任职、版本，原子保存范围/任命/审计 |
| 6 | 查看结果 | 直接生效；后续请求与 UC-11 按各自原范围依据复核 |

## 5. 变更与访问边界

- 取消管理员任命仅取消后台资格，不等于该员工离职、来源关权或删除业务角色；其他有效任命仍可使用。
- 缩小某个范围的部门或系统后，新请求使用最新范围。该范围原始申请在 UC-11 重新校验，不合法则失效；不能换用总管理员查看身份绕过。
- 原管理员离任、同范围暂时无人，不单独使已提交合法申请失效；范围记录和原提交依据保留。目标员工来源关闭则另按来源周期拒绝旧批准。
- 账号停用拒绝所有旧会话，不自动删除任命或业务授权；启用后仍需员工有效及当前有效任命，旧会话不复活。
- 员工全局停用或失去任命所需部门任职使相关任命失效，恢复员工/任职不自动恢复任命；总管理员重新任命。
- 历史管理与授权事件按记录时来源部门和当前范围过滤，员工调岗不把旧记录迁往新部门。

## 7. 异常、并发与事务

| 编号 | 条件 | 处理 |
| --- | --- | --- |
| E01 | 非总管理员配置任命或扩大范围 | 拒绝 |
| E02 | 部门不属于目标公司、系统未知或新增停用系统 | 拒绝；合法移除旧系统不被其停用状态阻止 |
| E03 | 员工无效、缺少适用任职、账号停用/不存在 | 拒绝新增任命 |
| E04 | 同范围重复任命或歧义输入 | 拒绝，不通过覆盖丢失其他任命 |
| E05 | 陈旧版本、不同内容复用请求编号 | 冲突，不静默覆盖 |
| E06 | 保存或成功审计失败 | 范围、任命、版本与审计整体回滚 |
| E07 | 空名单/系统集合 | 明确预览影响后允许，保留历史 |
| E08 | 请求使用不覆盖全部目标的范围，或拼接多项资格 | 拒绝；拆分为范围明确的操作 |

逻辑数据包括范围记录、范围系统集合、管理员任命、账号/员工任职、版本及审计。具体表名、并发手段和接口在后续设计确定。后台请求按当前资格检查；自动执行按提交时范围依据及当前对应范围复核。
