# UC-07 配置管理员及管理范围

版本：V1.0，2026-10-13。状态：本轮需求审视已确认的最终用例基线，供小组设计与验收使用。

本轮更新：统一公司上下文、任职持续资格、失效不自动恢复、操作支持范围及人员资料规则。

### 最终需求基线（2026-10-13）

- 一期实现 RBAC0 权限管理：员工经角色获得权限，无角色继承、直接用户授权或显式拒绝。外部系统只做简单 HTTP 调用演示，不实现其内部业务。
- 角色属于一个公司和一个业务系统，可限定部门；公司级角色要求本公司有效任职，部门级角色要求在该部门直接有效任职，不自动覆盖下属部门。岗位不自动绑定角色；任职条件与权限需要均未改变时，不因岗位名称变化更换角色。
- UC-05/06 按“员工＋当前公司＋业务系统”计算权限。仅合并该公司、该系统内的有效角色；系统进入资格与功能权限也必须来自该公司、该系统。公司数据隔离、SELF 对象判断和过滤由业务系统实施。
- 任职变化后不再满足角色条件的授权立即失效；有其他符合条件的兼岗则保留该授权。员工全局停用使其全部业务授权及公司专员任命失效，不区分临时停用与离职。保留历史，不物理删除；恢复身份或任职不自动恢复失效授权，业务角色重新申请 OA 批准，专员由总管理员按 UC-07 重新任命。
- 操作目录明确支持范围：有明确本人语义的操作可支持 SELF/ALL，其他功能操作一期仅支持 ALL；SYSTEM_ACCESS 不适用范围，scope=null。配置及执行均校验所选范围属于支持集合。
- 员工、公司、部门使用稳定内部 ID；首次导入以源唯一用户名建立员工映射，组织分配稳定编码，更名不改变身份。人员变更模板明确新增任职、结束任职、停用、恢复等动作，不从文件缺行推断离职。
- 一期使用至少两个公司、两个系统的代表性数据，覆盖多角色、兼岗、公司隔离、本人范围、审批生效、撤销、失效及重新申请。其余资料后续逐步补齐。

以上为本轮已确认规则，详细流程与验收必须遵循；描述的是需求设计，不代表代码已实现或真实外部系统已完成对接。

## 1. 用例概述

| 项目 | 说明 |
| --- | --- |
| 编号与名称 | UC-07 配置管理员及管理范围 |
| 目标 | 指定公司权限管理专员，并配置其共同管理的人员、业务系统及角色范围 |
| 发起者 | 权限中心总管理员，不是外部 OA 系统管理员 |
| 被配置对象 | 公司的共同管理范围及专员名单 |
| 触发 | 初始化公司（含总公司和分公司）管理职责、任命或替换专员、调整可管理系统、取消专员资格 |
| 前置条件 | 总管理员已登录且资格有效；目标公司（含总公司和分公司）、候选人员和已登记业务系统可查询 |
| 成功结果 | 配置与审计保存成功后直接生效，不生成 OA 申请 |
| 失败保证 | 不部分修改名单或范围，原有效配置保留 |

本用例管理权限中心后台资格，不给员工分配 OA、HR 等业务系统角色。总管理员账号的初始化及任免不在本用例处理；本页面不能把专员升级为总管理员。

### 统一管理与公司边界（本轮已确认）

“公司权限管理专员”即公司授权管理员（早期图中称部门授权管理员）；总公司和各分公司各自指定 1～3 名，可仅一名。公司人员范围按明确公司归属及所属部门层级计算，遇到另一个公司节点停止，不因总公司位于组织树上层而包含全部分公司。

权限中心总管理员可管理所有公司、所有系统及所有公司专员，也可办理 UC-02～04；公司专员仅在本公司获准系统内办理。双方的业务角色配置、分配、撤销均经过 OA。总管理员跨公司办理时仍明确目标公司；每份申请按一个公司归属保存，系统状态、目标合法性及版本校验照常执行。

一期不配置逐操作及 ALL／SELF 的申请上限，也不逐个指定可分配角色。获准系统目录内的合法权限可以申请，角色授权内容仍由 OA 审批。后台资格不自动产生外部业务系统进入权限。


## 2. 已确认规则与一期约定

已确认：

- 人员范围为本公司及所属部门及其下级部门（不跨其他公司边界）；兼岗员工只处理本公司来源的角色授权。
- 总管理员配置可管理的业务系统，范围存于公司层面，由该公司专员共同使用。
- 同公司专员共享角色管理资格，不按角色创建人隔离，不逐个指定可分配角色。
- 属于本公司及所属部门及其下级部门（不跨其他公司边界）、位于获准系统内的角色可管理；只有已生效且符合分配条件的角色才可申请分配。
- 每公司指定 1～3 名专员；一期仅安排一名也适用。
- 任命、取消专员资格和管理范围配置由总管理员直接执行，记录审计，不经过 OA。UC-02～04 的业务角色配置、分配及撤销仍经 OA 批准后执行。

一期设计约定（不是新增的用户确认项）：

1. 已确认不逐项配置“可申请的操作权限及 ALL／SELF 上限”。专员在公司获准系统的有效目录内提出配置申请，由 OA 审批；若后续要求更细上限，再扩展范围模型。
2. 专员具备范围内角色配置申请、员工角色分配和撤销申请能力；相关方案可见性与审计查询遵守同一范围。暂不拆成每人不同的后台功能组合。
3. 候选人应具有本公司有效任职及可关联的后台账号身份；任职信息来自员工数据，缺少账号时先按 UC-09 子流程 D 由总管理员创建，创建不自动任命；账号登录实现交给 UC-09，不在本用例生成或展示明文密码。
4. 为支持初始化或全部离任，允许公司暂时无专员；保存后最多三名未取消且未因员工状态／任职失效的专员任命。同一人在同公司重复选择只算一名，不允许重复任命。
5. 仅停用后台账号与员工全局停用不同：前者不改变业务授权，也不自动释放任命名额；后者按 UC-10 使任命失效，恢复后须重新任命。仅停用账号时，总管理员明确取消旧任命后再补任，避免账号恢复时突破上限。候选人跨公司兼岗时，每个公司任命分别配置、分别计数，不自动取得另一公司的管理资格。

### 系统进入权限（已确认）

公司“允许管理哪些系统”与员工“允许进入哪些系统”独立。任命专员、扩大公司系统范围均不自动授予专员或员工 SYSTEM_ACCESS。专员可在获准系统中申请给本公司角色配置进入权限，再按 UC-03 分配；仍走 OA。

专员无需先获得某外部系统的业务进入权限，才能在权限中心管理该系统目录范围内的角色；其后台操作资格由当前任命和公司管理范围决定。权限中心后台登录不以 oa:access、hr:access 等外部系统进入权限作为前置。

## 3. 管理范围如何确定

| 范围 | 计算规则 |
| --- | --- |
| 人员 | 根据公司组织节点及其下属部门识别有效任职；不按公司/部门名称字符串匹配 |
| 系统 | 总管理员为公司配置的系统集合，新增登记系统不自动加入 |
| 角色 | 角色归属在本公司组织范围内，且所属系统在获准系统集合内 |
| 分配资格 | 在上述角色范围内进一步检查角色已生效、可分配及目标员工任职等 UC-03 条件 |
| 历史撤权 | 员工已调离时仍可处理本公司来源的历史关联，遵循 UC-04，不要求员工仍在原部门任职 |

“共享”发生在公司内部。桥梁公司和水利公司即使都能管理 OA，也不能互相管理对方角色。能管理 HR 系统表示能提交该系统角色配置及授权申请，不表示专员获得 HR 业务数据访问权限。

纯组织管理范围不自动产生“仅本公司业务数据”的过滤条件。业务权限的数据范围仍由角色权限中的 ALL／SELF 表达，并由业务系统执行。

## 4. 输入与输出

| 输入 | 说明 |
| --- | --- |
| 公司 ID | 当前被配置的组织主体；不允许专员通过请求伪造总管理员身份 |
| 系统 ID 集合 | 该公司允许管理的已登记系统 |
| 专员身份 ID 集合 | 最终拟保留的任命名单，预览中明确新增、保留和取消人员 |
| 配置版本 | 防止两个页面相互覆盖 |
| 修改原因、请求编号 | 审计及重复提交识别 |

输出：保存后的公司配置、专员名单、系统范围、版本和审计关联编号。角色范围动态计算，不输出或保存一份需要手工逐项维护的角色白名单。

空名单或空系统集合是明确清空操作，预览提示影响；缺失字段不解释为清空。操作者身份取自登录上下文，不由表单指定。

## 5. 正常流程

| 步骤 | 总管理员操作 | 系统处理 |
| --- | --- | --- |
| 1 | 打开管理员配置页面 | 校验总管理员会话及资格 |
| 2 | 选择公司（含总公司和分公司） | 读取公司及下属部门、当前专员名单、系统范围和配置版本 |
| 3 | 选择允许管理的系统 | 展示已登记系统，不逐个选择角色 |
| 4 | 新增、移除或替换专员 | 展示符合任职和身份条件的候选人，预检查重复与人数上限 |
| 5 | 预览并填写原因 | 展示人员任免、系统增减及可能受影响的待处理申请，提示不改变既有业务授权 |
| 6 | 确认保存 | 后端重新校验总管理员资格、组织、候选身份、系统、人数及版本，防并发覆盖 |
| 7 | 查看保存结果 | 同一事务保存公司系统范围、任命名单、新版本与成功审计，直接生效 |
| 8 | 专员后续访问管理功能 | 后端按最新资格和公司范围校验；不能仅依赖旧页面或旧登录时的权限快照 |

一期可从每公司一名专员开始，数据模型仍保留公司范围与人员任命的分离，未来增加同公司专员无需复制角色或重新逐个授权。

## 6. 变更生效与既有数据

- 增加系统范围：专员可管理该公司在此系统内的角色；不会自动创建角色，也不会自动给员工分配业务权限。
- 新增公司角色：只要符合组织和系统范围，自动出现在专员可管理列表；草稿角色仍不可分配，首次配置依然须经 OA 批准执行。
- 取消专员资格：后续管理请求被拒绝，不停用其员工身份、不撤销其业务角色；其创建的公司角色及历史记录保留。
- 缩小系统范围：公司专员不再管理被移除系统的角色与授权；旧业务授权不自动撤销。专员原始申请执行前重新检查公司范围，不符合则失效；总管理员原始申请按全局资格依据检查，不受专员系统清单限制，不借 OA 批准绕过管理边界。
- 需要清理被移出公司专员范围的历史授权时，总管理员可凭全局资格直接发起 UC-04，仍经 OA；不赋予失去范围的专员例外权限。
- 原申请人离任：已生效配置保留；其未执行申请保留原提交人、资格来源及固定内容；批准后按原资格来源复核对应范围及目标条件并自动执行，不因离任或暂时无专员而等待接手。
- 组织发生调整时，后续请求按最新组织归属判定；不自动迁移角色。任职条件不满足时旧授权及对应专员资格失效，历史保留，重新任职不自动恢复。已有角色、授权或其他历史引用的部门及其子树不得直接跨公司迁移，按 UC-10 建新组织并明确调整任职。

范围变更成功后开始的新请求必须使用最新范围；与正在执行的授权事务发生并发时，通过配置版本复核或事务锁确定先后顺序，不能只做前端隐藏。

## 7. 页面示例

```text
公司：桥梁公司
人员范围：本公司及所属部门及其下级部门（不跨其他公司边界）（根据组织结构展示）
可管理系统：[✓] OA  [✓] HR  [ ] 财务
专员名单：专员甲

角色范围：自动按本公司组织归属＋所选系统计算
能力：角色配置申请、员工角色分配/撤销申请及范围内记录查询

按钮：预览变更、保存配置、取消
```

此时专员甲可管理桥梁公司的 OA、HR 角色；不能管理桥梁公司财务角色，也不能管理水利公司的 OA 角色。增加专员乙后两人共享范围；无须把甲创建的每个角色再逐项交给乙。

## 8. 替代与异常流程

| 编号 | 条件 | 处理 |
| --- | --- | --- |
| E01 | 非总管理员或会话失效 | 拒绝保存；专员不得自行任命人员或扩大范围 |
| E02 | 公司不存在/停用，新增系统不存在/停用 | 拒绝新增配置；允许在合法清理流程中移除已停用系统或旧任命，不因旧对象停用阻止清理 |
| E03 | 新候选人无有效身份或本公司任职 | 拒绝任命，不能用相同姓名匹配替代身份 |
| E04 | 保存后超过三名，或重复人员项 | 拒绝超限或重复输入；并发新增也必须受人数限制 |
| E05 | 替换专员 | 同一次保存明确移除旧人、加入新人，按最终名单校验；不要求先增加到四人 |
| E06 | 配置版本陈旧 | 返回冲突，重新读取预览，不静默覆盖另一管理员修改 |
| E07 | 空名单或空系统集合 | 必须明确提交并显示影响；允许暂时无人管理或无系统可管理，记录原因 |
| E08 | 相同请求重试 | 相同内容返回已保存结果；同编号不同内容拒绝 |
| E09 | 保存或成功审计失败 | 整体回滚，原名单和范围保留 |
| E10 | 专员账号停用后使用旧会话 | 资格检查拒绝；不因旧会话尚未过期而继续允许管理 |

## 9. 数据与结构化处理

逻辑数据：公司组织、员工任职、后台身份、系统目录、公司管理系统关联、专员任命、配置版本、审计记录。后台管理资格与 EmployeeRole 业务角色关联分开保存。

保存名单、系统集合、配置版本和成功审计采用同一本地事务。以公司维度约束并发修改、唯一任命和人数上限；只读预览不改数据。后台鉴权与 UC-11 执行前复核共同使用这套范围计算逻辑。

```text
配置管理员及管理范围
├── 校验总管理员资格
├── 读取公司组织、系统范围及专员名单
├── 整理任免与系统范围差异
├── 校验候选任职、人数上限及配置版本
├── 预览变更影响
└── 原子保存配置、版本和审计

人工管理请求：检查当前总管理员/专员资格 → 对应管理范围 → 目标条件
批准方案自动执行：核对固定提交资格来源 → 对应范围 → 目标条件及版本
```

这是功能分解，不要求为每一步新增独立服务。没有 OA 申请、审批节点或回调步骤。

## 10. 验收示例

| 编号 | 场景 | 预期 |
| --- | --- | --- |
| UC07-T01 | 总管理员任命一名专员并配置 OA、HR | 保存成功即生效，不生成 OA 申请 |
| UC07-T02 | 同公司增加第二名专员 | 共享范围及角色，不按创建人隔离 |
| UC07-T03 | 公司在获准系统中新角色批准生效 | 自动纳入可分配范围，无须逐个指定 |
| UC07-T04 | 新角色仍为草稿 | 可在范围内配置，但不可分配 |
| UC07-T05 | 专员管理其他公司角色或未获准系统 | 后端拒绝 |
| UC07-T06 | 员工跨公司兼岗 | 只管理本公司来源授权，其他公司关系不受影响 |
| UC07-T07 | 原公司专员清理已调离员工历史关系 | 范围内可按 UC-04 申请撤销 |
| UC07-T08 | 保存第四名专员，或并发新增突破上限 | 拒绝，最终不超过三名未取消且未失效的任命 |
| UC07-T09 | 三人名单中替换一人 | 同事务保存最终三人名单，不临时超限 |
| UC07-T10 | 取消专员资格后继续使用旧会话 | 后续管理请求拒绝；员工业务角色及公司角色保留 |
| UC07-T11 | 移除系统范围后 OA 批准专员原始申请 | 执行前范围检查不通过，不执行；已有有效授权不被自动撤销 |
| UC07-T12 | 增加管理范围 | 不自动给专员或员工分配业务权限 |
