# UC-09 管理员登录与退出

版本：V1.0，2026-10-13。状态：本轮需求审视已确认的最终用例基线，供小组设计与验收使用。

### 最终需求基线（2026-10-13）

- 一期实现 RBAC0 权限管理：员工经角色获得权限，无角色继承、直接用户授权或显式拒绝。外部系统只做简单 HTTP 调用演示，不实现其内部业务。
- 角色属于一个公司和一个业务系统，可限定部门；公司级角色要求本公司有效任职，部门级角色要求在该部门直接有效任职，不自动覆盖下属部门。岗位不自动绑定角色；任职条件与权限需要均未改变时，不因岗位名称变化更换角色。
- UC-05/06 按“员工＋当前公司＋业务系统”计算权限。仅合并该公司、该系统内的有效角色；系统进入资格与功能权限也必须来自该公司、该系统。公司数据隔离、SELF 对象判断和过滤由业务系统实施。
- 任职变化后不再满足角色条件的授权立即失效；有其他符合条件的兼岗则保留该授权。员工全局停用使其全部业务授权及公司专员任命失效，不区分临时停用与离职。保留历史，不物理删除；恢复身份或任职不自动恢复失效授权，业务角色重新申请 OA 批准，专员由总管理员按 UC-07 重新任命。
- 操作目录明确支持范围：有明确本人语义的操作可支持 SELF/ALL，其他功能操作一期仅支持 ALL；SYSTEM_ACCESS 不适用范围，scope=null。配置及执行均校验所选范围属于支持集合。
- 员工、公司、部门使用稳定内部 ID；首次导入以源唯一用户名建立员工映射，组织分配稳定编码，更名不改变身份。人员变更模板明确新增任职、结束任职、停用、恢复等动作，不从文件缺行推断离职。
- 一期使用至少两个公司、两个系统的代表性数据，覆盖多角色、兼岗、公司隔离、本人范围、审批生效、撤销、失效及重新申请。其余资料后续逐步补齐。

以上为本轮已确认规则，详细流程与验收必须遵循；描述的是需求设计，不代表代码已实现或真实外部系统已完成对接。

## 1. 用例概述

| 项目 | 说明 |
| --- | --- |
| 编号与名称 | UC-09 管理员登录与退出 |
| 目标 | 验证权限中心后台使用者身份，建立或结束会话，并保证后续访问符合当前管理资格 |
| 参与者 | 权限中心总管理员、已任命的公司权限管理专员 |
| 触发 | 打开管理后台登录页，或在已登录页面选择退出 |
| 登录前置 | 后台账号已建立、状态可用，拥有至少一项有效后台管理资格；关联员工身份有效（若有） |
| 登录成功结果 | 返回当前身份、管理能力及范围；需修改临时密码者仅进入受限修改流程 |
| 退出成功结果 | 当前会话失效，后续管理请求需重新登录 |
| 失败保证 | 不建立可访问管理业务的有效会话，不修改业务角色或员工授权 |

本用例不经过 OA，不实现外部业务系统登录、单点登录或自由注册。OA、HR 的 SYSTEM_ACCESS 是外部业务授权，既不能替代后台管理资格，也不是后台登录的前提。

### 统一管理与公司边界（本轮已确认）

“公司权限管理专员”即公司授权管理员（早期图中称部门授权管理员）；总公司和各分公司各自指定 1～3 名，可仅一名。公司人员范围按明确公司归属及所属部门层级计算，遇到另一个公司节点停止，不因总公司位于组织树上层而包含全部分公司。

权限中心总管理员可管理所有公司、所有系统及所有公司专员，也可办理 UC-02～04；公司专员仅在本公司获准系统内办理。双方的业务角色配置、分配、撤销均经过 OA。总管理员跨公司办理时仍明确目标公司；每份申请按一个公司归属保存，系统状态、目标合法性及版本校验照常执行。

一期不配置逐操作及 ALL／SELF 的申请上限，也不逐个指定可分配角色。获准系统目录内的合法权限可以申请，角色授权内容仍由 OA 审批。后台资格不自动产生外部业务系统进入权限。


## 2. 账号、员工与管理资格

| 概念 | 含义 |
| --- | --- |
| 员工资料 | 统一员工标识、组织任职和状态，由 UC-10 提供 |
| 后台账号 | 本平台登录名、密码摘要、启停状态等身份数据 |
| 管理资格 | 总管理员资格，或 UC-07 中有效的公司专员任命及共同范围 |
| 会话 | 一次登录的服务端可验证状态，不是永久管理授权 |

导入员工不自动创建后台账号；创建账号也不自动任命专员。专员身份与员工稳定 ID 关联，不凭姓名或职位判断。一个后台账号可承载多项明确任命，每次操作仍限于相应公司范围。

本稿采用以下一期约定：

- 总管理员账号在初始化时建立，不提供自助注册或升级为总管理员的入口；初始化凭据不写入公开文档或版本库。
- 任命专员时关联其已有后台账号；没有账号则先创建并关联员工，再由 UC-07 保存任命。只有账号没有管理资格时不能进入管理后台。
- 新建专员账号或重置密码时，总管理员设置临时密码并安全交付；不展示原密码，不使用全员相同的默认密码。
- 临时密码首次验证成功后必须修改，完成前只能访问修改密码与退出功能，不能调用管理接口。
- 忘记密码由总管理员重置；不做短信/邮箱找回。唯一总管理员无法登录时由部署维护者按受控恢复步骤处理，不提供未认证重置接口；具体步骤留到部署设计。

## 3. 输入与输出

| 场景 | 输入 | 输出 |
| --- | --- | --- |
| 登录 | 本平台登录名、密码 | 成功会话及当前身份摘要，或需修改密码的受限状态，或统一失败结果 |
| 修改临时/本人密码 | 当前受信会话、原密码、新密码与确认值 | 修改成功并要求重新登录，或校验失败 |
| 退出 | 当前会话及必要请求校验信息 | 当前会话已结束 |
| 重置专员密码（配套流程） | 总管理员会话、目标账号、新临时密码、原因 | 重置成功；目标旧会话失效，下次登录强制修改 |

响应只包含所需身份和管理范围，不返回密码摘要、原始服务端会话秘密或其他账号资料。会话凭据的交付方式在 API 设计中统一，并与所选认证机制一致。

登录后的范围信息用于页面展示，不能作为后续请求的唯一授权依据。后端每次管理请求都检查当前账号、资格和范围；不相信浏览器提交的管理员类型、公司或功能列表。

## 4. 登录正常流程

| 步骤 | 管理员操作 | 系统处理 |
| --- | --- | --- |
| 1 | 打开登录页并填写账号密码 | 校验参数，通过受保护的通信通道接收凭据 |
| 2 | 提交登录 | 查询账号，以密码哈希验证密码，检查账号及关联员工状态 |
| 3 | 等待结果 | 检查总管理员资格或至少一项有效专员任命，不以业务角色代替 |
| 4 | 查看登录结果 | 普通账号建立正常会话；临时密码账号仅建立受限会话并提示修改 |
| 5 | 进入后台 | 返回当前身份、公司范围及能力；多公司任命分别展示，操作时明确目标公司 |
| 6 | 访问管理页面/接口 | 后端按最新资格和目标范围授权，记录必要登录结果 |

成功登录不会获得任何外部系统进入或功能权限。后台具备管理资格但当前公司没有可管理系统时，可进入必要后台页面并显示无可操作系统，不因此扩大范围。

## 5. 密码修改、退出与重置

### A. 首次或重置后修改密码

验证受限会话、当前密码及账号资格 → 检查新密码与确认值及基本密码策略 → 保存新的密码哈希并清除强制修改标记 → 使该账号全部旧会话失效 → 返回登录页重新登录。

普通本人改密采用同样的旧会话失效规则。具体长度、错误次数限制及会话期限在技术设计确定，不在一期增加可视化密码策略管理模块。

### B. 退出

管理员点击退出 → 后端撤销当前会话 → 客户端清理会话信息并返回登录页。不能仅删除浏览器中的标记而让原会话继续有效。重复退出或会话已过期可返回已退出，不触发业务变更。

一期允许同账号有多个会话，普通退出仅结束当前会话；账号停用、密码修改或重置需使该账号所有旧会话不可继续使用。具体会话实现不在用例中限定。

### C. 总管理员重置专员密码

总管理员选择目标专员账号 → 填写新临时密码及原因 → 后端检查总管理员资格及目标身份 → 原子更新密码哈希、强制修改标记和凭据版本并记录操作 → 旧会话失效，下次登录先修改密码。

重置仅改变后台凭据，不任命人员、不恢复已停用账号、不恢复已取消资格、不修改员工业务角色；不显示可供查询的历史密码。该配套流程不开放给专员重置其他人的密码。

### D. 总管理员创建专员后台账号

本子流程由已登录且资格有效的总管理员发起，不经过 OA。目标员工须存在且全局有效；是否具备目标公司的有效任职，由 UC-07 任命时另行检查。账号创建不授予总管理员资格、公司专员资格或外部系统权限。

输入：员工稳定 ID、平台登录名、临时密码及确认值、创建原因、请求编号。操作者取自受信会话。登录名全局唯一；一期每名员工至多关联一个后台账号，兼任多公司专员时复用同一账号。已有账号应关联使用，不重复创建，也不通过创建接口改绑其他员工。

| 步骤 | 总管理员操作 | 系统处理 |
| --- | --- | --- |
| D1 | 从待任命员工中选择人员 | 校验总管理员资格、员工有效状态，查询是否已有账号 |
| D2 | 无账号时填写登录名、临时密码及原因 | 校验必填、密码一致性及基本策略、登录名唯一和员工关联唯一 |
| D3 | 确认创建 | 后端再次检查资格和约束，原子保存账号、员工关联、密码哈希、强制改密标记及创建审计 |
| D4 | 查看结果并安全交付临时密码 | 返回账号 ID、登录名及未任命提示，不返回密码或哈希，不自动建立目标账号会话 |
| D5 | 继续任命专员 | 通过 UC-07 单独保存任命；任命成功后才能登录，首次登录仍须先修改临时密码 |

账号创建成功、任命失败时，账号保留但没有新增管理资格，不能凭账号存在进入后台；修正任命条件后可复用。并发创建由唯一约束保证不重复；同请求编号同内容重试返回原结果，不同内容拒绝，幂等与审计不持久化明文密码。账号、关联或成功审计写入失败则整体回滚；无总管理员资格、员工无效或唯一性冲突返回明确的安全错误，不覆盖已有账号。创建审计仅供总管理员查看，记录操作者、目标员工/账号、时间和结果，不含密码。

## 6. 状态变化与访问边界

| 变化 | 后续访问行为 |
| --- | --- |
| 账号停用或关联员工停用 | 拒绝后台访问，旧会话不能绕过 |
| 唯一专员任命被取消，且无其他管理资格 | 不能继续进入管理业务；保留账号与审计记录 |
| 一项任命取消，但还有其他有效管理资格 | 仅保留当前仍有效资格对应的范围，不扩大到已取消公司 |
| 公司管理系统范围缩小 | 后续请求使用最新范围，旧页面可能显示旧内容但接口必须拒绝越范围操作 |
| 专员离任后重新任命 | 有效账号可重新登录；已撤销/过期会话不自动复活 |
| OA/HR 系统进入资格撤销 | 不直接取消权限中心后台资格；反之亦然 |

会话只证明已经完成身份验证，具体管理能力始终以当前数据为准。已启动事务与资格变更并发时的复核机制与 UC-07、UC-11 统一。

## 7. 替代与异常流程

| 编号 | 条件 | 处理 |
| --- | --- | --- |
| E01 | 登录字段缺失或格式错误 | 参数校验失败，不尝试默认账号 |
| E02 | 账号不存在、密码错误、停用或无管理资格 | 对外使用统一登录失败提示；服务端记录必要原因但不记录密码 |
| E03 | 临时密码会话直接调用角色/授权接口 | 拒绝，必须先完成改密并重新登录 |
| E04 | 原密码错误、新密码不符合规则或两次不一致 | 不修改密码，提示适当错误 |
| E05 | 退出后、过期会话或已失效凭据继续请求 | 返回未认证/会话失效，不接受旧页面状态 |
| E06 | 频繁失败尝试 | 基础限速或短暂限制，参数在技术设计中确定，不向外泄露账号存在性 |
| E07 | 数据库/会话存储不可用 | 返回服务错误，不退化成允许登录，也不假称密码错误 |
| E08 | 非总管理员重置他人密码 | 后端拒绝 |
| E09 | 改密、重置或会话建立写入失败 | 不返回成功；相关本地写入回滚，不产生半完成的可用身份状态 |

密码使用专用密码哈希方式保存，不明文、不可逆“查回”，不使用普通快速摘要代替密码存储算法。具体算法和会话防护方式留到实现设计，避免把技术选型当成新的业务功能。

## 8. 数据与事务边界

读取后台账号、关联员工状态、管理资格与公司范围；写入会话及必要登录记录。改密/重置涉及密码摘要、强制修改标记、凭据版本和敏感管理操作审计，应原子保存。

一期优先采用可在服务端立即撤销或验证失效版本的会话。若会话另存其他介质，密码凭据版本必须参与后续请求验证，不能只依赖异步清理旧会话。不能将长期不变的管理范围固化为唯一鉴权依据。

登录日志与授权变更审计分开，UC-08 一期不要求展示全部登录明细；重置密码的审计只能记录操作者、目标、时间和结果，不能记录新旧密码或会话凭据。实际错误堆栈仅在服务端排错。

## 9. 结构化功能分解

```text
管理员身份与会话
├── 总管理员创建专员账号并关联员工
├── 登录处理
│   ├── 校验参数、密码及账号状态
│   ├── 检查当前后台管理资格
│   └── 建立正常或受限会话
├── 本人改密处理
├── 总管理员重置专员密码
├── 退出并撤销当前会话
└── 后续请求校验会话、账号状态与当前管理范围
```

UC-07 负责任命和管理范围，本用例负责登录凭据及会话，复用身份和范围校验逻辑，不重复建立一套角色授权模型。

## 10. 验收示例

| 编号 | 场景 | 预期 |
| --- | --- | --- |
| UC09-T01 | 有效总管理员使用正确密码登录 | 建立正常会话并返回后台身份 |
| UC09-T02 | 有效专员登录 | 返回当前公司范围，无额外外部业务授权 |
| UC09-T03 | 仅导入员工或仅有业务角色 | 没有后台账号/资格时不能登录后台 |
| UC09-T04 | 无账号、密码错误、停用或无资格 | 对外统一失败，不泄露敏感原因 |
| UC09-T05 | 临时密码首次登录 | 仅可改密/退出，不能调用管理接口 |
| UC09-T06 | 完成首次改密 | 清除标记、旧会话失效，重新登录后使用后台 |
| UC09-T07 | 退出后重放当前会话 | 被拒绝；重复退出不产生副作用 |
| UC09-T08 | 账号停用或关联员工停用 | 后续请求拒绝，包括其他设备旧会话 |
| UC09-T09 | 取消最后一项管理资格 | 后续管理请求拒绝，账号和业务角色保留 |
| UC09-T10 | 取消一个公司资格，仍有另一公司任命 | 只能操作剩余范围 |
| UC09-T11 | 登录后公司系统范围缩小 | 后端按最新范围检查，不相信旧页面 |
| UC09-T12 | 总管理员重置专员密码 | 原密码和旧会话失效，临时密码登录后必须修改 |
| UC09-T13 | 专员重置他人密码或重置以恢复任命 | 前者拒绝；密码重置不产生新任命 |
| UC09-T14 | 修改密码失败或存储不可用 | 不返回成功、不允许绕过登录 |
| UC09-T15 | 撤销员工的 hr:access | 不直接撤销其有效后台管理资格 |
| UC09-T16 | 检查接口响应与日志 | 不含明文密码、密码摘要或无关凭据 |

## 11. 后续衔接

- UC-07 关联或建立后台身份后任命专员；账号存在不代表任命已成功，部分流程失败不得产生管理资格。
- UC-10 导入员工不批量生成后台账号，员工全局停用后本用例拒绝关联账号的后台访问。
- API/数据库设计确定账号唯一约束、会话期限、基础限速、密码算法及部署恢复步骤；本用例不扩展为单点登录、短信找回或自定义认证平台。

## 配套边界补充验收

| 编号 | 场景 | 预期 |
| --- | --- | --- |
| UC09-B01 | 总管理员为有效员工创建唯一后台账号 | 保存哈希和强制改密标记并审计，不自动任命或授予业务权限 |
| UC09-B02 | 非总管理员创建账号或员工全局无效 | 拒绝，不产生账号 |
| UC09-B03 | 登录名或员工关联重复，含并发请求 | 拒绝重复，不覆盖已有账号；多公司任命复用原账号 |
| UC09-B04 | 账号已创建但 UC-07 任命失败 | 无新增管理资格，未获任何管理资格时不能登录；后续可复用账号 |
| UC09-B05 | 创建成功审计写入失败或同请求重试 | 前者整体回滚；后者同内容返回原结果，不重复创建 |

### 员工恢复后的后台资格

员工全局停用使原公司专员任命失效，即使账号记录保留，恢复员工后也不能凭原任命重新进入后台；总管理员按 UC-07 重新任命后才可登录。不得通过密码重置或重新登录恢复旧任命。
