# UC-10 导入／同步员工组织信息

版本：V1.0，2026-10-13。状态：本轮需求审视已确认的最终用例基线，供小组设计与验收使用。

### 最终需求基线（2026-10-13）

- 一期实现 RBAC0 权限管理：员工经角色获得权限，无角色继承、直接用户授权或显式拒绝。外部系统只做简单 HTTP 调用演示，不实现其内部业务。
- 角色属于一个公司和一个业务系统，可限定部门；公司级角色要求本公司有效任职，部门级角色要求在该部门直接有效任职，不自动覆盖下属部门。岗位不自动绑定角色；任职条件与权限需要均未改变时，不因岗位名称变化更换角色。
- UC-05/06 按“员工＋当前公司＋业务系统”计算权限。仅合并该公司、该系统内的有效角色；系统进入资格与功能权限也必须来自该公司、该系统。公司数据隔离、SELF 对象判断和过滤由业务系统实施。
- 任职变化后不再满足角色条件的授权立即失效；有其他符合条件的兼岗则保留该授权。员工全局停用使其全部业务授权及公司专员任命失效，不区分临时停用与离职。保留历史，不物理删除；恢复身份或任职不自动恢复失效授权，业务角色重新申请 OA 批准，专员由总管理员按 UC-07 重新任命。
- 操作目录明确支持范围：有明确本人语义的操作可支持 SELF/ALL，其他功能操作一期仅支持 ALL；SYSTEM_ACCESS 不适用范围，scope=null。配置及执行均校验所选范围属于支持集合。
- 员工、公司、部门使用稳定内部 ID；首次导入以源唯一用户名建立员工映射，组织分配稳定编码，更名不改变身份。人员变更模板明确新增任职、结束任职、停用、恢复等动作，不从文件缺行推断离职。
- 一期使用至少两个公司、两个系统的代表性数据，覆盖多角色、兼岗、公司隔离、本人范围、审批生效、撤销、失效及重新申请。其余资料后续逐步补齐。

以上为本轮已确认规则，详细流程与验收必须遵循；描述的是需求设计，不代表代码已实现或真实外部系统已完成对接。

## 1. 用例概述

| 项目 | 说明 |
| --- | --- |
| 编号与名称 | UC-10 导入／同步员工组织信息 |
| 目标 | 建立和更新公司、部门、岗位、员工及任职关系，供人员管理、授权范围和身份状态检查使用 |
| 主要参与者 | 权限中心总管理员，发起预检并确认导入 |
| 外部数据来源 | HR 资料；一期使用老师提供的文件，不要求实现真实 HR 接口或定时同步服务 |
| 触发 | 初始化人员组织数据，或收到明确的人事更新资料 |
| 前置条件 | 总管理员登录有效；数据来源和处理范围明确；文件符合约定模板或有明确映射 |
| 成功结果 | 通过预检的数据原子提交，返回批次、变更数量及问题报告 |
| 失败保证 | 预检不修改正式数据；本次执行失败回滚，不产生半完成任职关系 |

本用例不经过 OA，不自动配置业务角色，不自动赋予系统进入权限，不自动创建后台登录账号或任命专员。外部系统自行认证员工，本用例只提供统一身份映射与组织资料。

### 统一管理与公司边界（本轮已确认）

“公司权限管理专员”即公司授权管理员（早期图中称部门授权管理员）；总公司和各分公司各自指定 1～3 名，可仅一名。公司人员范围按明确公司归属及所属部门层级计算，遇到另一个公司节点停止，不因总公司位于组织树上层而包含全部分公司。

权限中心总管理员可管理所有公司、所有系统及所有公司专员，也可办理 UC-02～04；公司专员仅在本公司获准系统内办理。双方的业务角色配置、分配、撤销均经过 OA。总管理员跨公司办理时仍明确目标公司；每份申请按一个公司归属保存，系统状态、目标合法性及版本校验照常执行。

一期不配置逐操作及 ALL／SELF 的申请上限，也不逐个指定可分配角色。获准系统目录内的合法权限可以申请，角色授权内容仍由 OA 审批。后台资格不自动产生外部业务系统进入权限。

## 3. 身份与数据模型规则

| 对象 | 识别和更新规则 |
| --- | --- |
| 组织 | 内部生成稳定 ID；无来源编码时首次按完整组织路径建立显式映射并分配公司／部门稳定编码，后续通过编码或已确认映射更新，更名不重建身份 |
| 岗位 | 在具体组织下识别，重名岗位不跨组织合并；岗位不等于角色 |
| 员工 | 使用老师已有唯一用户名作为一期来源统一标识，并映射到稳定内部员工 ID；不重新生成拼音账号 |
| 任职 | 单独记录员工与公司、部门、岗位的关系及状态，允许一人多项任职 |
| 后台账号 | 与员工身份分离；只有 UC-07/09 明确办理时才创建或关联 |

更名不重新创建员工或组织，须凭稳定标识/已有映射更新。员工来源用户名如果变更，要有明确的旧新标识对应依据，不能通过姓名自动认领原员工及其授权。

同一员工多条不同任职允许导入；员工级姓名、状态等字段冲突属于数据错误。相同任职重复出现只算一条且报告重复；相互矛盾的重复行阻止该批次提交。

一期没有真实任职起止时间或状态字段时，初始化数据的“当前有效”作为明确导入选项显示，不伪造历史入职日期，也不从缺失字段推断员工离职。

## 4. 导入与更新约定

- 一期采用新增及明确更新模式，不用文件缺行推断删除、离职、取消兼岗或停用组织。
- 更新不存在的员工/任职时应区分“新增”和“更新”意图，预览中明确提示，不能静默新建另一个人。
- 一期提供简单人员变更模板：员工内部 ID／来源标识、变更动作、组织编码、岗位及目标任职标识等必要字段；明确新增任职、结束任职、停用、恢复等意图；老师原始表不具有这些字段时，不声称已支持自动识别变化。
- 同一来源批次重复执行返回原结果。相同内容作为新批次提交仍按稳定 ID 比对，重复行不产生新员工或任职。
- 预检通过后冻结文件内容、映射和变更摘要；执行时复核相关数据版本，变化冲突则重新预检，不能用旧预览覆盖新数据。
- 一期每次提交的批次整体成功或回滚。预检中存在阻断错误时先修正再提交；不悄悄跳过错误行形成部分导入。

这些是文件导入的设计约定，不引入消息队列、持续同步或复杂数据治理平台。文件类型、大小和批次数量上限在 API/实现设计中确定。

### 部门跨公司迁移边界（一期）

跨公司迁移指修改组织父级或公司归属，使部门及其子树从公司 A 变为公司 B；改父级同样需要检查，不能只校验显式的公司字段。总公司与各分公司按同一规则处理。

一期禁止直接跨公司迁移已被角色或授权记录引用的部门及其子树。检查包括草稿/已生效角色、未结束申请、有效或已撤销的授权关联及相关历史来源；不能仅因角色暂未分配就判定无引用。已有任职、管理员任命或审计来源引用也不得随迁移隐式改归属。预检发现此类情况应阻断批次、列明原因；正式提交须在同一事务内复核依赖，防止预检后新增引用。

此类调整采用在目标公司建立新组织、明确结束/新增任职的方式处理；原组织、角色和历史授权保留原公司归属。新角色与授权仍按 UC-02/03 申请，旧授权清理由 UC-04 办理，不通过 HR 导入自动转移或授权。仅对没有上述引用的组织节点允许明确迁移，并校验完整子树、目标公司、无循环、稳定标识及版本；组织更名不属于跨公司迁移。

## 5. 输入、输出与正常流程

输入：文件或已规范化数据、来源与批次编号、模板/字段映射、导入类型、明确初始化状态选项及修改原因。操作者由会话取得，不能在文件中指定自己为总管理员。

输出：预检结果、行号/字段问题、新增/更新/不变/结束任职/停用数量、待确认映射及执行结果。批次中的计划数量与实际提交数量分开，预检完成不表示已经导入成功。

| 步骤 | 总管理员操作 | 系统处理 |
| --- | --- | --- |
| 1 | 选择数据类型、来源文件和权威工作表 | 校验身份、允许格式与批次，读取实际数据区域 |
| 2 | 设置或核对字段及组织映射 | 检查必须字段、编码、完整路径和映射歧义 |
| 3 | 发起预检 | 检查组织依赖、循环、岗位归属、员工标识、重复行及兼岗关系 |
| 4 | 查看报告并修正错误 | 返回逐项问题与计划变更；不写正式组织、员工或授权数据 |
| 5 | 预览通过批次的变更并确认 | 冻结内容及映射，提示停用/结束任职的影响，不因导入默认授予权限 |
| 6 | 执行导入 | 重新验证资格与版本，按依赖顺序在同一事务更新数据、批次结果和成功摘要 |
| 7 | 查看执行报告 | 返回实际计数及批次编号；失败整体回滚并提供安全错误说明 |
| 8 | 后续分配或权限查询 | UC-03 使用最新任职判断可分配范围，UC-05/06 和 UC-09 使用员工状态、任职及已失效关系；新增业务授权仍按 UC-03 办理 |

文件内容只作为数据读取，不执行宏或把单元格文字当作指令。详细错误日志保留在服务端，界面不返回 SQL、凭据或完整异常堆栈。

## 6. 入职、兼岗、调岗与停用

| 场景 | 本用例动作 | 对权限的影响 |
| --- | --- | --- |
| 新员工 | 建立员工及明确任职 | 默认无业务角色、无系统进入权限、无后台账号 |
| 增加兼岗 | 新增明确任职，保留其他任职 | 不自动授予新公司/系统角色 |
| 调岗 | 明确结束旧任职并建立新任职，保留历史 | 不自动把旧角色迁移到新部门，不自动按新岗位授权 |
| 只结束某项任职 | 标记该任职结束，检查剩余任职 | 不再满足适用条件的授权及任命失效；其他适用兼岗保留 |
| 明确全局离职/停用 | 更新员工全局状态，保留历史关系 | UC-05 返回不可进入及空集合；UC-06 拒绝；关联后台账号按 UC-09 拒绝访问，不等待 OA |
| 明确恢复员工 | 恢复员工有效状态并核对任职 | 原授权和专员任命不自动恢复；分别重新申请或任命 |

**任职持续资格与失效不恢复：** 公司级角色要求本公司有效任职，部门级角色要求在本部门直接有效任职，不覆盖下属部门。按变更后的全部任职判断：岗位名称变了但条件仍满足时授权不变；有其他适用兼岗时不失效。确实不再满足条件的已生效授权立即标记失效，更新关系状态／版本并记录原因，历史保留。重新回到原组织不能复活旧记录，必须通过 UC-03 重新申请并经 OA 批准执行。

员工全局停用不区分临时停用与离职：使其全部业务授权、公司专员任命失效，并阻止关联后台账号访问。恢复员工仅恢复身份可用状态，不恢复旧授权或旧任命；业务角色重新走 UC-03，公司专员由总管理员按 UC-07 重新任命。失效检查与本批次身份／任职更新、历史及审计一起提交，不能仅返回查询时临时过滤，否则恢复身份可能错误复活旧授权。旧待执行分配方案必须检查失效后的版本，不能因员工恢复而重新放行。

后台专员失去某公司任职条件时，对应任命也失效；其他仍符合条件的公司任命不受影响。失效任命不占在任专员名额，历史保留。原申请人任命失效仍不单独阻止其此前合法申请执行，沿用 UC-11 的原资格来源与目标复核规则。

系统/角色层面的权限变更仍走 UC-02～04；员工全局状态本身是统一身份条件。调用方仍负责根据权限 API 的当前结果执行外部系统访问限制，本用例不直接注销外部系统登录会话。

| E10 | 组织停用/迁移等影响大量既有记录 | 列出影响；有角色、授权或其他历史引用的部门及其子树跨公司迁移必须阻断，不得仅提示后放行；不得因文件漏行自动变更 |

## 8. 数据与事务边界

逻辑实体：Organization、Position、Employee、EmployeeAssignment、来源标识映射、ImportBatch、EmployeeRole、专员任命及失效审计。本用例更新不满足条件的授权／任命有效状态，保留历史，不自动新增授权，不修改 RolePermission。

预检数据与正式业务数据分开；正式提交更新员工组织、受影响授权及任命的失效状态、批次状态和成功审计采用同一本地事务。失败报告在回滚后记录，数据库整体不可用时保留服务端诊断，不伪报审计表已经持久化失败结果。

员工标识、来源映射与任职唯一约束在数据库落实。执行按稳定标识和版本匹配，不通过姓名猜测；并发预检/执行不能导致一批数据覆盖另一批已确认变更。

文件与问题报告限制为总管理员可读，返回最少必要个人信息。保留周期和导入文件清理属于后续运维设计，不在一期提供任意删除员工历史的入口。

## 9. 结构化功能分解

```text
导入／同步员工组织信息
├── 校验管理员、文件类型与来源批次
├── 解析字段及权威工作表
├── 映射组织、岗位与员工统一标识
├── 校验依赖、重复、冲突及任职
├── 生成变更预览与影响报告
└── 复核版本并原子提交数据及批次结果

UC-03：根据当前任职办理新授权
UC-04：撤销旧来源角色关联，独立经过 OA
UC-05/06/09：按员工状态及各自规则决定有效访问
```

HR 是数据来源，不在权限中心实现 HR 自身的入转调离业务流程，也不自动生成角色配置审批。

| UC10-T03 | 已有唯一用户名 | 保留来源标识映射，不另造拼音账号 |
| UC10-T04 | 员工总表与分表重复、相同批次重试 | 不重复创建员工，已执行批次返回原结果 |
| UC10-T05 | 同员工两项合法任职 | 保留兼岗；不按后出现行覆盖前一任职 |
| UC10-T06 | 名称歧义、未知组织或循环 | 预检阻断，修正映射后再提交 |
| UC10-T07 | 标识相同但员工级属性冲突 | 不静默覆盖，阻断批次 |
| UC10-T08 | 文件缺行或没有状态字段 | 不推断离职、不清空历史关系 |
| UC10-T09 | 新员工导入成功 | 无自动后台账号、专员任命、业务角色或系统进入权限 |
| UC10-T10 | 明确调岗/结束单项任职 | 历史保留；仅不再满足条件的授权失效，不影响其他有效任职授权 |
| UC10-T11 | 明确全局停用 | UC-05 不可进入，UC-06 拒绝，关联后台访问拒绝，不等待 OA |
| UC10-T12 | 恢复员工有效状态 | 只恢复身份；全部旧失效授权和任命不恢复，需重新办理 |
| UC10-T13 | 预检后数据版本或映射改变 | 要求重新预检，不用旧预览覆盖 |
| UC10-T14 | 批次执行或成功摘要写入失败 | 整体回滚，不产生半完成数据 |
| UC10-T15 | 专员失去本公司任职条件 | 对应后台管理请求拒绝，其他有效任命按范围保留 |
| UC10-T16 | 非总管理员尝试导入或读取报告 | 拒绝，不泄露完整人员资料 |

## 11. 后续衔接

- API/数据库设计确定模板、字段映射、批次上限、唯一键和版本控制；先用小样本验证，再导入完整老师资料。
- 真实 HR 认证、数据交换协议、定时任务和增量事件不属于一期必须实现项，未来接入仍复用本用例的校验与更新规则。
- 任职条件丧失及员工停用使旧授权失效，保留历史且不自动恢复；人员变更不代替新授权审批。
- 本轮只编写用例，不读取或输出员工个人明细，不导入数据库、不修改原 Excel。
