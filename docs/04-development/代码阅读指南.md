# 代码阅读指南

后端源码根目录为 [`backend/src/main/java/com/rbac/rbac0/`](../../backend/src/main/java/com/rbac/rbac0/)。采用按技术职责分层的结构，先选一个业务，再沿调用链阅读。

## 各层职责

| 位置 | 职责 |
| --- | --- |
| `RbacStructuredApplication.java` | Spring Boot 启动入口 |
| `config/` | 认证配置、Web 配置和拦截器注册 |
| `controller/` | HTTP 路由、请求校验、会话拦截和统一异常响应 |
| `dto/` | 按业务组织的请求与响应类型 |
| `service/` | 业务规则、管理范围、授权和事务 |
| `mapper/` | Spring Data JPA 仓储接口与查询 |
| `entity/` | 数据库实体与关联表映射 |

`mapper/` 中的接口继承 `JpaRepository`，使用的是 Spring Data JPA。请求通常从 `controller` 进入 `service`，再通过 `mapper` 访问 `entity` 对应的数据。

## 按业务查找

下表类名均相对于源码根目录，分别在 `controller/`、`service/` 中。

| 业务 | 接口入口 | 核心业务实现 |
| --- | --- | --- |
| 登录、身份、退出 | `SessionController` | `SessionService` |
| 部门结构 | `DepartmentController` | `DepartmentService` |
| 用户维护、员工调动 | `UserController` | `UserService` |
| 应用、菜单、按钮 | `ApplicationController` | `ApplicationService` |
| 业务角色、角色权限 | `RoleController` | `RoleService` |
| 用户角色分配 | `AuthorizationController` | `UserAuthorizationService` |
| 当前权限、应用鉴权 | `AuthorizationController` | `PermissionCheckService` |
| 操作日志查询 | `OperationLogController` | `OperationLogQueryService` |

其他入口：`BootstrapService` 初始化管理员，`OperationLogService` 写入操作日志；`SessionInterceptor` 处理管理接口会话，`ApiExceptionHandler` 统一转换错误响应。

## 建议阅读顺序

1. 先看[核心需求](../01-requirements/核心需求草稿.md)，理解总管理员、部门管理员与业务角色的区别。
2. 看[建表迁移](../../backend/src/main/resources/db/migration/V1__init_schema.sql)，再对照 `entity/` 理解用户、角色和权限关系。
3. 看 `SessionController → SessionService → SessionMapper`，理解登录和会话。
4. 看 `RoleController → RoleService` 与 `AuthorizationController → UserAuthorizationService`，区分角色配置与给用户分配角色。
5. 看 `PermissionCheckService → PermissionMapper`，理解有效权限查询和业务系统鉴权。
6. 查看对应的 [API 集成测试](../../backend/src/test/java/com/rbac/rbac0/)，对照请求与预期结果。

## 配置与验证

[application.yml](../../backend/src/main/resources/application.yml) 从环境变量读取数据库和初始管理员配置。建表由 Flyway 迁移执行，JPA 校验表结构。

在仓库根目录执行 `mvn -f backend/pom.xml verify`。现有 API 测试需要独立 MySQL 测试库及 `RBAC_TEST_DB_*` 环境变量，具体见[后端说明](../../backend/README.md)。
