# 核心处理流程与事务调用

本文件把数据库T0～T12落实到模块调用，锁定/提交规则继续以[数据库事务设计](../04-database/TRANSACTIONS.md)为准。所有步骤均为设计，尚无服务/SQL/并发运行结果。可编辑辅助图见[core-flows.drawio](core-flows.drawio)。

## F0 统一命令、读取与幂等

1. M12严格解析DTO、版本及上下文头，身份链验证JWT形式/签名/用途；昂贵密码校验、文件解析及网络放事务外，得到的候选事实不能作最终授权。
2. M00使用TransactionTemplate开启RC事务，先锁`mutation_guard(1)`，取当前身份/会话/员工/任命/范围；缺guard或连接不可用报完整性/503，不临时另建锚点。业务写端口都接收同一WriteContext。
3. 有Idempotency参数的操作查主体/method/path/key。完成记录先以固定授权事实复核当前单项覆盖，然后回放安全响应，不再比较原操作已推进的目标版本。相同key异内容409；处理中有效租约409；过期只有同摘要可换token。
4. 新key以短事务固定HMAC摘要和租约，再另开业务T0重新鉴权并核对栅栏；两次之间允许状态变化，第二次必须重新读取。不能为了少一个事务让失败时丢失同key内容绑定。
5. 完整目标授权→准确关系/无变化分类→仍需目标版本→预览依赖复算→受控写端口→完整审计→安全响应及authorization_basis→COMPLETED同事务提交。租约token条件失败或预期更新行数不符全部回滚。
6. 业务失败原事务回滚后，M00错误记录器另T0核对同token、未已成功，白名单确定4xx可记录安全结果；未认证/越权不回放敏感内容；503不永久缓存。完成响应、授权事实及安全头不可改写。

来源关闭的内部实际影响可能跨范围：授权事实只包括输入来源与实际披露响应所需范围，不能把不可披露混合申请的B部门加入原本只需办理A来源的权限要求。完整业务失效仍全部执行。HTTP幂等不用于OA回调、只读POST/预览、登录改密退出；精确入口见TRACEABILITY。

M00读取边界为新主库RR一致快照，M11在同一事务内读身份和数据；不可复用跨HTTP EntityManager或在序列化时补读。事务代理/TransactionTemplate层只在外层一个地方开启，写端口采用MANDATORY语义/显式上下文断言，不按每条明细REQUIRES_NEW。

## F1 系统目录及角色元数据

M04登记系统，在同T0创建唯一SYSTEM_ACCESS。目录命令锁内读取同系统完整父关系，将本地引用解析为预分配ID，构造最终树/权限集合，校验无环、类型、同系统、合法可见绑定、输入重复及对象/catalog版本。按停用新节点→操作→绑定→最终状态处理即时FK，全部成功才推进catalogVersion/audit/幂等；合法无变化不增版本。

停用目录/权限保留角色配置和grant，M11按当前有效祖先过滤；恢复只可能恢复仍有效关系的目录能力。角色改名由M05仅增metadataVersion。createRole由M07编排M05插入UNCONFIGURED角色＋初始草稿/claim，同事务返回角色，不写有效配置。

## F2 草稿与预览确认、固定提交

1. M07取当前角色/来源/关系及全部适用任职，固定一公司和明确明细；新来源/baseline由M06在T0物化。拒绝重复业务键，不做员工×角色隐式组合；employmentIds不得裁为100项。
2. 修改草稿时比draftVersion，在同事务释放移除的claim、获得新增claim、替换完整内容和目标投影。任一新占用失败全部回滚，原草稿/claims保留。无变化项可留草稿展示但不占用。
3. M11生成预览依赖：输入/草稿版本、完整目标/状态版本、适用任职集合、实际影响查询的键/版本集合（含空集合断言）、原创建上下文和5分钟到期。结果统计/分页来自同一快照及安全投影。
4. submit在T0依次：全部目标当前授权；同源已ACTIVE→ALREADY_GRANTED、准确旧ID已结束→ALREADY_ENDED；仍需项检查配置/来源周期/关系版本；对比预览输入/分类/依赖。陈旧409，不静默删新无变化项。全部无变化200且不投OA；空配置422。
5. 有实际内容时，只把实际清单一起固定为content和change_target，保留全部当时适用证据/名称/版本。原资格由后端生成GLOBAL或SCOPE快照；submittedVersion取当前draftVersion，submittedAt/提交人/原因固定。CanonicalPayloadCodec按契约包和稳定集合排序生成RFC8785字节与SHA256。
6. 写申请PENDING、固定内容/字节/摘要、提交审计及oa_outbox，一次提交；有效配置/grant不变。状态变化不改submittedVersion。驳回复制仅新ID草稿，不能修改原固定申请。

范围变化后的DRAFT不伪造INVALIDATED提交分支，当前不能覆盖的权限管理员收到通用占用提示，不能取得隐藏申请ID；总管理员用现有查看/编辑/删除入口清理。删除前固化审计和幂等授权事实，释放claim/目标后再删草稿；历史已提交申请不可删除。

## F3 OA受理、最终结果和执行唤醒

M08领取待发送项：T0取锚点→读PENDING/NONE、PENDING_SEND或SEND_FAILED及无关联→取得租约→提交。发送前另T0核对状态/token，然后事务外调用OaSubmissionPort。超时保持原requestId重试；返回后T0校验回执版本/摘要/实例，写唯一oa_link。已失效申请只记录历史关联、STOPPED，不变回PENDING；人工重试仅合法SEND_FAILED/statusVersion匹配。

回调经过OaJwt与当前实例，M08在T0先查可靠关联，无关联409/Retry-After且不占成功事件。再按(instance,eventId)比完整规范payload，核对申请固定版本/摘要/审批号和唯一最终结果。同事件异内容或相反决定409；不同事件同决定可记诊断并200 duplicate=true。新可信结果可靠写事件/final_result、批准/驳回状态及审计，独立提交后202。批准不写有效授权；驳回释放claim。原已INVALIDATED只留历史。

afterCommit可提示执行器但不是可靠队列。M09启动及每30秒扫描APPROVED/到期EXECUTION_FAILED，只取候选ID后逐个进入F4；丢失唤醒仍能恢复。建议单节点一个发送器/执行器循环，扩实例也依赖数据库锚点/租约，不依赖JVM synchronized。

## F4 批准后一次成功执行

1. M09先T0锚点，再查execution_success。已有成功回读历史；否则读取固定申请/投影/可靠关联/最终批准，校验规范字节与投影一致；状态不合法不执行。
2. 原范围覆盖：GLOBAL不依赖管理员系统列表；SCOPE只看原scopeId当前覆盖全部固定目标及持久失效历史，不要求原申请人/原任命仍有效。范围缩小、来源推进已导致INVALIDATED时不因后来恢复复活。
3. 类型复核：配置检查固定基础configurationVersion及完整差集，新增当前有效/同系统/祖先有效，保留停用项合法，最终非空；授予检查员工/系统/角色EFFECTIVE、固定配置/来源epoch/baseline及当前适用任职；撤销只查准确grantId仍ACTIVE/版本/来源，不机械要求配置或系统启用。
4. 全部目标先复核，任一不合法则**整份**INVALIDATED/释放全部claim/停outbox/写失效审计，不改合法子集。执行期不重新用ALREADY分类裁剪批准内容。
5. 全部合法才调用M05/M06应用器写业务/版本及证据；写成功audit→execution_success请求PK→配置历史/attempt→EXECUTED/SUCCEEDED→释放claims，一起COMMIT。角色配置变更由M09调用M07失效受影响旧授予，不能在M05形成反向服务调用。
6. 存储/审计异常整事务回滚；FailureRecorder在原事务外另T0，重新读success/当前状态，已成功或已失效则不覆盖；仍合法才记EXECUTION_FAILED/失败码/attempt/nextRetryAt。退避从5秒至5分钟，不以重试次数自动取消。数据库不可用时保持可靠批准记录，仅运行日志诊断。

验收必须用两连接分别控制先提交执行/关权的顺序，以及第N项和成功审计失败，不能仅靠接口返回码证明原子性。

## F5 来源关闭、员工状态与范围替换

M10提供一个LifecycleCoordinator，跨域写端口共享WriteContext。关来源时，当前单项范围覆盖所选全部来源→物化0基线→精确expected epoch/version→逐源推进周期→M06结束有效grant/推进baseline→M07按命中事实整份失效已提交授予和准确撤销→释放claims/停止待办→审计、安全计数和幂等同提交。无grant也推进；其他来源/角色配置/员工身份保留。

员工全局停用先防当前/唯一总管理员自锁，再写员工INACTIVE、推进全部有关来源、结束grant、终结全部任命、推进关联sessionEpoch及失效申请；恢复只写ACTIVE。账号停用由M01只改后台账号/会话，不做此生命周期动作。范围替换由A负责M10入口，调用M03完整替换，原范围实质失覆盖才持久失效；新增任命必须当前适用，扩回不复活原任命/申请。

离岗按每个明确END事件检查适用任职：仍有适用兼岗则按来源/部门角色各自资格保留；最后适用任职结束即推进有关周期/关系版本、终结失去资格任命/旧申请。Q-01明确同批随后ADD新岗不抵消已经发生的离岗；仅岗位更名不制造END。所有调用在外层同一事务，底层端口不独立提交。

## F6 HR冻结预检与原子提交

上传先在事务外解析/校验文件边界并把字节持久到受控路径，SHA确认后T0存元数据。元数据失败的孤文件受控清理，不返回成功后缺原文件。预检用新快照生成不可变计划，锁内再核对依赖后落import_batch/plan_row/issues并seal，预检不写正式组织/员工。

计划包括原始/规范化前后值、源标识和映射、候选稳定ID/code、目标版本、唯一键不存在断言、任职动作顺序及影响。首次无编码按完整来源路径建立候选，不按姓名合并。文件/映射变化用新批号预检，不原地改固定批次。

提交在T0先当前总管理员→成功批次长期回放→批次/version/digest及允许状态→全部依赖/唯一性/防自锁复核→按冻结动作顺序调用M02及F5生命周期→实际counts/audit/SUCCEEDED同事务。1000行可以分段flush但不能分段COMMIT、REQUIRES_NEW逐行或跳错行。

陈旧/冲突整批无正式写入，原事务回滚后另T0确认未成功才记STALE；暂时存储失败同样防覆盖成功才记FAILED，重试重新完整复核。部门迁移有任何业务/历史引用就阻断，合法无引用迁移按数据库即时FK和映射顺序执行，不改写历史归属。

## F7 有效权限、影响与审计

M11对业务调用绑定系统、当前公司员工资格及完整ACTIVE/有效epoch/适用任职的grant合并角色有效配置，过滤系统/权限/目录有效祖先。先判断SYSTEM_ACCESS；无进入则操作和菜单为空；有进入再独立计算操作并集、菜单可见操作及必要containerOnly父级。不能用管理员可见来源子集替代完整业务授权，也不能把编辑推导成查看。

影响预览和审计只披露当前一项范围允许目标，混合固定申请必须全部覆盖才返回ID/内容/计数；完整内部失效不因展示过滤而被裁剪。读取旧previewId需当前创建上下文和有效期复核，变化则要求重预览。直接关权结果仅含可见计数和可读auditId；有隐藏实际影响使用SCOPED/true，不能返回全局0含义。
