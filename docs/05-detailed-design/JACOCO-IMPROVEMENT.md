# JaCoCo 采集与边界测试改进

## 范围与基线

基于 main/c22e922，保留首次共享报告作为历史快照：579 项测试通过，行覆盖率 95.70%、分支覆盖率 72.99%。未覆盖行中，BootstrapAdminApplication 占 79 行，DemoServiceApplication 占 36 行；现有测试通过独立 Java 子进程执行，原 agent 未随子进程启动。

本轮先补采集，再以报告定位有业务意义的边界用例；不排除正式源码、不降低断言、不通过改写业务规则提高数字，不预先承诺全部指标达到 100%。

## 实现与验证顺序

1. 新增仅用于测试的 Java 子进程工厂，保持显式环境清理；coverage 启用时转交当前测试 JVM 的 JaCoCo agent，为每个子进程分配独立 exec 文件，普通测试保持可运行。
2. 先以真实子 JVM 执行并检查采集文件的测试复现缺口，再接入 agent；将管理员初始化和演示 CLI 的现有命令接入该工厂。
3. Maven 在 post-integration-test 汇总主测试和子进程 exec，再在 verify 生成报告；只使用本次 clean 构建的采集文件。
4. 依据剩余红/黄行补可观察的错误处理、权限/输入和导入边界断言；测试既有行为时保留真实运行结果，不将新增回归用例冒充新功能的 RED。
5. 在本轮专属临时 MySQL8.4 完整运行普通与真实 HTTP/MySQL 测试，验证默认 profile，核对随机库/账号清理及实例关闭。
6. 同时保留首次结果和改进结果，更新团队共享说明、完整归档和摘要，标明新增覆盖来自采集修复还是新增测试。

## 验收行为

- 移除子进程 agent 转交将使采集回归测试失败；进程实际退出成功且产生本轮独立采集文件。
- 未启用 coverage 时子进程正常运行，不生成子进程 exec，不依赖本机额外配置。
- 初始化与演示工具仍通过真实退出码、数据库结果、禁止覆盖及输出脱敏断言，原业务测试全部保留。
- 新增边界测试断言实际结果，不只调用方法或检查源码文本。
- 报告仅包含正式编译类；无新增包/类排除规则，百分比由 XML 顶层 counter 计算。
