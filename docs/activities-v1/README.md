## 图的读法与责任边界

实心圆是初始节点，靶心圆是活动终点；圆角矩形是动作，带 `[条件]` 的菱形是决策，小菱形是合并。泳道表示管理员、权限中心、外部调用方的责任，不表示技术模块或线程。实际父子关系保存在文件中，可以分别编辑动作与泳道。

控制箭头全部采用直线与空心箭头，不使用正交折线或沿泳道边界的路由。返回修改、继续使用和故障重试通过泳道内部的合并节点汇入，不把多个输入直接接成动作的隐式同步。

UC-02～04 只展示外部 OA 审批及最终结果交付；权限中心调用 UC-11 处理结果和自动执行，不设计 OA 内部步骤，不增加人工再次确认。UC-11 区分结果可靠接收与业务执行事务，短暂失败保留批准依据，恢复后自动重试并重新校验。终点只表示本次活动结束，不取消后台恢复任务。

UC-05／06 仅返回权限结果，业务系统负责实际拦截、公司数据隔离及 SELF 对象判断。UC-10 当前采用文件或模拟来源导入，文件选择由管理员操作，因此不另画一个主动调用权限中心的真实 HR 服务泳道。

## 文件与维护

详细用例仍是验收依据；黄色备注补充范围、幂等、整体回滚、身份恢复不复活旧授权等规则。图不替代完整异常说明，也不代表后端已实现。

`generate_all.py` 从当前流程定义复用业务步骤，在本目录构建活动节点、真实泳道和直线布局；不执行流程图输出代码，不读取 history。`generate_uc02.py` 是单张样板的兼容入口。生成脚本会覆盖相应文件，手工编辑后不要直接重跑。

已检查 XML、唯一 ID、连线引用与父级、起点可达、节点不重叠、节点位于泳道内、直线不穿过无关动作框及文字边界。PNG 使用同一节点数据在本地辅助绘制，并非 draw.io 客户端导出；未将图内容自动发送到第三方网站，尚未在实际 draw.io 客户端逐页人工验收。

在 draw.io 中选择“文件 → 从以下位置打开 → 设备”，打开汇总文件后切换底部页签；也可以打开对应的单个用例文件。
