## UC-11 接收审批结果并执行权限变更

详细依据：[原用例](UC-11_接收审批结果并执行权限变更.md)

| 项目 | 内容 |
| --- | --- |
| 级别 | 子功能（支撑外部审批执行） |
| 包 | 外部审批结果接入 |
| 参与者 | OA 系统 |
| 描述 | 接收最终审批结果，并按已批准的原申请执行角色配置、分配或撤销。 |
| 触发事件 | OA 向权限中心交付某项申请的最终审批结果。 |
| 前置条件 | 本地已存在正式提交的申请，并已与外部审批关联。 |

| 主成功场景 | 信息 |
| --- | --- |
| 1. OA 提交最终批准结果及对应申请信息。 | OA 服务身份、申请与审批编号、最终结果 |
| 2. 权限中心核对结果来源、申请及批准内容。 | 固定申请、内容匹配情况 |
| 3. 权限中心记录批准结果，并确认原方案仍符合执行条件。 | 审批状态、原资格依据、当前范围和目标条件 |
| 4. 权限中心自动执行获批的角色配置、分配或撤销。 | 批准的完整变更清单 |
| 5. 权限中心记录实际生效结果及审计信息。 | 执行状态、实际变更、执行时间 |
| 6. OA 获得处理状态，管理员可查询申请结果。 | 接收结果、执行状态 |

| 扩展场景 | 信息 |
| --- | --- |
| 2a. 来源不可信、内容不符或非最终结果：拒绝执行。 | 拒绝原因 |
| 2b. 重复已成功通知：返回原结果，不重复授权；冲突最终结果拒绝。 | 已有处理结果 |
| 3a. OA 最终驳回：记录驳回，不执行权限变更，结束本次处理。 | 驳回结果及原因 |
| 3b. 原方案范围、目标条件、权限有效状态或版本已不合法（含停用后恢复）：标记失效，需重新申请。 | 失效原因 |
| 4a. 暂时执行失败：整批不生效，保留批准依据；条件仍合法时自动重试。 | 失败／待恢复状态 |

其他：仅承接 UC-02～04，不实现 OA 内部审批。原申请人离任或公司暂时无专员不单独阻止执行；总管理员原申请按全局资格，专员原申请按公司范围复核。已批准方案不提供人为取消入口。批准不等于已生效。
