# API 设计入口

版本：1.0.0；需求 V1.3；日期：2026-10-16。适用 Spring Boot + Spring Data JPA、REST、JWT，数据库后续采用 MySQL。本目录交付接口设计，不代表服务已实现或 Apifox 已同步。

## 阅读顺序

1. [公共约定及资源关系](CONVENTIONS.md)：三类入口、标识、认证、分页、校验、错误。
2. [接口清单](ENDPOINTS.md)：按模块列出方法、路径、权限、用例。
3. [OpenAPI 3.1 契约](openapi.yaml)：请求、响应、模型、示例及各操作约束的权威接口文件。
4. [追踪表](TRACEABILITY.md)：UC—页面—operationId—关键验收语义。
5. [状态与一致性](CONSISTENCY.md)：固定申请、幂等、并发、原子批量、自动执行及恢复。
6. [Apifox 同步记录](APIFOX.md)：项目 8934976、导入及回读流程、实际完成边界。
7. [数据库设计交接](DATABASE-HANDOFF.md)：持久化与事务要求，不确定物理表。
8. [验证与待办](VALIDATION.md)：工具结果、设计审查、非阻塞未决项。

Git 中 `openapi.yaml` 为接口契约权威来源。修改契约后先校验，再人工导入 Apifox 默认模块，经 MCP 刷新、回读及语义比较确认；未导入不宣称远程一致。当前任务不修改原型，R-01～R-03 继续按 D-029 跟踪；相应 API 规则均保留。

## 资源关系草图（逻辑对象，非物理表）

```text
公司 → 平级部门 → 岗位 ← 任职 → 员工 ← 后台账号 → 会话
                       员工 ← 任命 → 管理范围 → 一个公司、一个部门、系统集合
业务系统 → 导航/功能目录 → 功能操作；业务系统 → 唯一系统进入权限
角色 → 公司、可选部门、一个系统、当前有效权限配置
授权来源（员工、公司、部门、系统、周期） → 独立授权关系 → 角色
固定申请 → 原资格依据、配置/分配/撤销明细、固定摘要
固定申请 → OA 投递 → 最终结果 → 自动执行尝试 → 成功审计
导入批次 → 文件/规范数据、映射、预检、目标版本 → 原子提交
```

这些箭头表达关联，不能据此直接生成 JPA 实体或数据库外键。稳定标识和业务编码分开；岗位不绑定角色；管理资格不授予业务权限。
