## UC-01 维护业务系统与权限目录

详细依据：[原用例](../usecases-v1/UC-01_维护业务系统与权限目录.md)

| 项目 | 内容 |
| --- | --- |
| 级别 | 用户目标 |
| 包 | 系统与权限目录 |
| 参与者 | 权限中心总管理员 |
| 描述 | 维护接入系统、菜单及功能操作，供角色配置和业务权限查询使用。 |
| 触发事件 | 新系统接入，或已有系统需要增加、修改、停用权限目录。 |
| 前置条件 | 总管理员已登录；待维护内容的业务含义及归属明确。 |

| 主成功场景 | 信息 |
| --- | --- |
| 1. 管理员选择已有系统或登记新系统。 | 系统名称、编码、说明 |
| 2. 系统展示该系统的权限目录及系统进入权限。 | 系统进入权限、目录树、当前状态 |
| 3. 管理员维护菜单、操作权限及菜单可见条件。 | 菜单层级、操作编码、功能归属、关联查看／进入页面权限 |
| 4. 系统展示变更及对已有授权的影响。 | 新增、修改、启停明细及影响提示 |
| 5. 管理员核对变更，填写原因并确认保存。 | 确认内容、修改原因 |
| 6. 系统保存目录并显示维护结果。 | 保存结果、最新目录 |

| 扩展场景 | 信息 |
| --- | --- |
| 3a. 编码重复、归属错误或菜单绑定不合法：提示原因，返回第3步修正。 | 问题字段、规则说明 |
| 3b. 停用或恢复目录：第4步提示对子目录及已有授权的影响，确认后保存；保留历史。 | 受影响目录及授权 |
| 3c. 删除已引用项或跨系统迁移：拒绝，改用新增与停用方式。 | 拒绝原因 |
| 5a. 内容已被他人修改：重新读取并核对后提交。 | 最新内容、冲突提示 |
| 6a. 保存失败：本次变更不生效，提示稍后重试。 | 失败说明 |

其他：无需 OA 审批。每系统有独立进入权限，登记不等于授予；新增目录不自动授权。清单中含义不明的项目须核对，不猜测“全部”。


## UC-02 创建角色并配置权限

详细依据：[原用例](../usecases-v1/UC-02_创建角色并配置权限.md)

| 项目 | 内容 |
| --- | --- |
| 级别 | 用户目标 |
| 包 | 角色配置 |
| 参与者 | 权限中心总管理员、公司权限管理专员；协作：OA 系统 |
| 描述 | 管理员创建角色或调整已有角色权限，经 OA 批准并执行后生效。 |
| 触发事件 | 需要建立角色，或调整角色的系统进入权限及功能操作集合。 |
| 前置条件 | 管理员已登录并具有目标公司、组织和系统的配置申请资格。 |

| 主成功场景 | 信息 |
| --- | --- |
| 1. 管理员选择归属公司、组织和系统，新建角色或选择已有角色。 | 角色名称、全局唯一编码、组织归属、业务系统 |
| 2. 系统展示该系统可配置权限及角色已有配置。 | 系统进入权限、菜单及操作、当前配置 |
| 3. 管理员勾选系统进入权限或功能操作，并填写申请原因。 | 功能权限集合、申请原因 |
| 4. 系统展示配置差异和影响，供管理员核对。 | 新增操作、移除操作、影响摘要 |
| 5. 管理员确认提交角色配置申请。 | 确认后的完整配置方案 |
| 6. 系统受理申请并提交 OA，显示待审批。 | 申请编号、申请内容、待审批状态 |
| 7. OA 返回最终批准结果，由 UC-11 接收并执行变更。 | 最终审批结果、执行结果 |
| 8. 管理员查看结果，系统显示已生效的角色配置。 | 角色配置、执行状态 |

| 扩展场景 | 信息 |
| --- | --- |
| 1a. 仅保存草稿：保留未生效配置；新角色不可分配，可稍后继续。 | 草稿编号、状态 |
| 3a. 越管理范围、选择无效操作、混入其他系统权限或配置为空：拒绝提交，返回修改。 | 不合法项、原因 |
| 5a. 无实际变更或已有未结束配置申请：不新建审批，提示现状。 | 现有配置或申请 |
| 7a. OA 驳回：有效配置不变；可复制原方案为新草稿，修改后重新提交。 | 驳回原因、原申请 |
| 7b. 方案失效或执行失败：显示未生效及原因，按 UC-11 处理。 | 申请状态、失败原因 |

其他：角色属于一个公司和一个系统，可限定直接任职部门，岗位不自动绑定。同公司专员共享范围内角色管理权；总管理员可管理全部公司、系统。旧配置在修改审批期间继续有效；全部权限仅配置是否授予；一期无独立角色启停。


## UC-03 为员工分配角色

详细依据：[原用例](../usecases-v1/UC-03_为员工分配角色.md)

| 项目 | 内容 |
| --- | --- |
| 级别 | 用户目标 |
| 包 | 员工授权 |
| 参与者 | 权限中心总管理员、公司权限管理专员；协作：OA 系统 |
| 描述 | 为员工申请新增业务角色，审批执行成功后员工获得对应授权。 |
| 触发事件 | 员工入职、兼岗或工作需要新增角色。 |
| 前置条件 | 管理员已登录且有管理资格；目标员工有效并满足角色任职条件，角色已生效。 |

| 主成功场景 | 信息 |
| --- | --- |
| 1. 管理员选择目标公司和待授权员工。 | 公司、员工统一标识、任职信息 |
| 2. 系统展示已有授权及可分配角色。 | 已有角色、授权来源、有效角色 |
| 3. 管理员明确各员工拟新增的角色并填写原因。 | 员工—角色配对、分配原因 |
| 4. 系统展示实际新增明细和权限摘要。 | 角色所属系统、功能权限、进入资格提示 |
| 5. 管理员确认提交，系统受理并交由 OA 审批。 | 固定分配清单、申请编号、待审批状态 |
| 6. OA 返回最终批准结果，由 UC-11 执行角色分配。 | 审批结果、实际新增关系 |
| 7. 管理员查看执行结果。 | 生效状态、员工新增角色 |

| 扩展场景 | 信息 |
| --- | --- |
| 3a. 已有相同有效关系：排除重复项；全部无变化时不提交审批。 | 无变化明细 |
| 5a. 存在越范围、任职不符、无效角色或重叠申请：拒绝，修正后再提交。 | 问题明细、现有申请 |
| 6a. OA 驳回：不增加角色；修改后以新方案重新申请。 | 驳回原因 |
| 6b. 角色内容变化或员工已不符合任职条件：原方案失效，重新申请。 | 失效原因 |
| 6c. 执行失败：整批不增加授权，按 UC-11 恢复处理。 | 执行状态 |

其他：只新增选定关系，不替换已有角色；允许兼岗和跨系统持有多个角色。范围来自角色配置；仅有功能权限而无同公司、同系统进入权限时功能不可使用。失效历史不阻止重新申请。岗位变化但条件仍满足时保留；失去任职条件则授权失效，恢复任职后重新申请。部门角色只适用直接任职。


## UC-04 撤销员工角色

详细依据：[原用例](../usecases-v1/UC-04_撤销员工角色.md)

| 项目 | 内容 |
| --- | --- |
| 级别 | 用户目标 |
| 包 | 员工授权 |
| 参与者 | 权限中心总管理员、公司权限管理专员；协作：OA 系统 |
| 描述 | 撤销指定员工与角色的授权关系，保留其他有效来源的权限。 |
| 触发事件 | 员工职责变化或不再需要某项角色授权。 |
| 前置条件 | 管理员已登录并具备目标授权来源的撤权资格。 |

| 主成功场景 | 信息 |
| --- | --- |
| 1. 管理员查询目标员工可管理的角色授权。 | 员工、公司、系统、授权来源 |
| 2. 系统展示可撤销关系，包括本组织的历史授权。 | 角色关联、状态、来源组织 |
| 3. 管理员选择撤销关系并填写原因。 | 明确的撤销清单、撤销原因 |
| 4. 系统展示撤销明细和可见范围内的影响。 | 角色及权限摘要、重合权限提示 |
| 5. 管理员确认提交，系统受理并交由 OA 审批。 | 固定撤销清单、申请编号 |
| 6. OA 返回最终批准结果，由 UC-11 执行撤销。 | 最终审批结果、执行结果 |
| 7. 管理员查看结果，后续权限按剩余有效角色计算。 | 撤销状态、剩余授权 |

| 扩展场景 | 信息 |
| --- | --- |
| 3a. 关联已撤销：排除无变化项；全部无变化时不发起审批。 | 当前关系状态 |
| 5a. 超管理范围或目标关系已变化：拒绝提交，重新查询。 | 拒绝原因 |
| 6a. OA 驳回：本次申请不改变授权；可修改后重新申请。 | 驳回结果 |
| 6b. 旧方案已不适用：不撤销后续重新授予的新关系。 | 失效原因 |
| 6c. 执行失败：整批不执行撤销，按 UC-11 处理。 | 失败状态 |

其他：撤销关联不删除角色、不停用员工、不影响其他员工；重合权限仍由剩余角色提供。员工已调离或停用时，失效关系作为历史／无变化项；旧回调不得影响重新授予。提交撤销申请本身不改变有效授权。


## UC-05 查询员工有效权限

详细依据：[原用例](../usecases-v1/UC-05_查询员工有效权限.md)

| 项目 | 内容 |
| --- | --- |
| 级别 | 用户目标 |
| 包 | 对外权限服务 |
| 参与者 | 业务系统后端 |
| 描述 | 查询员工在当前公司、调用方所属系统的进入资格、可见菜单及允许的功能操作。 |
| 触发事件 | 业务系统需要取得员工当前权限，例如展示功能入口时。 |
| 前置条件 | 调用方已登记；业务系统自行认证员工，并可信传递统一员工标识。 |

| 主成功场景 | 信息 |
| --- | --- |
| 1. 业务系统提交员工与当前公司权限查询请求。 | 服务身份、员工统一标识、当前公司、系统标识 |
| 2. 权限中心确认调用身份、公司和系统，检查员工有效性及任职。 | 身份和系统匹配结果、公司及员工任职 |
| 3. 权限中心确定员工在当前公司、当前系统的进入资格及有效权限。 | 进入资格、未失效的已生效授权 |
| 4. 权限中心返回进入资格、可见菜单及允许的功能操作集合。 | 进入资格、菜单集合、功能操作集合 |
| 5. 业务系统接收结果，用于本系统入口和功能展示。 | 权限结果、菜单与本地页面的对应关系 |

| 扩展场景 | 信息 |
| --- | --- |
| 2a. 参数不合法、身份无效、跨系统或系统停用：拒绝查询，返回错误。 | 错误原因 |
| 3a. 员工不存在、停用、无当前公司有效任职或无该公司进入资格：返回无进入资格，菜单和操作为空。 | 进入资格为否、空集合 |
| 3b. 有进入资格但无功能授权：返回有进入资格，菜单和操作为空。 | 进入资格为是、空集合 |
| 4a. 查询服务故障或授权数据异常：返回错误，不伪装为空权限。 | 服务错误 |

其他：同公司、同系统有效角色权限取并集；相同功能操作去重，不同操作互不推导。菜单须有对应查看／进入页面权限，祖先可仅作导航。编辑权限不自动推导查看权限。业务系统负责后续功能访问拦截；待审批方案不参与计算。


## UC-06 检查员工指定操作权限

详细依据：[原用例](../usecases-v1/UC-06_检查员工指定操作权限.md)

| 项目 | 内容 |
| --- | --- |
| 级别 | 用户目标 |
| 包 | 对外权限服务 |
| 参与者 | 业务系统后端 |
| 描述 | 查询员工是否拥有指定系统进入权限或功能操作权限。 |
| 触发事件 | 业务系统准备让员工进入系统或执行某项受保护操作。 |
| 前置条件 | 调用方已登记，员工身份由业务系统认证并可信传递。 |

| 主成功场景 | 信息 |
| --- | --- |
| 1. 业务系统提交员工、当前公司及待检查权限。 | 服务身份、员工统一标识、当前公司、系统、权限编码 |
| 2. 权限中心确认调用身份、公司及系统归属、员工状态和任职。 | 调用资格、公司、员工状态与任职 |
| 3. 权限中心判定指定权限是否有效且已获授；功能操作同时要求系统进入资格。 | 权限类型、有效授权、进入资格 |
| 4. 权限中心返回是否拥有该功能权限。 | 有无权限；系统进入权限与功能操作均为布尔结果 |
| 5. 业务系统据结果执行访问限制及自身业务校验。 | 拒绝／允许对应功能、后续业务校验 |

| 扩展场景 | 信息 |
| --- | --- |
| 2a. 参数错误、身份无效、跨系统或系统停用：返回调用错误，不提供正常鉴权结果。 | 错误说明 |
| 3a. 员工无效、权限未知／停用、未获授或缺少所需进入资格：返回无权限。 | hasPermission=false |
| 3b. 检查系统进入权限：直接判断其授权，不要求功能权限，返回有无权限。 | 进入权限结果 |
| 4a. 查询故障或数据异常：返回服务错误，业务系统不能据此放行。 | 服务错误 |

其他：可独立调用，不要求先调用 UC-05。权限中心不查询外部业务记录，不设计数据权限。按当前公司、系统计算功能授权；业务系统执行对应功能拦截及自身业务规则。


## UC-07 配置管理员及管理范围

详细依据：[原用例](../usecases-v1/UC-07_配置管理员及管理范围.md)

| 项目 | 内容 |
| --- | --- |
| 级别 | 用户目标 |
| 包 | 后台管理资格 |
| 参与者 | 权限中心总管理员 |
| 描述 | 为各公司配置权限管理专员及共同管理的系统范围。 |
| 触发事件 | 公司需要任命、替换专员，或调整可管理系统。 |
| 前置条件 | 总管理员已登录；公司和候选人员资料已登记。 |

| 主成功场景 | 信息 |
| --- | --- |
| 1. 总管理员选择公司。 | 总公司或分公司标识 |
| 2. 系统展示当前专员及共同管理范围。 | 专员名单、公司部门范围、系统集合 |
| 3. 总管理员调整可管理系统及专员名单。 | 最终专员名单、获准系统 |
| 4. 系统展示变更和对后续管理的影响。 | 任免差异、系统增减、待处理申请影响 |
| 5. 总管理员填写原因并确认。 | 变更原因、确认内容 |
| 6. 系统保存配置并显示生效结果。 | 最新名单及管理范围 |

| 扩展场景 | 信息 |
| --- | --- |
| 3a. 候选人没有账号：先按 UC-09 配套流程创建，再继续任命。 | 员工标识、后台账号 |
| 3b. 候选人不符合任职条件、重复或超过3人：提示修正，不能保存。 | 问题人员、人数 |
| 5a. 明确提交空名单或空系统集合：提示暂时无人／无系统可管理，确认后保存。 | 影响提示、原因 |
| 5b. 资格无效或配置已变更：拒绝，重新读取后办理。 | 拒绝原因 |
| 6a. 保存失败：保留原名单及范围。 | 失败说明 |

其他：不经过 OA。每公司通常1～3人，同公司专员共享范围内角色；不按创建者分配管理权。公司边界不跨其他公司节点。任免或缩小范围不自动删除业务授权，不自动授予系统进入权限。员工停用使任命失效，恢复后总管理员重新任命。


## UC-08 查询授权审计记录

详细依据：[原用例](../usecases-v1/UC-08_查询授权审计记录.md)

| 项目 | 内容 |
| --- | --- |
| 级别 | 用户目标 |
| 包 | 授权审计 |
| 参与者 | 权限中心总管理员、公司权限管理专员 |
| 描述 | 在管理范围内查询角色配置与员工授权的历史及执行结果。 |
| 触发事件 | 管理员需要核对某次权限变更或追溯授权来源。 |
| 前置条件 | 管理员已登录并具有当前查询范围内的管理资格。 |

| 主成功场景 | 信息 |
| --- | --- |
| 1. 管理员打开审计查询并填写条件。 | 时间、公司、系统、员工／角色、事件、申请编号 |
| 2. 系统展示范围内匹配记录。 | 摘要列表、结果数量、分页 |
| 3. 管理员选择一条记录查看详情。 | 记录标识 |
| 4. 系统展示变更内容及关联审批、执行情况。 | 操作者、时间、变更前后、审批和执行状态 |
| 5. 管理员核对记录，或调整条件继续查询。 | 查询条件、核对结果 |

| 扩展场景 | 信息 |
| --- | --- |
| 1a. 条件不合法：提示修正，重新查询。 | 问题字段 |
| 2a. 无匹配记录：显示空列表，不作为服务故障。 | 零条匹配结果 |

其他：只读，不修改、删除或重放历史。批准与执行成功分别展示；历史不等于当前权限。专员查本公司来源且当前获准系统内记录；全局目录和任免日志仅总管理员查看。

## UC-11 接收审批结果并执行权限变更

| 项目 | 内容 |
| --- | --- |
| 级别 | 子功能（支撑外部审批执行） |

| 2. 权限中心核对结果来源、申请及批准内容。 | 固定申请、内容匹配情况 |
| 3. 权限中心记录批准结果，并确认原方案仍符合执行条件。 | 审批状态、原资格依据、当前范围和目标条件 |
