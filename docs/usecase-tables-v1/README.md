## 打开与编辑

1. 打开 https://app.diagrams.net/ ，选择“设备”。
2. 选择“文件 → 从以下位置打开 → 设备”，打开 [权限管理系统_课程格式用例说明.drawio](权限管理系统_课程格式用例说明.drawio)。
3. 底部有 UC-01～UC-11 共 11 个页签，每页一份说明表。
4. 双击单元格修改文字；单元格是可编辑的原生矩形和文字，不是嵌入图片。整表移动时框选所有单元格；长文字需要增高该行两侧单元格，并将下面的行一起下移。
5. 修改后保存 `.drawio`。需要插入报告时，可从 draw.io 导出当前页为 PNG、SVG 或 PDF；导出前检查缩放与分页。

页面采用按内容确定高度的自定义尺寸，不是预设 A4。若需 A4 打印，导出时适合一页，并检查文字大小。可先用 [预览.html](预览.html) 在浏览器逐页查看；同目录 `UC-01.png`～`UC-11.png` 是本轮同步生成的静态预览。

## 格式与范围

按课件采用：用例编号与名称、级别、包、参与者、描述、触发事件、主成功场景／信息、扩展场景／信息、其他。额外列出前置条件，便于说明谁在什么情况下可办理。

- “包”表示业务功能归类，不是 Java 包名，也不意味着后端已确定模块结构。
- “信息”描述交互所需或产生的业务数据，不是数据库字段或最终 API 定义。
- 扩展编号如 `3a` 表示在主流程第 3 步出现的分支；合并编号表示相同处理适用于多个步骤。
- 主流程按正常成功路径编写，5～8 步；拒绝、无变化、驳回、失败等放在扩展中。
- UC-02～04 的审批执行衔接统一引用 UC-11；等待 OA 是异步业务过程，不表示管理员一直停留在页面或一次接口完成全部处理。
- UC-09 沿用现有合并用例，展示一次登录至退出的过程；创建账号、改密和重置作为配套场景概述，没有新增用例编号。
- UC-11 为支撑审批执行的子功能级用例，其余按现有目标粒度呈现。

## 与详细文档的关系

[课程格式用例说明.md](课程格式用例说明.md) 提供相同正文，且每个用例链接到对应的详细来源。原 `usecases-v1` 保留详细规则、状态、异常、实现约束与验收，课程表并非它的逐条复印或替代。

共通口径仍适用：总管理员管全部公司与系统；权限管理员按指定公司、部门子树及系统范围协作。后台管理资格与业务系统权限分离。业务角色变更经 OA 批准并实际执行才生效；原申请人离任不单独阻止合法申请执行。进入权限为系统使用前提；按员工、当前公司、业务系统查询；仅同公司、同系统有效角色权限取并集，相同功能操作去重。外部业务系统负责认证员工及功能访问拦截。

原长文档中的事务、并发、接口及测试细节不逐项展开在课程表中；若变更业务规则，需要同步简表和详细文档。本目录是用例说明表；配套 [全部流程图](../flows-v1/README.md) 已依据统一用例重新绘制。

## 生成与检查

`generate_tables.py` 保存精简后的文字并统一生成 draw.io、Markdown、HTML 和 PNG。需要 Python 与 Pillow，使用 Windows 微软雅黑字体。

```powershell
python docs/usecase-tables-v1/generate_tables.py
```

重新运行会覆盖本目录的生成文件。若已在 draw.io 中手工修改，请另存副本；脚本不会从修改后的 draw.io 反向同步到 Markdown 或图片。直接在 draw.io 修改后，预览请从 draw.io 重新导出。

已检查 11 个用例与来源编号、名称对应，主流程步数与扩展引用有效，XML 可解析且页面内对象不越界，并抽查 PNG 排版。PNG 由同一套内容和尺寸生成，并非 draw.io 应用导出的截图；不同字体环境下打开时仍需检查换行。

## 本轮统一规则

部门角色只适用直接任职，岗位不自动联动。任职条件丧失使对应授权失效；员工全局停用使全部业务授权及权限管理员任命失效。恢复身份或任职不自动恢复，业务角色重新经 OA 申请，权限管理员由总管理员重新任命。操作配置校验功能归属和有效性，系统进入资格也限定当前公司和系统。资料采用稳定 ID、来源映射和明确人员变更模板；一期使用代表性数据及简单独立 HTTP 调用，后续逐步补齐。
