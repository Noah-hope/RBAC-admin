# 正式前端使用指南

这里是连接真实后端的 Vue 3 + TypeScript 前端，沿用界面原型的 Material 3 风格。原型仍保留在 `docs/02-ui-design/prototype`，日常开发和联调使用本目录。页面中没有模拟账号、模拟数据或切换身份的按钮。

## 本机启动

1. 安装 Node.js 22.12 或以上版本，终端执行 `node -v` 检查。首次获取本工程或依赖锁文件变化后安装依赖：

   ```powershell
   cd D:\NoahProject\rbac-admin\frontend
   npm ci
   ```

   路径替换成自己的 clone 目录。也可在 IDEA 的 `frontend/package.json` 中运行 npm 脚本。

2. 在 IDEA 启动已有的 **BackendApplication** 配置。继续使用现有 JDK 21、数据库、身份开关及 RSA 配置；前端无需生成或持有密钥。用来登录的管理员必须存在于该配置连接的数据库中。建议使用独立测试运行配置，避免反复修改开发库 URL。后端配置说明见 [基座使用指南](../docs/05-detailed-design/FOUNDATION-USAGE.md) 和 [BE-32 初始化](../docs/05-detailed-design/BE-32-DEPLOYMENT.md)。

3. 确认后端健康接口正常，再启动前端：

   ```powershell
   npm run dev
   ```

4. 浏览器打开终端显示的地址，默认 **http://127.0.0.1:5174**。输入自己已初始化的管理员登录名及密码。首次登录会要求修改临时密码，成功后使用新密码重新登录。

前端默认把 `/api` 请求代理至 `http://127.0.0.1:8080`。若后端端口不同，将 `.env.example` 复制为 `.env.local`，修改 `BACKEND_URL` 后重启前端。不要把管理员密码、JWT 或 RSA 私钥写入环境文件。登录后自动携带令牌，不需要在 Apifox 中复制 token；可选的 `X-Request-Id` 不发送空值。

令牌仅存内存，刷新页面需重新登录。总管理员可使用所有平台入口；权限管理员登录后选择一项有效管理任命，页面会携带该任命和范围版本，不把多个任命拼接为更大权限。

## 先验证一个完整故事

使用测试数据库和测试资料，依次操作：

1. **员工组织**：查看已有公司、部门、岗位；没有资料时通过“导入资料”上传 CSV/XLSX，配置映射，检查预检报告后明确确认整批提交。可下载空白 CSV 模板，并阅读界面的字段及操作说明。
2. **系统与权限目录**：登记业务系统、功能及操作。目录修改先看影响预览，再确认保存。系统进入权限与功能操作分开选择。
3. **角色权限**：创建部门角色，打开权限配置，选择权限后保存草稿。创建角色和保存草稿不会直接授予员工权限。
4. **变更申请**：打开草稿，预览有效内容及影响，确认提交 OA。审批在已配置的外部 OA 或后端演示适配器完成；前端不能自行批准。刷新申请，核对审批结果和实际执行状态。
5. **员工授权**：为有有效任职的员工选择角色及来源部门，保存授权草稿；同样经申请预览、提交和审批执行后，在员工“任职与授权”中核对结果。
6. **审计记录**：查看实际操作及字段差异。需要测试撤销时，从员工授权明细发起撤销申请；“关闭来源”和“停用员工”会产生不同的直接失效影响，应先核对预览。

后台账号与范围可在 **管理员与范围** 创建：账号关联员工，管理范围选择公司、部门、系统与协作账号。创建账号不等于授予管理任命，也不等于授予业务权限。

## 出现错误时

| 现象               | 核对内容                                                                        |
| ------------------ | ------------------------------------------------------------------------------- |
| 无法连接服务 / 502 | 后端是否运行；8080 与 `BACKEND_URL` 是否一致；修改代理后是否重启前端            |
| 登录 401           | 账号和密码是否属于当前后端连接的数据库；账号是否有效。页面不会发送旧 token 登录 |
| 登录后回到登录页   | 会话已过期、被撤销或密码已修改，需要重新登录                                    |
| 无有效任命         | 请总管理员核对员工任职、后台账号与管理范围；刷新任命后重新选择                  |
| 409 / 预览失效     | 其他操作已改变版本或范围，重新读取并预览，不强制覆盖                            |
| 422                | 根据页面字段错误修正输入；请求号可用于关联后端日志                              |
| 写入期间断网       | 先保留当前表单，同内容重试会复用幂等键；若已经关闭，先查询结果再重新办理        |
| OA 一直待处理      | 检查后端 OA 配置及投递状态；页面仅在允许状态下提供投递重试，批准不等于执行成功  |

测试中不要把返回失败当作成功保存。空列表表示服务端当前可见范围没有记录，不会自动显示演示数据。历史申请和审计详情保留服务端固定内容，不用当前名称倒推历史事实。

## 开发与检查

```powershell
npm run generate:api # 从 Git OpenAPI 生成管理员路由和类型；契约未改时无需运行
npm run check        # TypeScript 与 Vue 类型检查
npm test             # 9 项请求层 + 19 项浏览器检查，使用受控服务/响应
npm run build        # 生产构建，输出 dist/
```

浏览器测试默认使用本机 Microsoft Edge。使用 Chrome 时，PowerShell 设置 `$env:PLAYWRIGHT_CHANNEL='chrome'`；没有系统浏览器时可安装 Playwright Chromium（`npx playwright install chromium`）并设置为 `chromium`。测试默认启动独立的前端 5174 服务；若日常前端正在运行，先设置 `$env:FRONTEND_TEST_PORT='5184'` 再执行 `npm test`，即可使用其他端口而不停止日常前端。测试无需真实后端或数据库。仅运行请求层可用 `npm run test:api`。

`src/pages` 按业务页面组织，`src/components` 放表格、选择器、表单、预览等组件，`src/api` 放契约类型和统一客户端，`src/state.ts` 管理内存会话及任命上下文。业务写入复用 `Mutation`，需要预览的操作保留原版本和原预览；不要在页面中直接绕过客户端调用 `fetch`。

生产部署应托管 `dist/`，并让同一站点的 `/api` 反向代理到后端。开发代理不是生产部署配置；`npm run preview` 仅用于检查静态构建，不提供开发代理。使用 hash 路由。真实服务器部署仍属于后续部署任务。
